- **[sig-gen]** `rigor sig-gen --write` now repairs a `sig/` header that opens a generic class such as `class Array` or `class Hash` without its type parameters, so `Object` and every class that reaches it build again. ([#2602](https://github.com/rigortype/rigor/pull/2602))
  - Earlier releases wrote such headers, and `rbs` rejects them with `GenericParameterMismatchError`; later runs kept writing members into them.
  - The plain parameters of the first loaded declaration are inserted after the class name, in any file under `sig/`, even one no method of the run maps to ([#2655](https://github.com/rigortype/rigor/pull/2655)); `--write` reports `repaired N generic header(s)`, counting each declaration, and `--check` fails until the repair is written.
  - A header that spells type parameters of its own is left as written, and no opening of a class is repaired when one of its bare openings names a type like a parameter (`def old: () -> E`), since the parameter would capture it ([#2655](https://github.com/rigortype/rigor/pull/2655)).
  - Such a held-back class is reported as `generic header left bare: Array in <files>`, or under `left_bare` in `--format=json`, without failing `--check`; write the name as `::E` to let the repair through. A method's own type parameter (`def m: [E] (E) -> E`) does not hold a header back ([#2655](https://github.com/rigortype/rigor/pull/2655)).
