- **[inference]** A `refine X do … end` written in a module's `def self.x`, or in a `def` inside its `class << self`, is now recorded as that module's refinement of `X`, so `M.setup; using M; "a".yy` no longer reports `call.undefined-method`. The module is no longer opaque either: `"a".zz` under `using M` is still reported, and the checks and calls under it no longer decline or type as `Dynamic[top]`. A refinement a method creates is in effect only for a `using` that runs after the method, so its names are recorded for the visibility decline and no call is typed from its body. ([#1749](https://github.com/rigortype/rigor/issues/1749), [#1835](https://github.com/rigortype/rigor/pull/1835))
