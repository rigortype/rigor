- **[engine]** Refining a constant no longer loads and runs a library inside Rigor itself: a reference to something like `Prism::Translation::RubyParser` used to be resolved in the analyzer's own process, executing the target file — which in that example calls `exit` when an optional gem is missing, killing `rigor check` outright with no diagnostics and no summary. Constant refinement now answers only from a fixed list of core Ruby constants, so no name in the code being checked can drive it, and the one remaining place that does resolve your class names in-process can no longer end the run when that resolution throws. ([#680](https://github.com/rigortype/rigor/issues/680), [#691](https://github.com/rigortype/rigor/pull/691))
