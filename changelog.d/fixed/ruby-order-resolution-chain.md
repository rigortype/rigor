- **[engine]** Method, constant and override lookups now follow Ruby's ancestor order, so a module that an included module includes answers ahead of the superclass, and a prepended module is no longer read as something the class's own method overrides: `class C < Base; include A` where `A` includes `M` types `C.new.foo` (and `C.foo` through `extend A`, and `C::X`) from `M` rather than `Base`, no longer reporting a false `call.undefined-method`, and a public `P#foo` prepended over a private `C#foo` no longer reports `def.override-visibility-reduced` or `def.method-visibility-mismatch`. ([#1567](https://github.com/rigortype/rigor/issues/1567), [#1568](https://github.com/rigortype/rigor/issues/1568), [#1571](https://github.com/rigortype/rigor/issues/1571), [#1578](https://github.com/rigortype/rigor/pull/1578))
