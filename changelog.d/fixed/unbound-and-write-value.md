- **[inference]** A `&&=` on an instance, class, global or local variable that nothing visibly assigned no longer takes its right-hand side as the value. Such a write returns `nil` (or raises, for a class variable) without running the right-hand side, so `if (@x &&= 1)` no longer reports `flow.always-truthy-condition` on a program that takes the else arm, and `@x &&= raise("b")` reads as whatever set `@x` rather than `bot`. An instance variable that only `&&=` writes is no longer typed by that write in the class's other methods, so `rigor sig-gen` no longer declares `def token=: ("refreshed") -> "refreshed"` for an `attr_accessor :token` whose only write is `@token &&= "refreshed"`; for the same reason it now skips `def close = (@io &&= nil)` rather than declaring `-> nil`. A `&&=` on a variable something else assigns keeps its stored-value type. ([#1340](https://github.com/rigortype/rigor/pull/1340))
