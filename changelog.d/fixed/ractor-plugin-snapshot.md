- **[plugins]** Under the experimental Ractor pool backend (`RIGOR_POOL_BACKEND=ractor`), a plugin's class-level declarations (rules, producers, manifest callables) are now shared with the workers, so a run with rigor-ffi, rigor-dry-schema or most other bundled plugins no longer loses every worker to `Ractor::IsolationError` in its constructor, and a plugin block that cannot be shared declines the pool with a `pool-degraded` row naming the plugin. The backend is still not usable: on a non-trivial project a plugin run now gets far enough to hit the CRuby crash tracked in #1064 (`[BUG] Bus Error`, no output) instead of degrading to a sequential run. ([#2088](https://github.com/rigortype/rigor/pull/2088))
