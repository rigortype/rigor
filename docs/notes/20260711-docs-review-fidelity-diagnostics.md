## Verifications that PASSED (no defect)

- **`documentation_url` anchor scheme** (`04:27–35`) matches `RuleCatalog.doc_anchor` (`rule-<id with dots→dashes>`) and `DOCUMENTATION_BASE`; the `<a id>` anchors are present; the note that `rbs_extended.unsatisfied-conformance` carries no `documentation_url` and `rigor explain` cannot resolve it is correct (`RULE_FAMILIES = call flow assert dump def`, no `rbs_extended` entry → `resolve` returns `[]`).
- **Rule IDs / families** — every rule ID in all three chapters matches a `CheckRules` constant; the manual families table (call/flow/def/assert/dump) matches `RULE_FAMILIES`.
- **Manual `04` severity-profile table (lines 88–92)** — accurate against `severity_by_profile`, including both `strict` exceptions.
- **Session change 1 (ADR-57 WD3 module-singleton resolution)** — no doc in scope claims module-facade calls stay `Dynamic`; the "why a diagnostic might NOT fire" list (`08:285–293`) does not assert module silence. No contradiction.
- **Session change 2 (union-arm predicate polarity, `present?`/`blank?`, `narrowing.rb:876`)** — confirmed implemented (ActiveSupport methods). No handbook example claims `present?`/`blank?` fail to narrow a nilable receiver; the `03-narrowing.md` predicate table and "what's not narrowed" list neither cover nor contradict them.
- **Session change 3 (ADR-78 reflexive over-fold / ADR-76 WD2 freeze/dup/clone shape preservation)** — `flow.always-truthy-condition` prose (`04:47`, `08:87`, catalog `does_not_fire_when`) remains accurate. Neither chapter describes `freeze`/`dup`/`clone` carrier behaviour or `public_send` folding, so nothing to contradict.

## Intentional-simplification section (flagged NOT as defects)

- **`03-narrowing.md` omits `present?`/`blank?` narrowing.** This is ActiveSupport, not core Ruby; the handbook narrowing chapter is deliberately core-method-scoped (its predicate table lists only `String#empty?`, `Array#empty?`, `Hash#empty?`, `Integer#zero?/positive?/negative?`). Adding gem-method narrowing would be depth-for-depth's-sake, not a fidelity fix. Leave as is.
- **Manual `04` lenient row** ("uncertain ones drop to `warning`/`info`") does not enumerate that `def.override-*`/`self-undefined`/`unresolved-toplevel` drop to `off` under lenient. This is a stance description, not an enumeration, and reads defensibly — no change needed. (Finding #2 is scoped to the *handbook*, whose sentence additionally mis-implies proven rules become warning.)
- **Neither chapter covers module-facade resolution, `present?`/`blank?` narrowing, freeze-carrier preservation, or `public_send` fold-suppression.** These are precision-additive engine improvements with no diagnostic-surface contract; user docs are not obliged to enumerate them, and doing so would bloat software reference docs. Correct to omit.

## Verdict

The **manual `04-diagnostics.md` is fully faithful** to the implementation across every claim in scope — evidence tiers, severity profiles, documentation URLs, rule IDs, and firing conditions all match `RuleCatalog`/`CheckRules`, and none of this session's four engine changes contradict it. The **handbook `03-narrowing.md` is clean** — its core-scoped narrowing catalogue neither over-claims nor contradicts the new `present?`/`blank?` and module-facade behaviour. The single real defect is the **handbook `08-understanding-errors.md` severity-profile summary table (lines 143–147)**: all three rows drifted from the per-rule reality, and two of them (`strict`, `balanced`) directly contradict that same chapter's detailed `flow.*`/`def.*` rule tables, with the `strict` "everything → error" row being literally false since `unreachable-clause` (`warning`) and `self-undefined-method` (`off`) are exceptions. The fix is to bring those three rows into line with the accurate manual `04` profile table — no code change, and no other stale rule IDs, wrong severities, or wrong firing conditions were found.
