- **[inference]** An `attr_writer` / `attr_accessor` declaration now counts as a write to its instance variable, as a hand-written setter does, so an ivar injected through the accessor and set to `nil` or `false` in `initialize` no longer reports a false `flow.always-truthy-condition` on `if @cb` or a false `undefined method for nil` on `@cb.call`. Because a writer can assign anything, `rigor sig-gen` now skips an accessor-backed reader or writer, and any other method returning such an ivar, as `sig.skipped.untyped-return` where it used to propose a type (`@logger = Logger.new` no longer yields `def logger: () -> Logger`); a reader declared in RBS that returns a writer-only ivar can now report `def.return-type-mismatch` until the RBS attr type is used ([#1406](https://github.com/rigortype/rigor/issues/1406)). Thank you @bash0C7! ([#541](https://github.com/rigortype/rigor/issues/541), [#1409](https://github.com/rigortype/rigor/pull/1409))
