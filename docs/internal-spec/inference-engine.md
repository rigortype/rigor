# Inference Engine

This document specifies the public contract that the Rigor type-inference engine MUST satisfy: the `Rigor::Scope#type_of(node)` query, the immutable-Scope discipline, the fail-soft `Dynamic[top]` policy, and the environment-loading boundaries that surround them. It is the engine-side counterpart of the type-language semantics in [`docs/type-specification/`](../type-specification/) and the type-object public API in [`internal-type-api.md`](internal-type-api.md).

The slice-by-slice growth plan and the rationale behind the tentative answers to ADR-3's open questions live in [`docs/adr/4-type-inference-engine.md`](../adr/4-type-inference-engine.md). When that ADR and this document disagree on observable Ruby behavior, this document binds.

## Scope

This document binds:

- The shape and stability of the `Rigor::Scope#type_of(node)` query.
- The immutable-Scope discipline that surrounds the query.
- The fail-soft policy for AST nodes the typer does not yet recognise.
- The environment-loading boundaries: which surface MUST be available, and which surface MAY change between slices.

This document does **not** bind:

- The internal data structure used by `Rigor::Scope` (so long as the public surface is preserved and immutability is observable).
- The visitor or pattern-match strategy used inside `Rigor::Inference::ExpressionTyper`.
- The exact catalogue of Prism nodes recognised in any particular slice; that catalogue is informational and tracked in [`docs/adr/4-type-inference-engine.md`](../adr/4-type-inference-engine.md).

## The `Scope#type_of(node)` Contract

`Rigor::Scope#type_of(node)` MUST be a pure query. It MUST NOT mutate any flow-state field of the receiver scope — the local, instance-, class- and global-variable binding maps, the fact store, `self_type`, the narrowing maps — or any object reachable through them, and it MUST NOT cause persistent state changes anywhere else in the analyzer. The same `(scope, node)` pair MUST produce structurally equal `Rigor::Type` results across calls within a single analyzer run.

**As of this writing that purity binds the return value and the flow state, not every object the scope can reach.** `Rigor::Scope` also carries two identity-keyed *advisory* side-tables — `dynamic_origins` ([ADR-75](../adr/75-dynamic-provenance.md) / [ADR-82](../adr/82-dynamic-provenance-wiring.md), why a `Dynamic` value is dynamic) and `void_origins` ([ADR-100](../adr/100-static-diagnostic-family-and-void-origins.md), where a `top` recovered from an author-declared `-> void` came from) — which `Rigor::Inference::ExpressionTyper` and `Rigor::Inference::MethodDispatcher` write in place while typing, threaded by reference through every transition and so observable on the receiver scope. Three properties keep the query's contract intact and MUST be preserved: the tables are keyed by node identity and hold provenance *about* a value, never part of what it *is*; they are excluded from `Scope#==` and `Scope#hash`, so they can never fork a flow-dedup or a cache key; and nothing in the engine reads them back into a typing decision — they are consumed only by the diagnostic and coverage layers, downstream of inference. An implementation MAY therefore carry them as genuinely external state keyed on the node.

The query MUST return a `Rigor::Type` per [`internal-type-api.md`](internal-type-api.md). It MUST NOT return `nil`, raise on unsupported nodes, or expose Prism objects in its return value.

The receiver MUST be a `Rigor::Scope` instance. Implementations MUST NOT accept a raw Hash or Array of bindings; the binding container is internal to `Rigor::Scope`.

The `node` argument MUST be either a `Prism::Node` or a `Rigor::AST::Node` (a synthetic node from the *Virtual Nodes* family below). Implementations MAY accept additional Prism node families when added by upstream Prism, and additional `Rigor::AST::Node` subtypes when registered through the engine, but MUST treat unrecognised concrete classes within either family under the fail-soft policy below rather than raising.

## Immutable Scope Discipline

`Rigor::Scope` instances MUST be immutable. They MUST be `freeze`d at the end of construction. Mutation through any public or internal method is a contract violation, including through accessors that expose internal containers.

State changes MUST be expressed as new scopes returned from explicit transition methods. The minimum set is:

- `Rigor::Scope.empty(environment:)` — constructs a scope with no local bindings and an empty `Rigor::Analysis::FactStore`, attached to a `Rigor::Environment`.
- `Rigor::Scope#with_local(name, type)` — returns a new scope identical to the receiver except that `name` is bound to `type`. Rebinding a local MUST invalidate facts that target that local.
- `Rigor::Scope#local(name)` — returns the bound `Rigor::Type` or `nil` if `name` is not bound.
- `Rigor::Scope#fact_store` — returns the immutable `Rigor::Analysis::FactStore` attached to the snapshot.
- `Rigor::Scope#local_facts(name, bucket: nil)` / `Rigor::Scope#facts_for(target:, bucket: nil)` — return facts from the scope's `Rigor::Analysis::FactStore` without exposing bucket storage directly.
- `Rigor::Scope#with_fact(fact)` — returns a new scope with `fact` added to the fact store.
- `Rigor::Scope#join(other)` — returns a new scope at a control-flow merge point. Implementations MUST require the two scopes to share the same `Environment`. The joined scope MUST be bound to every name that BOTH receivers bind; for each such name the joined type MUST be `Type::Combinator.union(self.local(name), other.local(name))`. Names bound in only one receiver MUST be dropped from the joined scope; nil-injection of half-bound names is the responsibility of the statement-level evaluator (see Slice 3 in [`docs/adr/4-type-inference-engine.md`](../adr/4-type-inference-engine.md)), not of `#join`. The joined fact store MUST retain only facts present on both input edges.

`Rigor::Scope` MUST share underlying data structurally where useful. Two scopes that share a parent and differ in one binding MAY share the storage of all other bindings; this is an implementation detail and not part of the contract.

`Rigor::Scope#environment` MUST return the same `Rigor::Environment` instance that constructed the scope. The environment is treated as immutable from the scope's perspective for the duration of a query.

### FactStore (Slice 6 phase 2 sub-phase 2)

`Rigor::Analysis::FactStore` is the immutable fact bundle carried by each `Scope` snapshot. The first implementation is intentionally small but establishes the long-term bucket shape from [`control-flow-analysis.md`](../type-specification/control-flow-analysis.md):

- `Rigor::Analysis::FactStore.empty` MUST return an empty frozen store.
- `FactStore::Target.local(name)` identifies a local-binding target.
- `FactStore::Fact` MUST carry `bucket`, `target`, `predicate`, `payload`, `polarity`, and `stability`. The recognised buckets are `local_binding`, `captured_local`, `object_content`, `global_storage`, `dynamic_origin`, and `relational`.
- `FactStore#with_fact(fact)` MUST return a new store and deduplicate structurally equal facts.
- `FactStore#invalidate_target(target, buckets: nil)` MUST return a new store with facts mentioning `target` removed. When `buckets:` is provided, only facts in those buckets are removed.
- `FactStore#join(other)` MUST retain only structurally equal facts present in both stores.

The fact-store buckets are an internal optimisation boundary. `Scope` may expose fact queries and fact-adding transitions, but callers MUST NOT mutate bucket storage in place.

### Discovery Index (ADR-53 Track A)

Alongside its flow state, every `Rigor::Scope` snapshot carries a single immutable **discovery index** (`Rigor::Scope::DiscoveryIndex`) holding the seed-time discovery tables — `declared_types`, `class_ivars`, `class_cvars`, `program_globals`, `discovered_classes`, `in_source_constants`, `discovered_methods`, `discovered_def_nodes`, `discovered_singleton_def_nodes`, `discovered_def_sources`, `discovered_singleton_def_sources`, `discovered_method_visibilities`, `discovered_parameter_envelopes` (the [#992](https://github.com/rigortype/rigor/issues/992) positional envelope table, below), `discovered_superclasses`, `discovered_includes`, `discovered_prepends` (the instance-side prepend ORDER table, [#1123](https://github.com/rigortype/rigor/issues/1123), below), `discovered_extends` (the singleton-side mixin table, [#898](https://github.com/rigortype/rigor/issues/898); it records `extend M`, `extend self`, a bare `module_function`, and — since [#915](https://github.com/rigortype/rigor/issues/915) — an `include` / `prepend` written inside a `class << self` body, which Ruby makes the same singleton ancestor), `discovered_class_sources`, `constant_sources` (the [#644](https://github.com/rigortype/rigor/issues/644) constant-write attribution, seeded only on an ADR-46 recording run), `published_constant_names` and `local_constant_names` (#644, the two halves of `Scope#published_constant?`), `data_member_layouts`, `struct_member_layouts`, `param_inferred_types` (the ADR-67 call-site parameter-inference table), and `run_generation` (the ADR-84 per-run identity token the user-method return memo buckets on). Membership is fixed by the criterion in [ADR-53](../adr/53-scope-discovery-index-separation.md): a field belongs in the index **iff no flow transition ever produces a scope whose value for that field differs from its seed**.

- The index MUST be immutable; it is a frozen `Data` and a seeded index is derived through `DiscoveryIndex#with`.
- Every flow transition (`with_local`, `with_fact`, `join`, …) MUST carry the receiver's index through to the result by reference, unexamined. `Scope#==` MUST NOT compare the index (it is ambient context, not flow state).
- `Scope` MUST keep exposing the per-table readers (`user_def_for`, `superclass_of`, `includes_of`, `discovered_method?`, `data_member_layout`, `class_ivars_for`, …) as delegates, so engine call sites and plugins are independent of the storage split. The ADR-46 dependency-recording instrumentation lives in those delegates and they MUST remain the only read path.
- `Scope#with_discovery(index)` is the sole seeding transition. The per-table `with_discovered_*` writers were removed in ADR-53 slice A2.
- A scope constructed for a nested body (method-entry, class-body, or re-typed user-method body) MUST inherit the parent scope's index whole — never by per-table copy, which is how `data_member_layouts` was silently dropped twice before the extraction.

**`discovered_parameter_envelopes` ([#992](https://github.com/rigortype/rigor/issues/992)).** `{qualified class name => {[kind, method_name] => envelope}}`, where an envelope is `Source::ParameterEnvelope` plain data `[min, max, required_keywords]` (`max` nil when a rest or `...` parameter leaves it unbounded) or `Source::ParameterEnvelope::OPAQUE`. It is the single source of a `def`'s positional envelope for `call.wrong-arity` when no trustworthy signature declares the method; an `inferred-signature` member synthesized by `rigor-rbs-inline` is routed to it rather than having its own arity read.

- The declaration walk MUST write it through the same recorder as `discovered_methods` (`ScopeIndexer#record_method`), so every name the existence table learns from an `alias`, `attr_*`, `define_method` or `Struct` / `Data` member is present as `OPAQUE`; only a `def` records a real envelope.
- Every contribution to one key MUST fold with `Source::ParameterEnvelope.merge` — equal envelopes stay, anything else is `OPAQUE`, and `OPAQUE` absorbs — across reopenings in one file, across files in the whole-project pass and its ADR-85 seed-bundle fold, across the compact-header re-keying, and when a file's own walk joins the project seed. No merge may keep one of several shapes (later-wins or first-wins).
- The walk also records evidence the existence table does not carry, as `OPAQUE` entries: both kinds of a name a receiverless class-body call passes as a literal or wraps inline (`memoize :f`, `memoize def f`), except the visibility / `module_function` / `require` macros; both names of an `alias`; an `undef`; the class-wide `DiscoveryIndex::ENVELOPE_MODULE_MARK` for a `module` / `Const = Module.new do … end`; and `DiscoveryIndex::ENVELOPE_DYNAMIC_MARK` for a class-body `class_eval`-family call, a computed `define_method` / `define_singleton_method` / `alias_method` / `remove_method` / `undef_method`, a `send`-family call, or an `include` / `prepend` / `extend` (or a `*_include_*`-style project helper) of a non-constant — and, on every name a constant receiver can denote from the call site, for those calls written as `Const.class_eval { … }` / `Const.include(M)` or as `refine Const do … end`. Method bodies are scanned too, though the declaration walk does not otherwise enter them: a `class_eval`-family or `define_method`-family call inside a `def` marks its constant receiver's candidates, or else the lexical class, dynamic; and a module passed to `extend` there carries `DiscoveryIndex::ENVELOPE_OBJECT_EXTENDED_MARK`, since an object of any class may then answer with its methods.
- A whole-project pass (`ScopeIndexer#finalize_def_index`) MUST add the class key `DiscoveryIndex::ENVELOPE_PROJECT_WIDE` with an empty bucket, and a consumer MUST NOT read an envelope from an index that lacks it: a single file's walk cannot see the reopening, subclass or `class_eval` in another file.
- `Scope#parameter_envelopes_of(class_name)` is the read path and records the ADR-46 class dependency; the table is part of the ADR-85 seed bundle and of the ADR-89 WD1 declaration signature, so a file whose only edit adds a wrapping macro is declaration-unstable.

## Fail-Soft Policy

When the typer encounters a node it does not yet recognise — either a Prism node whose class the engine has not yet wired in or a `Rigor::AST::Node` of an unknown kind — `Scope#type_of(node)` MUST return `Rigor::Type::Combinator.dynamic(Rigor::Type::Combinator.top)`, the canonical `Dynamic[top]` representation of "untyped, unchecked".

The fail-soft path MUST satisfy:

- It MUST NOT raise. Callers MAY rely on `Scope#type_of` for any expression node Prism produces and for any synthetic node that includes `Rigor::AST::Node`.
- It MUST preserve the dynamic-origin algebra in [`value-lattice.md`](../type-specification/value-lattice.md). Downstream queries against the returned type MUST observe the same gradual-typing rules that any other `Dynamic[T]` would.
- It MUST be observable to instrumentation through the *Fallback Tracer* contract below.

When a slice introduces support for a node kind, the fail-soft path for that kind MUST be removed in the same slice. The typer MUST NOT keep a fallback that masks an incorrectly-typed node.

### Fallback Tracer

`Rigor::Scope#type_of` MUST accept an optional `tracer:` keyword argument. When `tracer` is `nil` (the default), the engine MUST behave as if no tracer were attached: no tracer events MUST be recorded, and the fallback path MUST NOT allocate beyond what producing the return value and recording the node's `dynamic_origins` provenance (per the advisory side-table carve-out in § *The `Scope#type_of(node)` Contract* above) requires.

When `tracer` is non-`nil`, every fail-soft fallback (both Prism and synthetic) MUST be recorded into the tracer through a single method call:

```ruby
tracer.record_fallback(event)
```

`event` MUST be a `Rigor::Inference::Fallback` value object with the following structurally-equal fields:

- `node_class` — the Ruby `Class` of the node that triggered the fallback (e.g. `Prism::CallNode`, `Rigor::AST::SomeFutureNode`).
- `location` — the Prism source location object for real Prism nodes, or `nil` for synthetic nodes that do not expose a location.
- `family` — the symbol `:prism` for real Prism nodes and `:virtual` for nodes that include `Rigor::AST::Node`.
- `inner_type` — the `Rigor::Type` returned to the caller. This is `Dynamic[top]` today; later slices MAY enrich the inner type while keeping the fallback observable.
- `origin` — the `Rigor::Inference::DynamicOrigin` cause symbol (ADR-75) recorded as provenance for the widened value, or `nil` when no cause is known.

The tracer protocol exposed by `Rigor::Inference::FallbackTracer` MUST satisfy:

- `record_fallback(event)` MUST accept any `Rigor::Inference::Fallback` and reject other arguments.
- `events` MUST return a frozen, ordered snapshot of recorded events.
- `empty?` and `size` MUST report the current number of recorded events.
- `each` MUST iterate the recorded events in insertion order; the tracer MUST `include Enumerable`.

The tracer is the only *event-recording* state observable from `Scope#type_of` — the sole other mutable state the query touches is the advisory `dynamic_origins` / `void_origins` provenance carve-out in § *The `Scope#type_of(node)` Contract* above, which records no events and answers no query. The tracer MUST NOT change the return value of `type_of` and MUST NOT be exposed through `Rigor::Scope` accessors. Implementations MAY add additional `record_*` methods (for example a richer `record_dispatch_miss` once the Slice 2 dispatcher gains tiers, or `record_budget_cutoff` in Slice 6) so multiple event families share a single tracer; new methods MUST follow the immutable-event-value-object pattern above.

## Virtual Nodes

The engine MUST accept a synthetic AST family in addition to Prism nodes. Synthetic nodes are Ruby objects that include the documentation-only marker module `Rigor::AST::Node` and expose whatever node-specific data the engine needs to translate them into a `Rigor::Type`. They make it possible to ask `Scope#type_of` "what would the analyzer infer if a value of type T appeared here?" without constructing a real Prism expression.

Synthetic nodes MUST satisfy:

- They MUST be immutable. `Rigor::AST::Node` MUST be `freeze`d at construction.
- They MUST support structural equality. Two synthetic nodes that hold structurally equivalent data MUST compare equal under `==` and `eql?` and MUST share the same `hash`.
- They MUST be composable with real Prism children when the synthetic node has an inner-AST position. The engine MUST NOT require all transitive children to be synthetic.
- They MUST NOT carry analyzer state or fact-store entries. Any such state lives on `Rigor::Scope` or in the engine's environment, not on the node.

`Scope#type_of(virtual_node)` is dispatched through the same fail-soft contract as Prism nodes: an unrecognised concrete class within `Rigor::AST::Node` MUST return `Dynamic[top]` rather than raise.

### `Rigor::AST::TypeNode`

The minimum synthetic node family that this specification binds is `Rigor::AST::TypeNode`. It MUST exist, MUST include `Rigor::AST::Node`, MUST be constructible from a single `Rigor::Type`, and MUST satisfy:

- `Rigor::Scope#type_of(Rigor::AST::TypeNode.new(t))` MUST return a `Rigor::Type` that compares structurally equal to `t` for any non-`nil` `t`.
- The engine MUST NOT modify, normalise, annotate, or wrap the inner type. Round-trip through `TypeNode` is observably the identity.
- `TypeNode` MUST NOT be wrapped in `Dynamic[T]`, refinements, or any other carrier as a side effect of `Scope#type_of`.

Additional synthetic node kinds (call expressions, container literals, narrowing wrappers) are added by later slices and are non-normative until promoted. New kinds MUST follow the immutability, structural-equality, and composability rules above.

## Method Dispatch Boundary

Method dispatch (the rule that determines the result type of a call expression given a receiver type and argument types) MUST NOT live on `Rigor::Type` instances. Type classes remain thin value objects per [`internal-type-api.md`](internal-type-api.md): they hold structural data and answer capability questions, but they do not carry method-summary tables or operator handlers.

Slice 2 introduces `Rigor::Inference::MethodDispatcher` as a separate engine surface, originally planned for Slice 3 but pulled forward after the `rigor type-scan` dogfood signal showed `Prism::CallNode` and `Prism::ArgumentsNode` were the largest single source of unrecognised expressions. The Slice 2 dispatcher ships only a constant-folding tier; Slice 4 layers RBS-backed lookups behind it (see [`docs/adr/4-type-inference-engine.md`](../adr/4-type-inference-engine.md)).

The dispatcher's public signature is:

```ruby
Rigor::Inference::MethodDispatcher.dispatch(
  receiver_type:,        # Rigor::Type or nil (implicit self; unsupported in Slice 2)
  method_name:,          # Symbol
  arg_types:,            # Array<Rigor::Type>
  block_type: nil,       # Rigor::Type or nil; the inferred return type of an
                         #   accompanying `do ... end` / `{ ... }` block.
                         #   Slice 6 phase C sub-phase 2: when non-nil, the
                         #   selector prefers a block-bearing overload and the
                         #   method-level type parameter that the block's
                         #   return type references is bound to `block_type`
                         #   so a return like `Array[U]` resolves to
                         #   `Array[block_type]`.
  environment: nil,      # Rigor::Environment; required for RBS-backed dispatch
  call_node: nil,        # Prism::CallNode or nil; the call site being folded.
                         #   Required by the plugin return-type contribution
                         #   tier and by every dynamic-/void-origin provenance
                         #   record; the dispatcher's own internal re-entrant
                         #   callers pass nil, which makes those inert.
  scope: nil             # Rigor::Scope or nil; when present, enables the
                         #   ADR-43 RBS-complete-ancestor resolution described
                         #   in the RBS-backed tier below. Defaults to nil, in
                         #   which case that resolution is inert and every other
                         #   tier behaves identically.
) #=> Rigor::Type, or nil when no rule matches
```

A `nil` return value is the deliberate "no rule" signal. Callers MUST own the fail-soft fallback (`ExpressionTyper` records a `FallbackTracer` event and returns `Dynamic[top]`); the dispatcher itself MUST NOT touch the tracer or raise on unrecognised inputs.

The dispatcher MUST consult tiers in this order: the `Type::BoundMethod` backward fold first (`MethodFolding.try_backward`, which substitutes the bound `(receiver_type, method_name)` and re-enters `dispatch`, so a `Method` carrier never reaches a lower tier as a `Method` receiver and loses its binding to `Method#call: (*untyped) -> untyped`), then the precise tiers (constant-folding, shape-aware, file-fold, kernel-fold, block-fold) — the parenthetical names the bands, not the full catalogue, which is informational per § Scope — then the plugin return-type contribution tier (v0.1.1 Track 2 slice 7, per [ADR-2](../adr/2-extension-api.md) § "Plugin Contribution Merging"), then the HKT-builtin-return tier ([ADR-20](../adr/20-lightweight-hkt.md)) and the Rigor-bundled static-refinement tier, then the RBS-backed dispatch tier, then the [ADR-16](../adr/16-macro-expansion.md) synthetic-method tier (substrate Tier B / Tier C emit tables — user-authored RBS still wins above it), then the [ADR-17](../adr/17-monkey-patch-pre-evaluation.md) project-patched-methods tier (consults `Environment#project_patched_methods` for `pre_eval:`-declared reopened-class methods and returns `Dynamic[top]` so the call resolves cross-file without `call.undefined-method`), then the dependency-source inference tier (v0.1.3 / [ADR-10](../adr/10-dependency-source-inference.md) slice 2b-ii — consults `Environment#dependency_source_index` for opt-in gems' `(class_name, method_name)` catalog entries and returns `Dynamic[top]` on a hit so the call site carries the dynamic-origin marker), then the discovered-method tier (cross-file user-defined `def` resolution per [ADR-24](../adr/24-self-method-call-resolution.md): when the receiver names a discovered class whose method is recorded, it returns `Dynamic[top]` for the bare-`def` shape, but **declines** (returns `nil`) when `Scope#user_def_for` / `singleton_def_for` carries a re-typable body so that `ExpressionTyper#try_user_method_inference` re-types the callee body and adopts its inferred return — [ADR-57](../adr/57-self-call-return-adoption.md) opened that adoption gate unconditionally, removing the former `adoptable_self_call_result?` guard), then the [ADR-5](../adr/5-robustness-principle.md) synthesized-stub-type tier (a receiver Rigor invented to make an otherwise-unbuildable project signature resolve — a missing namespace, or a stub for a referenced-but-undeclared type — carries no methods, so an unresolved call against it would mis-fire `call.undefined-method`; it resolves to `Dynamic[top]` instead, under the same no-false-positive contract as the dependency-source tier), and finally the user-class ancestor fallback that retries against `Object` / `Class` for receivers Rigor knows by name but not by RBS. The first tier that returns a non-`nil` `Rigor::Type` wins; subsequent tiers MUST NOT be consulted on a hit. The dispatcher MUST take its input as a uniform call-shape that may carry either Prism child nodes or synthetic `Rigor::AST::Node` arguments (by way of the *Virtual Nodes* contract above), so synthesised expressions and real expressions share a single dispatch path.

### Dispatch tier contract

Every tier above is a *structural interface* — a duck-typed seam, an interface in the RBS/Go sense, not an ADR-28 protocol contract — codified as `interface _DispatchTier` in [`sig/rigor/inference.rbs`](../../sig/rigor/inference.rbs). A tier MUST expose a single entry point:

```
try_dispatch(context) #=> Rigor::Type, or nil to defer to the next tier
```

`context` is an immutable `Rigor::Inference::MethodDispatcher::CallContext` value object (a `Data`) carrying everything a tier needs to fold one call site: the call quartet (`receiver`, `method_name`, `args`) plus the optional `block_type`, `environment`, `call_node`, `scope`, `self_type_override`, and `public_only` fields. `dispatch` MUST build the context once and thread it — unchanged — to every tier; a tier that needs a varied receiver or a derived flag (the user-class fallback's `public_only` retry, the origin-module redispatch) MUST obtain a fresh context — by copy (`CallContext#with`) or by building a new one — rather than mutate the one it was given (the value object is frozen). A pure tier (constant-folding, shape-aware, the singleton folders) MUST read only `receiver` / `method_name` / `args` and ignore the rest. The "first non-`nil` wins" rule above governs the ordered consultation of these tiers.

The contract is declarative: it is not enforced by a base class or an `implements` clause (Ruby has none), and the bundled tiers stay untyped under Steep's lenient mode. Implementations MAY add a tier by conforming to `_DispatchTier` and inserting it at the correct precedence; they MUST NOT widen the entry point's keyword surface back out (the value object exists precisely to keep the per-tier signature uniform).

The RBS-backed tier MUST resolve receiver types to a `(class_name, kind)` pair where `kind` is `:instance` or `:singleton`:

- `Type::Constant[v]` resolves to `(v.class.name, :instance)`.
- `Type::Nominal[name]` resolves to `(name, :instance)`.
- `Type::Singleton[name]` (Slice 4 phase 2b) resolves to `(name, :singleton)`. The dispatcher MUST consult `RbsLoader#singleton_method` rather than `instance_method` for this kind, so `Foo.bar` correctly looks up the class methods of `Foo`.
- `Type::FloatRange` (ADR-109 WD4) resolves to `("Float", :instance)`, and `Type::IntegerRange` (issue #842) resolves to `("Integer", :instance)`: a bounded numeric carrier is its unbounded class for every method the fold tiers above this one do not already own.
- `Type::Dynamic[T]` recurses into `T`'s static facet using the same rules.
- `Type::Top` and `Type::Bot` produce no descriptor; the dispatcher MUST return `nil`.

`Union` receivers MUST dispatch each member individually — when every member resolves, the per-member return types are unioned and that union is returned; when any member returns `nil`, the whole dispatch MUST return `nil`. Mixing instance and singleton members within a single union MUST NOT be a special case; each member is dispatched against its own descriptor. This is the RBS tier's own distribution; the dispatcher repeats it for the whole chain in § *Composite receivers* below.

- A `Type::Refined` or `Type::Difference` receiver resolves through its BASE's descriptor ([#533](https://github.com/rigortype/rigor/issues/533)): a refinement is a precision layer, and the promotions that read it run in the catalog tiers above this one, so erasing here resolves `RUBY_VERSION != "1.0"` through `String#!=` instead of declining the whole dispatch.

#### Composite receivers ([#1101](https://github.com/rigortype/rigor/issues/1101))

Every tier listed above needs a receiver it can NAME — the RBS descriptor, the discovered-method lookup, the dependency-source and synthesized-stub tiers and the user-class ancestor fallback all key on `Nominal` / `Singleton` or a member carrier. A `Union` or a `Difference` is none of those, so the union distribution that lives INSIDE the RBS tier cannot help a member whose answer comes from a LOWER tier: a plugin-minted nominal with no RBS (`ActionController::Parameters`, which rigor-actionpack gives `params[:k]` as `Parameters | nil`) resolves only through the user-class fallback, and so the whole call landed `Dynamic[top]`.

After every other tier has declined, the dispatcher MUST therefore retry the call once per PROJECTED member of a composite receiver, each through this same full tier chain, and answer the union of the results. The tier MUST sit last, so it can only ever replace a `Dynamic[top]` the typer was about to produce; hoisting it above the RBS tier would change answers that already resolve. The projection is:

- `Union[A, B, …]` projects to its members. When every member resolves, the answers are unioned; when ANY member declines, the whole tier MUST decline. A partial answer is forbidden: a union whose members disagree about whether the method exists is exactly where an answer would be a guess, and claiming one would put `call.undefined-method`-grade confidence on a receiver half of whose inhabitants raise `NoMethodError`.
- `Difference[base, nil]` — where the removed type is `Constant[nil]` or `Nominal[NilClass]` — projects to `base` with its nil-valued members removed. Removing `nil` from a receiver cannot change method resolution at all, because `NilClass` is no other class's ancestor: every remaining inhabitant looks a method up exactly as a plain `base` inhabitant does, and the carrier is value-set-equal to the projection. This is the `T.must(x)` shape (`rigor-sorbet`'s `strip_nil`), whose base IS a union whenever `x` was nullable. A projection that empties the base MUST decline.
- Every other `Difference` MUST decline. `A − B` for a real class `B` is a claim about which inhabitants survive, and the projection has nowhere to put it: dispatching on `A` re-admits exactly the overrides `B` contributed, and over a union base — `(String | Integer) − Integer` is Strings only — it re-admits a member the difference eliminated and unions that member's answer in, which is WIDER than declining. Subtracting a class from a union needs an algebra the carrier does not have (`Difference` removes a value set, not a union member), so the engine MUST keep declining until a measured shape demands otherwise. The `#533` base erasure above is unaffected and still answers these for an RBS-known base.

`self` MUST bind to the projected receiver rather than to the composite carrier, so a `-> self` method answers per member and the union reassembles them (`(String | Symbol)#itself` is `String | Symbol`). Nothing is lost on the `Difference` arm, where the projection is value-set-equal to the carrier.

The retry MUST NOT leave a per-call record behind when it declines. `Scope#plugin_typed_calls` ([#653](https://github.com/rigortype/rigor/issues/653)) is set-only and is read as an EXEMPTION from `call.undefined-method` and `call.wrong-arity`, so a member a plugin answers beside a member that declines would mark a call the dispatcher never typed. That exemption is checked ahead of the receiver-shape branch, so it reaches the union rule as well, and the suppression is reachable: a plugin gated on one arm of a two-class union of RBS-declared classes silences the union's `call.undefined-method`. The plugin tier MUST therefore buffer that record while a projection is in flight, and the projection MUST commit it only when it answers. `Scope#dynamic_origins` needs no such treatment: it is last-wins and the caller's fail-soft widening overwrites it.

A projected member resolves exactly as the same receiver resolves on its own, which means the tier INHERITS the contracts of the tiers it re-enters rather than widening any of them — including the user-class ancestor fallback's known lenience, where a project's own `to_s` / `nil?` override loses to `Object`'s RBS. That is a property of the scalar path, not of this tier, and the projection MUST NOT acquire a rule the scalar path does not have.

The retry MUST be bounded, because it re-runs the full chain per member. Every projected member MUST itself be non-composite — `Difference[Union[A, B, nil], nil]` projects straight to `A` and `B` — so the re-entry is one level deep by construction rather than by a counter, and a member that is still a `Union` or a `Difference` MUST make the tier decline. The fan-out MUST also be capped (eight members), declining rather than paying one full chain walk per member on a receiver the engine has already lost precision on.

**Inherited resolution into an RBS ancestor ([ADR-43](../adr/43-rbs-complete-ancestor-resolution.md), [ADR-114](../adr/114-core-stdlib-ancestor-dispatch.md)).** When the resolved `(class_name, kind)` descriptor's class is NOT RBS-known (a Ruby-source subclass discovered by `ScopeIndexer`, absent from the RBS environment's class declarations), the direct method lookup misses and — because the class is unknown to RBS — no ancestor walk runs, so the call would degrade to `Dynamic[top]`. The dispatcher MUST keep that degradation as the general case: a Ruby class subclassing a GEM's RBS-only class (`class MyController < ActionController::Base`) routinely answers to methods a *partial* gem RBS omits. Three bounded exceptions resolve instead, all requiring a `scope:` threaded into `dispatch` and all keyed on `class_name` not being RBS-known.

**(a) Allow-listed RBS-complete ancestors.** When `class_name`'s discovered superclass chain (`Scope#superclass_of`, ADR-24) reaches a class on the engine's frozen `ALLOWED_RBS_COMPLETE_ANCESTORS` or on a loaded plugin manifest's `rbs_complete_ancestors:`, the dispatcher MUST resolve the method against that ancestor's RBS definition (instance or singleton per `kind`). The membership criterion is "this class's RBS is authoritative and complete — a call it does not declare is genuinely a mistake"; it is seeded with `Rigor::Plugin::Base` (this repository owns both the class and `sig/rigor/plugin/base.rbs`, kept in lock-step by the `lib` self-check) and MUST NOT include core / stdlib / third-party classes whose objects answer to methods their RBS omits. Resolution that reaches an allow-listed ancestor MUST be observationally identical to dispatching directly against that ancestor's RBS — so the normal `call.undefined-method` / `call.wrong-arity` rules apply to inherited contract calls, and the precision the ancestor's RBS carries flows to the call site. ADR-114 WD5: membership ALSO bypasses every decline of (b).

**(b) Core / stdlib ancestors (ADR-114).** When `kind` is `:instance` and `class_name`'s discovered SUPERCLASS chain reaches a class whose RBS declaration lives in the `rbs` gem's own `core/` or `stdlib/` tree (`RbsLoader#core_or_stdlib_class?`), the dispatcher MUST resolve the method against that ancestor's RBS — `class SubHash < Hash` answering `has_key?` as `bool`. It MUST decline when: the declaration's owner is `Object`, `Kernel` or `BasicObject` (the `::Object` MRO cut-off `Inference::ExternalAncestorResolution` owns); the class the declaration is written on is not itself core / stdlib; **the declaration's return type names the walked owner or one of that owner's own RBS instance ancestors**; `class_name` is an ADR-26 open receiver; `class_name` or a source ancestor carries issue #992's `DiscoveryIndex::ENVELOPE_DYNAMIC_MARK`; an ADR-17 `pre_eval:` patch declares the name on `class_name`, on a SOURCE ancestor between it and the owner, or on any RBS ancestor of the resolved owner; or the subclass or a nearer SOURCE ancestor declares the name (ADR-110 — `Scope#discovered_method_through_ancestors?` or `#user_def_through_ancestors`, each of which suppresses rather than answers on `Scope::ANCESTOR_WALK_LIMIT` exhaustion).

The return-type decline is ADR-114 WD7 and is load-bearing for ADR-5: CRuby PRESERVES the subclass where core / stdlib RBS names the base class (`SubHash#merge` → `SubHash`, `SubPathname#basename` → `SubPathname`), so adopting such a declaration yields a `Nominal` of an RBS-KNOWN class for a value that is not one, and the negative rules read that as a closed surface and fire on correct code one hop downstream. The dispatcher MUST answer `Dynamic[top]` there rather than substituting the receiver: the two families (`String#upcase`, which really returns `String`, and `Hash#merge`, which does not) are indistinguishable in RBS. The test MUST look for the owner ANYWHERE in the return type, descending through union members, the inside of an optional, and type ARGUMENTS: `Pathname#children: () -> Array[Pathname]` hands back an array of SUBCLASS instances, so restricting the test to the top level leaves the same false positive one level down. A `Bases::Self` / `Bases::Instance` return is NOT affected: those already substitute the receiver, which is what CRuby does. Type variables are NOT inferred from the subclass: the receiver carries no type arguments, so free variables degrade to `Dynamic[top]` per the translator's contract (`SubHash#keys` is `Array[Dynamic[top]]`, which is what a raw `Hash` receiver answers). The include / prepend edge is deliberately NOT walked here (#527 slice 2); the walk passes `mixins: false`. Both chain walks MUST carry a visited set so a malformed cyclic `class A < B` / `class B < A` source cannot loop.

**(c) Included-module ancestors (#1173).** When `kind` is `:instance` and `class_name`'s discovered ancestor walk reaches an `include` edge whose resolved owner is an RBS-known MODULE (`Environment#rbs_module?` — a project `sig/`, bundled core / stdlib, or shipped gem signature), the dispatcher MUST resolve the method against that module's RBS definition: `include M` inserts M into the ancestor chain outright, so the declaration IS the method the runtime dispatches to, and the "which classes may be read as complete" question the superclass arms exist to answer does not arise. The walk runs `Inference::ExternalAncestorResolution.resolve` with `mixins: true` over `Scope#external_ancestor_name_candidates`, which MUST emit candidate groups in instance-ancestor search order: a node's include edges precede its superclass edge, `includes_of` supplies them nearest-first (a later `include` statement nearer, one statement's arguments in written order), and the walk is depth-first so a resolved ancestor's own sub-chain precedes the includer's superclass (`class C < Hash; include M` where `M` includes `Widen` searches `Widen` before `Hash`). An answer whose owner is a CLASS MUST still decline — a non-core superclass is (b)'s deferred sibling question, not this arm's. It MUST decline under the same shadow guards as (b): the declaration's return type names the walked owner or one of its own RBS instance ancestors; `class_name` is an ADR-26 open receiver; `class_name` or a source ancestor — include edges walked too, since a source module in the chain sits ahead of the owner — carries `ENVELOPE_DYNAMIC_MARK`; a `pre_eval:` patch declares the name on the receiver, an intervening source ancestor, or an RBS ancestor of the owner; or the subclass or a nearer source ancestor declares the name. A `-> self` / `-> instance` return MUST substitute the RECEIVER class (an included module's `self` is the includer), and method-level type variables bind from the call's argument positions exactly as a direct dispatch's do.

When the resolved RBS method has multiple overloads, Slice 4 phase 2c selects one of them through `Rigor::Inference::MethodDispatcher::OverloadSelector`. The selector MUST:

- Filter overloads by positional arity. The actual `arg_types.size` MUST satisfy `required_positionals.size + trailing_positionals.size <= n` and either `rest_positionals` is present or `n <= required + optional + trailing`.
- Skip overloads whose `required_keywords` is non-empty. Slice 4 phase 2c does not thread keyword arguments through the call site, so a keyword-required overload is unreachable from the current call shape.
- Among the remaining overloads, MUST consult `param_type.accepts(arg_type, mode: :gradual)` for every (formal, actual) positional pair (rest positionals consume one declaration repeatedly). An overload matches when every pair returns `yes` or `maybe`.
- A `Type::StructClass` or `Type::DataClass` actual MUST be accepted by the raw class-object nominals `Class`, `Module`, `Object`, and `BasicObject`. An applied `Class[T]` MUST instead test `T` against the factory's instance class (`Struct` / `Data`, or its known assigned name); an unrelated `T` MUST be rejected. Singleton acceptance MUST use the known factory ancestry even when the carrier has an assigned project class name, so an unresolved name cannot turn a provably unrelated singleton into `maybe`.
- Before matching, the selector MAY reorder the overload list by receiver affinity (`ReceiverAffinity.reorder`), demoting arms whose parameter class is a disjoint sibling of the receiver class, so an arm another gem's RBS reopened onto the class (`Integer#+(BigDecimal)`) cannot win purely by declaration position. Every rule below reads that reordered list.
- Matching then runs as three ordered passes, and the first pass to produce a candidate wins: (1) **strict** — an overload whose every positional parameter translates to a concrete carrier (no `Alias` / `Interface` / `Intersection`, all of which the translator degrades to `Dynamic[top]` and which therefore accept anything) and accepts its actual; the pass is skipped entirely when any actual is *imprecise*, because gradual acceptance would then lock in an arbitrary strict arm; (2) **alias-strict-arm** — for overloads whose parameters are all strict-or-known-core-alias, the actual is matched against the alias's strict arm, so `Array#*(::int)` wins over `Array#*(::string)` for an Integer actual even though both parameters translate to `Dynamic[top]`; this pass is likewise skipped when any actual is imprecise; (3) **gradual** — the plain `accepts(…, mode: :gradual)` match, excluding an overload whose parameter is value-pinning (`nil` or a literal) when the actual is the bare `Dynamic[top]`, so a value-precise arm cannot inject a false constant on argument imprecision alone. "First match in declaration order" therefore binds *within* a pass, never across them.
- An actual is **imprecise** when it is the bare `Dynamic[top]` or a `Union` with a `Dynamic[top]` member (`Dynamic[top] | nil`, `Dynamic[top] | Integer`). The untyped member may reach any overload at runtime, so a strict or alias-strict match keyed on the union's other members is decided by those members alone: treated as precise, `Dynamic[top] | nil` pinned `Regexp#match?: (nil) -> false` and typed a live predicate as the literal `false` (#1021). A `Dynamic` whose static facet is not `top` (`Dynamic[String]`) is not imprecise; its facet discriminates. When an imprecise actual reaches the gradual pass, the selector returns *every* gradually-matching overload instead of the first, and the dispatch layer answers the union of their returns, wrapped in `Dynamic` when the returns differ (#521); with only precise actuals the gradual pass keeps its single first match. The value-pinning exclusion stays keyed on the bare `Dynamic[top]`: gradual acceptance still reads the whole union, so a value-pinning parameter that accepts it (`nil` against `Dynamic[top] | nil`) keeps its overload among the candidates and its return joins the union, while one that rejects a precise member (`nil` against `Dynamic[top] | Integer`) does not.
- When no pass matches, fall back to the first overload in the reordered list that does not *require* a block, and only then to that list's first element. The pass structure and this fallback are the normative deviations from "first match wins": both preserve the fail-soft contract of Slice 4 phase 1 / 2b for call sites whose actual argument types cannot be matched by any overload (because of `untyped`-degraded interfaces, generics, or callers we have not yet wired in), and the block preference keeps a no-block `[1, 2].filter` from adopting the block-bearing arm's `Array[Elem]` when the call actually yields an `Enumerator`.

Implementations MAY pre-translate parameter types per overload for performance, but MUST NOT cache results across `(class_name, method_name)` keys because `self_type` and `instance_type` substitution depends on the dispatch site.

`Rigor::Inference::RbsTypeTranslator.translate(rbs_type, self_type:, instance_type:, type_vars:)` is the only normative path from `RBS::Types::*` to `Rigor::Type`. It MUST be deterministic, MUST NOT raise on any well-formed RBS type, and MUST follow the mapping documented in [`docs/adr/4-type-inference-engine.md`](../adr/4-type-inference-engine.md). The substitution keywords are independent:

- `Bases::Self` MUST be substituted by `self_type:`. For singleton dispatch it is `Singleton[C]`. For instance dispatch it is `Nominal[C]`, except that a receiver whose projection carries type arguments substitutes a nominal **with arguments** built by `MethodDispatcher::SelfSubstitute` ([#1092](https://github.com/rigortype/rigor/issues/1092)), so `Array[Integer]#tap {}` is `Array[Integer]` rather than the raw `Array`. The rules for that substitute:
  - Every type argument MUST be widened deeply: a value-pinned type (a `Constant`, a refinement, a bounded integer or float) to its nominal base (`Type::Combinator.widen_value_pinned`), a nested `Tuple` to `Array[E]` over its widened element union `E`, a nested `HashShape` to `Hash[K, V]` over its widened key and value unions (an empty one to the raw nominal), recursing through unions, applied nominals and `Dynamic[T]`. A block can mutate the receiver, at any depth, through its yielded alias, which `MutationWidening` does not follow, so no literal or shape fact inside the arguments bounds the call's value: `[:a, :b].tap { |l| l << :c }` answering `Array[:a | :b]` would fold `.last == :c` to false, and `[[1, 2]].tap { |a| a[0] << 3 }` answering `Array[[1, 2]]` would fold `.first.size == 3`.
  - When every widened argument is the bare `Dynamic[top]`, the substitute MUST be the raw `Nominal[C]`, which carries the same information.
  - A `Tuple` / `HashShape` receiver MUST substitute its projected nominal (`[1, 2].tap {}` is `Array[Integer]`, `{ a: 1 }.tap {}` is `Hash[Symbol, Integer]`), never the shape itself. The pure self-returners `freeze` / `dup` / `clone` / `itself` keep the shape through ShapeDispatch, above this tier (ADR-76 WD3). A method in `MutationWidening::ARRAY_MUTATORS` (on a `Tuple`) or `HASH_MUTATORS` (on a `HashShape`) MUST keep the raw `Array` / `Hash`: `[1, 2].push(3)` is `Array`.
  - A `Nominal` receiver keeps its arguments unless the method may change its element, key or value types. By method name: the type-preserving in-place methods (`sort!`, `sort_by!`, `reverse!`, `uniq!`, `compact!`, `shuffle!`, `rotate!`, `select!`, `filter!`, `reject!`, `keep_if`, `delete_if`, `delete`, `subtract`, `clear`, `compare_by_identity`, `rehash`, `reset`) keep them. The element adders (`<<`, `push`, `append`, `unshift`, `prepend`, `add`, `add?`, and `insert` after its index) keep them only when the receiver has one type argument and every added argument is precise (no `Dynamic` member) and accepted by it (`ints.push(1)` is `Array[Integer]`, `ints.push("s")` is `Array`). The collection adders (`concat`, `merge`, `merge!`, `update`) keep them only without a block and when every argument is precise and accepted by `Nominal[C, args]`. Every other name in `ARRAY_MUTATORS` / `HASH_MUTATORS`, and every other `!` method, MUST degrade to the raw `Nominal[C]` (`ints.map!(&:to_s)`, `ints.replace(%w[a b])`, `ints.fill("x")`, `h.transform_values!(&:to_s)`). Any other method keeps the arguments.
  - A `Refined` / `Difference` receiver follows the rules for its base. A `Dynamic[T]` receiver MUST keep its wrapping: when `T` has a substitute `S` under these rules, the substitute is `Dynamic[S]`. Overload selection and `ReceiverAffinity` still read the static facet.
  - A receiver with no type arguments (a raw nominal, a `Constant` such as `1.tap {}`, which is `Integer`, an empty shape) substitutes `Nominal[C]` as before. The user-class fallback's `self_type_override` (the original receiver, dispatched through `Object`) takes precedence over all of the above.
  - The block-parameter probe (`RbsDispatch.extract_block_param_types`) consults the SAME verdict [#1130](https://github.com/rigortype/rigor/issues/1130): a block parameter that receives `self` (`Object#tap` yields it) substitutes the receiver's type arguments exactly when this policy keeps them, so `ints.tap { |a| }` binds `Array[Integer]` rather than the raw `Array`. The probe MUST reuse the verdict without the return path's value-pin widening: the block parameter is a destructure source, so the receiver's OWN type arguments stand (`[1, 2].tap { |a, b| }` binds the pinned element union `1 | 2` per slot through the binder's auto-splat, the parity the explicit `a, b = [1, 2]` element family gets), and a decline (an element-changing mutator) keeps the raw nominal. Both paths share ONE substitution decision; only the return path widens.
- `Bases::Instance` MUST be substituted by `instance_type:`. The dispatcher passes `Nominal[C]` regardless of dispatch kind so that `def self.create: () -> instance` resolves to `Nominal[C]` even when the receiver is `Singleton[C]`.
- `Variable` (Slice 4 phase 2d) MUST be substituted by `type_vars:`. The map is keyed by the RBS variable's `name` symbol (`:Elem`, `:K`, `:V`, ...). Bound variables MUST be replaced by the bound `Rigor::Type` value; unbound variables MUST degrade to `Dynamic[top]`.
- `ClassInstance` MUST translate its `args` recursively through the same `translate` call so `::Array[Elem]` round-trips into `Nominal["Array", [type_vars[:Elem]]]`. `Tuple` and `Record` already carry that recursion (Slice 5 phase 1; see the shape-dispatch contract below). `Proc` still translates to a bare `Nominal["Proc"]` and follows the same rule when it grows generic carriage.
- Any keyword MAY be omitted; the corresponding RBS token then degrades to `Dynamic[top]`. The `type_vars:` default MUST be the empty hash so the keyword does not influence non-generic calls.

Future slices that refine the mapping (intersection, interfaces, alias resolution) MUST keep the existing entries' outputs unchanged on the gradual-typing axis: any tightening of precision MUST be a non-breaking change to subtyping queries against the result type.

The Slice 4 phase 2d generic dispatch contract MUST also satisfy:

- `Rigor::Type::Nominal` MUST carry an ordered, frozen `type_args` array. The empty array MUST denote the "raw" form (`Array`) and any non-empty array MUST denote an applied generic (`Array[Integer]`). Two carriers MUST compare structurally equal only when both `class_name` AND `type_args` match.
- `Rigor::Environment::RbsLoader#class_type_param_names(class_name)` MUST return the class's declared type-parameter names as `Array<Symbol>`, drawing from the instance definition because singleton methods parameterize over the same names. It MUST return an empty array for non-generic classes and for unknown names (fail-soft).
- The dispatcher MUST build the `type_vars` map by zipping `class_type_param_names` against the receiver's `type_args`. Empty `type_args` (raw receivers and singletons) MUST yield an empty map so free variables degrade as before. A receiver with FEWER `type_args` than declared parameters MUST bind the supplied prefix in declaration order and leave the omitted trailing names unbound (they degrade to `Dynamic[top]` like any other free variable): that is the partial application RBS itself licenses when a trailing parameter declares a default, and it is the shape the generic dispatch surface is handed its own answers in — `Enumerable#lazy: () -> Enumerator::Lazy[Elem]` against `class Enumerator::Lazy[out E, out R = void]` is the worked case (issue [#1121](https://github.com/rigortype/rigor/issues/1121)), and withholding the whole map there left the element unbound, collapsing the first chained call's element type to `Dynamic[top]`. MORE `type_args` than parameters MUST yield an empty map: nothing licenses positionally assigning a surplus argument, so the map is withheld entirely rather than silently truncated or padded. A class whose parameter names are unknown (`class_type_param_names` empty) MUST keep the empty map, as above.
- The dispatcher MUST thread the same `type_vars` map through both the overload selector and the final return-type translation, so parameter types like `::Array[Elem]` substitute Elem before the accepts check rather than degrading to `Array[Dynamic[top]]`.

Method-level type parameters — the names the SELECTED overload declares in its own `type_params`, as opposed to the class-level names above — are bound from two positions, and the contract MUST satisfy:

- The block-return position (Slice 6 phase C sub-phase 2): when a `block_type:` is supplied and the overload's block return type is spelled as a bare `RBS::Types::Variable` naming a declared method-level parameter, that name MUST be bound to `block_type`.
- The argument position (issue #303): each positional parameter (required, then optional, zipped against the call's argument types in declaration order) whose declared type is EXACTLY a bare `RBS::Types::Variable` naming a declared method-level parameter MUST be bound to the corresponding argument's type. A variable reachable only through a container position (`Array[T] arg`), a rest positional, or a keyword parameter MUST NOT be bound; the dispatcher MUST NOT walk into the declared type looking for one.
- The one container position that IS admitted (issues #834, #862): a positional parameter declared as `Range[A]`, where `A` is a bare `RBS::Types::Variable` naming a declared method-level parameter, matched against a Range argument that names its own element. Two argument carriers qualify. A `Constant[Range]` whose endpoints are literals MUST bind `A` to the union of those endpoints lifted to their own classes — `Integer` for `1..9`, not `1 | 9` — which is the reading `ExpressionTyper` already gives a non-constant range literal's element parameter. A `Nominal[Range, [T]]` (the carrier `ExpressionTyper` hands back for a range literal with no literal endpoint, such as `1..ARGV.size`) MUST bind `A` to `T` when `T` is a `Nominal` or a union of `Nominal`s. Every other `T` — `untyped`, a `Dynamic`, a still-unbound type variable, a raw `Range` with no type args, any other type-arg arity — MUST decline: the caller's `self | A` would then read as `self | unknown` while claiming to be inferred. `Comparable#clamp: [A] (Range[A]) -> (self | A)` otherwise leaves `A` unbound and `i.clamp(1..9)` answers `Dynamic[top] | Integer` on a plain `Integer` receiver. The exception MUST NOT generalise to other containers: a `Range` is immutable and its element type is fixed at construction, whereas an `Array[T]` argument's carrier is mutable and may have been widened long before the call reached here.
- A name already present in the `type_vars` map MUST keep its binding, so a receiver-derived class-level binding and the block-return binding both outrank an argument. An argument whose type is `Dynamic[top]` carries no evidence and MUST contribute no binding; the variable then degrades to `Dynamic[top]` as an unbound variable does. Repeated occurrences of one name across positions MUST be unioned.
- The argument-position binding MUST be declined at any call site the dispatcher cannot prove is free of a user redefinition shadowing the resolved method — otherwise a benign mis-resolution (a self-send resolving through `Kernel`'s RBS because the receiver's class has none) is converted from an imprecise `Dynamic[top]` into a confidently WRONG precise type. It MUST therefore be gated on `scope` AND `call_node` both being present (which excludes the ancestor-fallback dispatch path, where they are nil by construction) AND on the scope carrying neither a discovered top-level `def` of the method name nor a discovered method of the resolved kind on the resolved class. The block-return binding is not gated: a block-typed call resolves its variable from the caller's own block, not from the resolved method's identity.

`RbsDispatch` reads the resolved overload's declared return type and MUST NOT reinterpret it, with one bounded exception (issue #661). `Kernel#<=>: (untyped other) -> 0?` is the identity comparison — `0` when the operands are the same object, `nil` otherwise — and every class inherits it. When `<=>` resolves through inheritance to that declaration on an INSTANCE receiver whose class is not `Kernel`, `Object` or `BasicObject`, the tier MUST answer `Integer?` instead: the literal `0` is a value-precise claim about an operator the receiver's signature was never required to mention, so under [ADR-5](../adr/5-robustness-principle.md) it is not a statement about the call. The cost of not widening is not confined to the expression — narrowing `n = a <=> b; … if n` reads the truthy arm as the literal `0` and folds a comparison branch to `bot`. The three owning classes MUST keep `0?`, a class that DECLARES its own `<=>` MUST keep its own return type unchanged, and the exception MUST NOT generalise to other inherited `Object` / `Kernel` selectors — `to_s`, `hash` and `inspect` carry no value-precise return to lose, and what an inherited universal signature may assert about a subclass in general is a larger question this does not settle.

The nominal-acceptance contract (`Rigor::Inference::Acceptance`, the `Nominal` self / `Constant` other route) MUST satisfy:

- A `Nominal[C, [T…]]` self MUST decide a `Constant[v]` other on the value's class alone (`v.is_a?(klass(C))`, or the value's ancestor chain when `C` is not loadable), ignoring its own `type_args`. A value-pinned literal carries a value, not a generic instantiation, so there is nothing in it to refute the args against and refuting them anyway would reject correct code.
- **A `Range` value is the one exception** (issue #833). The engine builds `Constant[Range]` only when both endpoints are static, so the element the range yields IS known. When the value is a `Range` and the self carries EXACTLY one type arg `T`, acceptance MUST additionally require that every non-`nil` endpoint, lifted to `Constant[endpoint]`, is accepted by `T` under the same mode; a `nil` endpoint MUST contribute nothing, because a beginless or endless literal inhabits `Range[T]` for every `T` (`Range[Integer?]` is core RBS's spelling of the slicing parameter). A raw `Range` with no type args, any other type-arg arity, a range with no endpoint at all (`nil..nil`), and a range whose endpoints are not literals MUST all keep the class-level answer. The rule MUST NOT be extended to any other constant class. Without it `Nominal[Range, [Integer]]` accepted `0.0...1.0` and overload selection pinned whichever `Range[…]` arm came first in declaration order — for `Kernel#rand` that is `(::Range[Integer]) -> Integer?`, ahead of every Float arm.
- **Known coarse spot, deliberately not special-cased.** A mixed-endpoint literal (`1.0..2`) is rejected by `Range[Integer]` and by `Range[Float]` alike, so overload selection falls through the strict pass to the gradual pass and then to the first-overload fallback, exactly as it did before the exception existed. Reading such a literal precisely would mean modelling a `Range[Integer | Float]` the RBS side never declares.

The Slice 5 phase 1 shape-dispatch contract MUST also satisfy:

- `Rigor::Type::Tuple` and `Rigor::Type::HashShape` MUST be projected onto their underlying nominal carriers when used as dispatch receivers. `Tuple[T1..Tn]` projects to `Nominal["Array", [union(T1..Tn)]]` (raw `Array` for empty Tuples); `HashShape{k: T,...}` projects to `Nominal["Hash", [union(constant_keys), union(values)]]` (raw `Hash` for empty shapes). The projection MUST be confined to `RbsDispatch.receiver_descriptor`; the surface contract on the carriers themselves MUST stay value-object thin.
- `Rigor::Inference::Acceptance` MUST treat shape carriers symmetrically with their projected nominal:
  - A nominal `self` MUST accept a shape `other` by projecting the shape and recursing through the existing nominal-acceptance route, so `Nominal[Array, [Integer]].accepts(Tuple[Constant[1], Constant[2]])` is equivalent to `Nominal[Array, [Integer]].accepts(Nominal[Array, [union(Constant[1], Constant[2])]])` and yields the same result.
  - A `Tuple` `self` MUST require `Tuple` `other` of equal arity, and recurse element-wise (covariant). Mismatched arity MUST collapse to `no`. Non-Tuple `other` MUST be rejected because the analyzer cannot prove arity from a generic nominal alone.
  - A `HashShape` `self` MUST require every required key of `self` to be required in `other` (depth covariant on shared entries). Optional keys on `self` MAY be absent in `other`; when present, their values MUST satisfy the same depth check. A closed `self` MUST reject known extra keys and open-extra-key sources; an open `self` MAY accept wider shapes. Missing required keys MUST collapse to `no`. Non-HashShape `other` MUST be rejected; nominal-side projection lives on the `accepts_nominal` route, not on the HashShape route.
- `Rigor::Inference::RbsTypeTranslator` MUST map `RBS::Types::Tuple` and `RBS::Types::Record` to the dedicated shape carriers (NOT to `Nominal[Array]`/`Nominal[Hash]`). Element and field types MUST be translated recursively under the caller's `self_type:` / `instance_type:` / `type_vars:` context, so generics inside tuples and records survive the boundary. `Record` MUST translate required fields from `RBS::Types::Record#fields`, optional fields from `#optional_fields`, and mark the resulting `HashShape` as closed.
- `Rigor::Inference::ExpressionTyper` MUST upgrade non-empty array literals whose every element is a non-splat value to `Tuple` carriers; literals containing splats MUST keep the Slice 4 phase 2d `Nominal[Array, [union]]` form so `[*xs, 1]` still produces an inferable element type. `ExpressionTyper` MUST upgrade hash literals whose every entry is an `AssocNode` with a static `SymbolNode` or `StringNode` key (with a non-`nil` `value`/`unescaped`) to `HashShape` carriers; literals with `AssocSplatNode` entries, dynamic keys, or duplicate keys MUST fall through to the `Nominal[Hash, [K, V]]` form. Integer-endpoint `RangeNode` literals MUST be carried as `Constant[Range]` so shape dispatch can resolve tuple range slices; dynamic ranges MUST remain `Nominal[Range]`.

When the receiver of a call is a `Rigor::Type::Dynamic` and no positive dispatcher tier matches, `ExpressionTyper#call_type_for` MUST return `Dynamic[top]` *silently*, without recording a `FallbackTracer` event. This is a recognised semantic outcome — the value-lattice algebra in [`value-lattice.md`](../type-specification/value-lattice.md) requires Dynamic to propagate through opaque method calls — and not a fail-soft compromise. Receivers that are not Dynamic still trigger the standard fail-soft fallback (with a tracer event) when no rule resolves.

The Slice 5 phase 2 shape-aware dispatch tier (`Rigor::Inference::MethodDispatcher::ShapeDispatch`) MUST run between the constant-folding tier and the RBS-backed tier so that `Tuple` and `HashShape` receivers resolve element-access methods to their precise per-position / per-key type rather than the projected `Array#[]` / `Hash#fetch` answer. The tier MUST handle the following catalogue, returning `nil` to defer to `RbsDispatch` when the call cannot be proved against the static shape:

- Tuple receivers: `first`, `last`, `size`/`length`/`count` (no-arg, no-block) MUST return the precise tuple element / `Constant[size]`. `[]` and `fetch` with a single `Constant[Integer]` argument MUST normalise negative indices by length and return the precise element when the index is in `[-size, size)`; out-of-range indices MUST defer (`nil`) so the projection answer applies for `fetch` (which would raise) and MUST resolve to `Constant[nil]` only when invoked through a chain step (see `dig` below). `[]` with `Constant[Range]` integer/nil endpoints and `[]` with two `Constant[Integer]` arguments MUST use Ruby `Array#[]` slice semantics and return a sliced `Tuple` or `Constant[nil]` for statically nil slices; `fetch` MUST NOT claim those forms. `dig` MUST recurse through the resolved member: a `Tuple`/`HashShape` member MUST re-dispatch into the catalogue with the remaining arguments; a `Constant[nil]` member MUST short-circuit the chain (Ruby's `Array#dig` does the same at runtime); other Constants and any non-shape carrier MUST defer so the projection answer applies. An out-of-range index that arises *during* a chain step MUST resolve to `Constant[nil]` because Ruby's `Array#dig` returns nil for out-of-range indices rather than raising.
- HashShape receivers: `size`/`length` (no-arg) MUST return `Constant[size]` only when the shape is closed and no known key is optional. `[]` and `fetch` with a single `Constant[Symbol|String]` argument MUST return the precise value when a required key is declared. Optional-key `[]`/`dig` MUST return `value | nil`, while optional-key `fetch` MUST defer because the key may be absent and Ruby would raise `KeyError`. On a **closed** shape a key outside `pairs` is provably missing and MUST resolve to `Constant[nil]` for `[]` (matching Ruby's runtime behaviour) and MUST defer for `fetch`. On an **open** shape (`extra_keys: :open`) a key outside `pairs` is *unknown*, not missing — the policy states that keys beyond `pairs` are permitted, so such a key MAY hold a value of any type — and every read of it (`[]`, `fetch`, `dig`, `values_at`) MUST resolve to `untyped`. Typing it `Constant[nil]` would be unsound in the direction that costs most: it puts `call.undefined-method` on the next line of correct code (`payload[:undeclared].upcase`). `dig` MUST follow the same chain semantics as Tuple `dig`: a single static key resolves to the precise value (or `Constant[nil]` for a key missing from a closed shape); a multi-key chain recurses with the resolved value as the new receiver, and a chain that reaches an `untyped` step MUST stay `untyped` for its remainder. `values_at` with one or more `Constant[Symbol|String]` arguments MUST return a `Tuple` whose per-position values are the per-key values, with keys missing from a closed shape filled by `Constant[nil]`. Falls through (defers) when any argument is non-static or when the call has zero arguments.

This mirrors the erasure rule in [rbs-erasure.md](../type-specification/rbs-erasure.md) § *Open shapes with extra-value bounds*: the known value union constrains only the declared entries, never an unseen extra key. Key-set-narrowing operations (`slice`, `except`, `merge`, `fetch_values`, `invert`, `size`) are already gated on `closed?` and MUST stay so — none of them can state a result whose key set is only partly known.

The shape tier MUST NOT consult the RBS environment, MUST NOT raise on any input, and MUST NOT touch the fallback tracer; it is a pure refinement layered on the type carriers. Methods outside the catalogue, non-static keys/indices, non-integer ranges, and any `dig`/`values_at` call whose chain steps cannot be resolved statically MUST defer so the projection-based `RbsDispatch` answer applies.

That deferred-to answer is **nil-free for a lookup that can miss**, and this is a deliberate choice rather than a gap. Core RBS declares `Hash#[]: (K) -> V` and `Array#[]: (int) -> Elem`, spelling the miss as an `%a{implicitly-returns-nil}` annotation instead of an `?` return; `RbsDispatch` reads the return type only and MUST NOT honour that annotation. Honouring it is rejected on false-positive grounds: a `Hash.new(0)` / `default_proc` receiver never returns nil, and a projected `V?` therefore fires `possible nil receiver` on correct code (measured on Rigor's own `lib`: 25 firings, every sampled one a false positive — `Hash.new { … }` and `Hash.new(0)` reads, plus `Array#max` on a provably non-empty receiver). A value union from a non-static-key `[]` is consequently **optimistic, not proof**: it omits nil because pessimising the common defaulted-Hash idiom costs more than the miss it would model, so `MAP[key]` reading as `"x" | "y"` asserts nothing about whether the key is present.

Certainty judgments MUST treat it that way. Per [ADR-78](../adr/78-reflexive-overfold-always-truthy.md) WD1, provable truthiness may rest only on a genuine constant, never on a fold whose soundness is conditional on a narrower form than the actual expression. A nil-free value union produced from a dynamic key is exactly that shape: sound for the keys the shape declares, applied to a read that may match none of them.

**This exclusion binds every reader of the judgment, and there are three.** `flow.always-truthy-condition` and the `&&`/`||` `constant_value_polarity` gate it shares (`StatementEvaluator#right_operand_dead?`, which both positions read) MUST NOT conclude truthiness from such a value, and MUST enforce that by consulting the mark rather than by restricting the carrier: a `Constant`-only gate is **not** sufficient, because a literal hash whose values share one type reads as a lone `Constant`, so `UNIFORM[key] || key` discards the author's fallback and `if UNIFORM[key]` fires the rule with no widening involved (issue #313). Any widening of the gate beyond `Constant` (issue #152, evaluated and declined) MUST likewise preserve this exclusion. The third reader is the `if`/`unless` branch elision — `Narrowing.predicate_certainty` as consumed by `StatementEvaluator#live_branch_for_if`/`#live_branch_for_unless`, which a value-position conditional reaches through the same evaluator — and per [ADR-101](../adr/101-optimistic-carrier-branch-elision.md) it MUST decline a verdict whose carrier is marked optimistic, for the same reason and with a wider effect: the gate above only withholds a diagnostic, whereas the elision deletes a branch the program really takes when the lookup misses.

The mark is `Rigor::Inference::OptimisticOrigin`, recorded where the dispatcher reads past the annotation and propagated as a side channel in the [ADR-75](../adr/75-dynamic-provenance.md) / [ADR-82](../adr/82-dynamic-provenance-wiring.md) sense: it MUST NOT participate in subtyping, consistency, normalization or erasure, and no diagnostic MUST fire from it. Three properties are normative. It is decided **per selected overload**, so `Array#first` is marked while `Array#first(3)` is not, and a signature that already spells the miss as `?` (`String#[]`, `Enumerable#find`) is never marked. It MUST NOT be applied to a read the shape tier resolved, because `ShapeDispatch` answers from a receiver that proves the read cannot miss (a static key on a declared shape, `first` on a non-empty `Tuple`). And the decline MUST be implemented at the consumers, never by widening `Narrowing.falsey_nominal?` / `.narrow_falsey`, which `&&=`/`||=` and the and/or surviving-left edge also read — widening the falsey fragment there re-admits `nil` into a bound local and costs `possible nil receiver` false positives.

**The exclusion binds the predicate a consumer actually reads, not only the bare carrier.** A guard is normally written `v.nil?`, `!v.nil?` or `v.nil? || w.nil?`, and each of those folds to a `Constant` of its own; treating that `Constant` as unmarked laundered the optimism straight through the gates (issue #313). Resolving the mark for an expression MUST therefore derive it through the folds that restate the carrier's nil-ness: an argument-free, blockless `nil?` or `!` call resolves to its receiver's mark, a blockless `==` / `!=` / `eql?` / `equal?` / `===` with exactly one argument where exactly one operand is the `nil` literal (`v == nil`, `nil != v`) resolves to the other operand's mark (issue [#1094](https://github.com/rigortype/rigor/issues/1094) — the same statement as `v.nil?`, spelled as a comparison), an `&&` / `||` node to either operand's, a single-statement parenthesised body to that statement's, and a local / ivar bound to any of those carries it onward exactly as a bare copy does. The derivation MUST stop there: a value predicate (`empty?`, `zero?`, `any?`), and a comparison against anything but the `nil` literal, folds from the carrier's *value* rather than its nil-ness, and deriving through it would widen this channel into a general taint that silences honest verdicts. One resolver MUST own the judgment for all three consumers, since a per-consumer copy is what let them disagree.

**The fold must also not stand as the predicate's own type.** The derivation above reaches only consumers that can see the AST and the scope's mark table; a folded `Constant[false]` on `v.nil?` additionally travels where the mark cannot — into the enclosing method's return summary, so a helper ending in `!h[k].nil?` published `Constant[true]`, and a caller's `if helper(…)` reported `flow.always-truthy-condition` on a guard a missing key makes live (issue [#1172](https://github.com/rigortype/rigor/issues/1172); the three `lib/` firings are the same shape — two call sites of `raise_duck_exception?` in `check_rules.rb` and one of `nil_class_defines?` in `expression_typer.rb`). A call whose mark is *derived through* the predicate folds above MUST therefore NOT type as `Constant[true]` / `Constant[false]`; `ExpressionTyper` widens that answer to `bool` (`Constant[true] | Constant[false]`) at the call's type funnel. A cause recorded on the call node itself is the carrier's own mark, and the carrier's type is unchanged — `h[k]` still reads nil-free even when `V` is a literal `true`/`false` — and a predicate over a proof-carrying receiver still folds: the gate is the derived mark, not the predicate's shape.

Carrier shape MUST NOT be used as a proxy for this judgment. A `Hash` whose values share one type yields a lone `Constant`, which is exactly as optimistic as the union case; conversely most non-`Constant` carriers reaching a verdict are genuine proofs. Measured over eleven projects: 47 of 2,060 verdicts rest on the optimistic mark, while a non-`Constant` shape gate would decline 134 and still miss 12 of the 47 (`docs/notes/20260806-issue-286-optimistic-carrier-provenance-census.md`).

This split is normative: implementations MUST NOT define operator-method-aware subclasses of any `Rigor::Type` form (for example, a hypothetical `Rigor::Type::IntegerType` carrying `+`/`*` rules). Operator semantics MUST be expressed as method-handler entries that the dispatcher consults; specialising the type class for built-in arithmetic is rejected to keep the type lattice and method semantics independently extensible.

## Local Variables

Local variable read nodes (`Prism::LocalVariableReadNode`) MUST be looked up in the receiver scope. A bound name MUST return the bound `Rigor::Type`. An unbound name MUST fail soft to `Dynamic[top]` per the rule above; `Scope#type_of` MUST NOT raise on unbound locals.

Local variable write nodes (`Prism::LocalVariableWriteNode` and the targets that imply it) MUST be typed as the type of their value expression. Binding the result back into the scope is the responsibility of the statement-level evaluator (see Slice 3 in [`docs/adr/4-type-inference-engine.md`](../adr/4-type-inference-engine.md)); `Scope#type_of` itself MUST NOT mutate the scope.

## Statement-Level Evaluation

`Rigor::Scope#type_of` is a pure expression-level query and MUST NOT thread scope. The statement-level evaluator `Rigor::Inference::StatementEvaluator` (Slice 3 phase 2) sits next to it and provides the complementary scope-threading surface. Its public delegate on `Rigor::Scope` MUST exist:

```ruby
Rigor::Scope#evaluate(node, tracer: nil) #=> [Rigor::Type, Rigor::Scope]
```

The contract MUST satisfy:

- The first element of the returned pair MUST be the type that `node` produces, equivalent to what `Scope#type_of(node)` would return for a pure expression. The second element MUST be the scope observable AFTER `node` has run; for nodes that perform no scope effect this MUST be the receiver scope (compared with `==`, the receiver's identity MAY differ).
- The receiver scope MUST never be mutated. Internal recursion MUST allocate fresh `StatementEvaluator` instances for every forked scope so branches stay isolated and the equality of distinct branch outputs is observable.
- The `tracer:` keyword MUST be threaded into every nested `Scope#type_of` call so fail-soft fallbacks emitted while typing children of a statement-y node are recorded under the same tracer.
- An `evaluate` call against a node that the evaluator does not specialise MUST defer to `Scope#type_of(node, tracer:)` and MUST return the receiver scope unchanged. This preserves the Slice 1 fail-soft policy: an unrecognised statement-y node MUST NOT raise.

The catalogue of nodes that the evaluator MUST recognise in Slice 3 phase 2 is:

- `Prism::ProgramNode` and `Prism::StatementsNode` — sequential evaluation that threads scope through every child statement in declaration order. The body's value MUST be the type of the last statement (or `Constant[nil]` for an empty body); the post-scope MUST be the post-scope of the last statement.
- `Prism::LocalVariableWriteNode` — evaluates the rvalue under the entry scope and binds `name` to the resulting type via `Scope#with_local`. The pair's type MUST equal the rvalue type.
- `Prism::MultiWriteNode` (Slice 5 phase 2 sub-phase 2) — evaluates the right-hand side once under the entry scope, then walks the destructuring tree (`lefts` / `rest` / `rights`, with `rest` a `Prism::SplatNode` whose `expression` MAY be a `Prism::LocalVariableTargetNode`) and binds every named local through `Rigor::Inference::MultiTargetBinder`. The pair's type MUST equal the right-hand side's type (matching Ruby's `(a, b = [1, 2]) #=> [1, 2]` semantics). When the right-hand side is a `Type::Tuple`, per-slot bindings MUST be element-wise: missing front/back slots collapse to `Constant[nil]`, the rest slot binds to a `Type::Tuple` of the middle elements (`Tuple[]` when the source has no surplus). An `Array[T]` right-hand side (including a `Refined` / `Difference` over one) binds each fixed slot to `T` and the rest to `Array[T]`, and every fixed slot it binds MUST also be recorded through `Scope#with_optimistic_local` (issue [#1093](https://github.com/rigortype/rigor/issues/1093); § Multi-Target Binder below). A union right-hand side distributes over its members, and a value that provably has no implicit `to_ary` binds as the one-element tuple `[rhs]` (issue [#1094](https://github.com/rigortype/rigor/issues/1094); same section). Other right-hand sides bind every slot to `Dynamic[top]`. Nested `Prism::MultiTargetNode` targets MUST recurse through the same binder. Instance-variable targets (`@a, *@rest = xs`) MUST decompose by the same rules and bind through `Scope#with_ivar`, each optimistic slot recorded through `Scope#with_optimistic_ivar` — the mark a single `@x = xs.first` write already records (issue [#1110](https://github.com/rigortype/rigor/issues/1110)). Other non-local targets (class/global variables, constants, index/call targets, anonymous splat) MUST be silently skipped.
- `Prism::IfNode` and `Prism::UnlessNode` — evaluate the predicate first (its post-scope is shared by both branches), then evaluate each branch under the post-predicate scope. The result type MUST be the union of the two branch types; the post-scope MUST be the join-with-nil-injection of the two branch scopes (see below). A `nil` branch (no else / no then) MUST contribute `Constant[nil]` and the post-predicate scope.
- `Prism::ElseNode` — evaluates its body under the receiver scope, returning `[Constant[nil], scope]` for empty bodies.
- `Prism::CaseNode` and `Prism::CaseMatchNode` — evaluate the predicate first; every `WhenNode`/`InNode` body and the optional else-clause are evaluated independently under the post-predicate scope and merged with the same join-with-nil-injection rule generalised to N branches.
- `Prism::WhenNode` and `Prism::InNode` — evaluate their statements under the receiver scope; an empty body MUST be `[Constant[nil], scope]`.
- `Prism::BeginNode` — evaluate the primary path (body, then optional else-clause; the else-clause MUST replace the body's value while the body's scope effects still apply because the body did run before the else). Each `Prism::RescueNode` in the chain is an alternative exit path evaluated under the entry scope. The exit type MUST be the union of the primary and rescue exits; the exit scope MUST be the join-with-nil-injection of the primary and rescue scopes. When an `ensure_clause` is present, its scope effects MUST be layered on the joined exit scope, so locals bound exclusively in the ensure stay observable; the ensure's value MUST NOT contribute to the exit type.
- `Prism::WhileNode` and `Prism::UntilNode` — evaluate the predicate (its post-scope is observable in the body), then evaluate the body. The result type MUST be `Constant[nil]`. The base post-scope MUST be the join-with-nil-injection of the post-predicate scope and the single-pass post-body scope, modelling "body might have run zero or more times". [ADR-56](../adr/56-block-captured-local-mutation.md) slice B overlays a capped body-fixpoint result on that base for every local the body can rebind (`loop_rebind_fixpoint`, sharing the `Inference::BodyFixpoint` helper, cap 3, final `Constant→Nominal` widen, `Dynamic[top]` floor on non-convergence): a pre-existing local seeds with its post-predicate binding, a local first assigned inside the body seeds with `Constant[nil]` for the zero-iteration path, and the predicate's loop-entry edge is re-narrowed each iteration. A loop body that rebinds no local is byte-identical to the single-pass base.
- `Prism::AndNode` and `Prism::OrNode` — evaluate the LHS, then the RHS under the LHS's *narrowed* entry edge (the truthy edge for `&&`, the falsey edge for `||`; the Slice 6 rule, normative in § StatementEvaluator integration below). The result type MUST be `union(narrow_falsey(left_type), right_type)` for `&&` and `union(narrow_truthy(left_type), right_type)` for `||` — only the operand's short-circuiting fragment can be the node's value, so `s || full` with `s : String?` types `String | <full>` rather than re-admitting the stripped `nil`. When the left operand is a `Type::Constant` whose polarity makes the RHS dead (`false && b`, `1 || b`), the result type MUST be the left operand alone; this `constant_value_polarity` short-circuit MUST stay `Constant`-only and MUST decline a left operand whose `OptimisticOrigin` resolves against the LHS post-scope (issue #313, below). The dead RHS is still evaluated and its post-scope still joins, so only its value is dropped. The post-scope MUST be the join-with-nil-injection of the LHS and RHS post-scopes (modelling "LHS always ran; RHS only sometimes ran"), except when the RHS provably terminates (`a or raise`), where control never reaches a successor through the RHS edge and both the type and the scope MUST be the surviving LHS edge alone.
- `Prism::ParenthesesNode` — threads scope through the inner expression so `(x = 1; x + 2)` binds `x` and produces `Constant[3]`.
- `Prism::ClassNode` and `Prism::ModuleNode` — evaluate the body in a *fresh* scope (Ruby's class/module scope does NOT see the outer locals; it shares only the Environment). The body's value is the body's last statement (or `Constant[nil]` for an empty body); the post-scope MUST be the receiver scope unchanged because a class/module definition does not bind any local in its enclosing scope. The evaluator MUST push a new lexical class frame onto its `class_context` for the body's evaluation; nested `def`s consult the frame to resolve their RBS lookup. The frame's qualified name MUST be the rendered `constant_path` (e.g., `"Foo::Bar"` for `class Foo::Bar` and the join of every nested name for `class A; class B`).
- `Prism::SingletonClassNode` — same fresh-scope contract. When the singleton expression is `self`, the innermost lexical class frame MUST be flipped to `singleton: true` for the body's evaluation, so a `def foo` inside `class << self` resolves through `RbsLoader#singleton_method`. For non-`self` expressions the receiver class is not statically resolvable; the evaluator MUST keep the existing class context unchanged and accept that nested defs degrade to the `Dynamic[top]` parameter default.
- `Prism::DefNode` — builds the method-entry scope by binding every named parameter through `Rigor::Inference::MethodParameterBinder` (see below) and evaluates the body under that scope. The pair's type MUST be `Constant[:method_name]` (matching Ruby's runtime behaviour of `def` evaluating to a Symbol) and the pair's scope MUST be the receiver scope unchanged (a `def` does not introduce a binding in its enclosing scope). The body MUST NOT see the outer scope's locals.

### Self typing (Slice A-engine)

`Rigor::Scope` carries an optional `self_type:` field, accessed through `Scope#self_type` and updated via `Scope#with_self_type(type)`. The field is `nil` for top-level scopes and is injected by the `StatementEvaluator` at the boundaries where Ruby gives `self` a definite identity:

- `Prism::ClassNode` / `Prism::ModuleNode` body: `self_type` MUST be `Singleton[<qualified-name>]` (because `self` inside the class body is the class object itself).
- `Prism::SingletonClassNode` body when the receiver is `self`: same as above (the body still runs with `self` = the enclosing class object), and the innermost class frame additionally flips to `singleton: true`.
- `Prism::DefNode` body: when the def is on the singleton side (`def self.foo` or any def lexically inside `class << self`) or the surrounding class frame is already singleton, `self_type` MUST be `Singleton[<qualified-name>]`. Otherwise (an ordinary instance def), `self_type` MUST be `Nominal[<qualified-name>]` with no type arguments. Top-level defs (no enclosing class) MUST leave `self_type` as `nil`.
- The block body of a class-creating meta call — `Class.new`, `Module.new`, `Struct.new`, `Data.define`, each with a literal block and a receiver that is the bare constant (or its `::`-rooted spelling) — is a class body: Ruby evaluates it with `self` bound to the class the call creates. `self_type` MUST be `Singleton[<anonymous-name>]` and the class context MUST carry one non-singleton frame under the same name, so a `def` in the body binds an instance method on that class. Unlike a `class` keyword body the block is a closure, so the outer scope's locals MUST stay visible. The `<anonymous-name>` is the per-call-site synthetic name defined below. At constant-write rvalue position (`Prism::ConstantWriteNode`, issue #590; `Prism::ConstantPathWriteNode` since [#703](https://github.com/rigortype/rigor/issues/703)) the same boundary holds with the constant's qualified name in place of the anonymous one — the key `ScopeIndexer` files the body's methods and member layout under (`meta_new_block_body`) — and the frame is appended to the enclosing class context rather than replacing it, so a body nested in `module M` is keyed `M::Const`. A PATH target MUST take the name a compact `class Holder::Const` header at the same position takes (`Source::ConstantPath.declaration_prefix`), ROOTED reset included: `::Holder::Const = Struct.new(…) do … end` written in `module Admin` names `Holder::Const`, so the frame stack MUST reset to it rather than gaining a frame under `Admin`. Declining the path spelling registered no factory at all, so the constant answered `singleton(Struct)` and its instance `Struct` — a class RBS knows — and every member read and block-defined override in it fired `call.undefined-method` on code Ruby runs. The walk MUST choose the key by the ScopeIndexer's own recognition, never a re-spelling of it: a rvalue that recognition does not key by the constant (a `Struct.new(*names)` whose members are not literal Symbols) was registered under the anonymous name and MUST be entered under it. A constant write whose rvalue is not a meta-new block form is typed through the expression typer with the scope unchanged, as before. The recognised WRITE spellings are `Const = …`, `Holder::Const = …` and their `||=` twins (`Prism::ConstantOrWriteNode` / `Prism::ConstantPathOrWriteNode`, since [#963](https://github.com/rigortype/rigor/issues/963)), because `Const ||= Struct.new(…) do … end` names its class exactly as the plain write does wherever the constant is unset — the case the define-once idiom is written for. `&&=` and the operator writes MUST NOT be recognised: neither names a freshly created class. Two value-preserving rvalue wrappers MUST be unwrapped before the recognition, in both this walk and every `ScopeIndexer` walk that keys a body by the constant: a `.freeze` tail (`Struct.new(:a) do … end.freeze` — `Module#freeze` answers its receiver, so the constant still holds the created class), repeated tails included, and a `Const = Const || <rvalue>` guard whose guarded name is the constant being written, the long spelling of `||=`. Only the argumentless, blockless, receiverful `.freeze` qualifies; `&.freeze` MUST NOT be unwrapped, its value being the receiver OR nil, and a guard over a DIFFERENT name (`A = B || Struct.new(:x)`) MUST NOT be unwrapped — `A` may hold `B`, whose class it does not name. The constant-publication census MUST thread the name a write gives the block's class THROUGH a `.freeze` tail: the tail sits between the write and the call whose block the constant names, so dropping the name there leaves the factory call opaque and suppresses every `self::X = …` the block publishes. It MUST keep declining the `||=` spellings, which it records unpublishable for the constant itself.

#### Anonymous class names

A class created by `Class.new do ... end` away from constant-write position has no constant to be keyed by, yet it owns whatever its block body defines. `Rigor::Inference::AnonymousMetaClass.name_for(call_node, source_path)` MUST supply one, spelled by `Rigor::Type::AnonymousClassName` as `#<Label:key>` where `Label` is the receiver constant (`Class`, `Module`, `Struct`, `Data`) and `key` is `source_path:line:column` (the path segment omitted when the caller has none). The spelling MUST NOT be producible by `Source::ConstantPath.qualified_name`, so a synthetic name can never collide with a real class in the discovery tables, and every pass over the same file MUST derive the same name from the same pair.

`ScopeIndexer` MUST register the block body's methods, def nodes and (for `Class.new(Parent)`) superclass under that name, and `MethodDispatcher`'s `Class.new` lift MUST answer `Singleton[<anonymous-name>]` for the parentless block form. For the `Struct.new` / `Data.define` block forms — anonymous and constant-keyed alike — it MUST also register every literal-Symbol member as a discovered `:instance` reader, exactly as it does for a `class X < Struct.new(...)` superclass, so a member read inside the body resolves as the struct's reader rather than falling through to a same-named `Kernel` private (`lambda` would otherwise read as a `Proc`). The parented form (`Class.new(Parent) do ... end`) MUST keep answering `Singleton[Parent]`, except that a block-free `Class.new` whose parent is a `Type::StructClass` or `Type::DataClass` MUST preserve that carrier so downstream construction retains its member layout. A block on that `Class.new` MUST decline the carrier lift because it can redefine a synthesised reader; constant-keyed forms recover safe folding through the reader-override tables. `ScopeIndexer` MAY unwrap nested, single-parent, block-free `Class.new(...)` calls to find a root `Struct.new(...)` / `Data.define(...)` layout, but MUST decline when an intermediate `Class.new` wrapper or the root factory call has its own block because those overrides belong to an intermediate superclass and cannot be keyed safely to the outer class. A `def` in an anonymous body MUST additionally remain in the `<toplevel>` def table (never clobbering a real top-level `def` of the same name): the body is a DSL block whose methods routinely reach some other object's `self`, and the leniency predates the name.

`Type::Singleton#describe` / `Type::Nominal#describe` MUST render an anonymous name without its key (`singleton(#<Class>)`), and `#erase_to_rbs` MUST answer `untyped` for one — the name is not valid RBS.

`ExpressionTyper` consumes the field in two places:

- `Prism::SelfNode` MUST type as `scope.self_type` when set, or `Dynamic[top]` when nil. This MUST NOT record a fallback event in either case.
- `Prism::CallNode` with `receiver: nil` (an implicit-self call such as `attr_reader_method`, `private_helper`, ...) MUST adopt `scope.self_type` as the receiver type for `MethodDispatcher.dispatch`. When `self_type` is nil, the receiver remains nil and the existing top-level fallback applies.

`Scope#==` and `Scope#hash` MUST include `self_type`. `Scope#join` MUST keep `self_type` when both sides agree and reset it to `nil` when they differ. `Scope#with_local`, `Scope#with_fact`, and `Scope#with_self_type` MUST all preserve the other two fields.

### Instance-, class-, and global-variable bindings (Slice 7 phase 1)

`Rigor::Scope` carries three additional binding maps alongside `locals`: `ivars`, `cvars`, and `globals` (each `Hash[Symbol, Type]`, default empty and frozen). The accessors are:

- `Scope#ivar(name)`, `#cvar(name)`, `#global(name)` — return the bound type for `name`, or `nil` when no write has been recorded in the analyzed slice of the program.
- `Scope#with_ivar(name, type)`, `#with_cvar`, `#with_global` — return a fresh scope with the named binding added. They MUST preserve `locals`, `fact_store`, `self_type`, and `declared_types` exactly like `with_local` does.

The `StatementEvaluator` MUST handle `Prism::InstanceVariableWriteNode`, `Prism::ClassVariableWriteNode`, and `Prism::GlobalVariableWriteNode` symmetrically with `LocalVariableWriteNode`: evaluate the rvalue under the entry scope, return `[rvalue_type, post_rvalue_scope.with_<kind>(name, rvalue_type)]`. The compound-write forms (`@x ||= …`, `@x &&= …`, `@x += …`) are bound in the post-scope by the Slice 7 phase 3 handlers specified below. The `ExpressionTyper` MUST handle `Prism::InstanceVariableReadNode`, `Prism::ClassVariableReadNode`, and `Prism::GlobalVariableReadNode` by consulting the corresponding scope binding map and falling through to `Dynamic[top]` (without recording a fallback event) when no binding exists.

`Scope#join` MUST union ivar/cvar/global bindings the same way it unions locals (drop any name not bound in BOTH sides; the statement-level evaluator is responsible for nil-injection on half-bound names if the catalogue ever extends to a control-flow construct that needs it). `Scope#==` and `Scope#hash` MUST include the three binding maps.

Slice 7 phase 2 lifts the method-local boundary for ivars: `Scope` carries a `class_ivars: Hash[String, Hash[Symbol, Type]]` accumulator keyed by qualified class name. `ScopeIndexer` populates it once at index time through a separate pre-pass that walks every `Prism::ClassNode` / `Prism::ModuleNode`, descends into each nested instance `Prism::DefNode`, and types every `Prism::InstanceVariableWriteNode` rvalue under a scope that carries the appropriate `self_type` (instance defs only — singleton defs operate on a different `self`). Multiple writes to the same ivar within the class union via `Type::Combinator.union`. `StatementEvaluator#build_method_entry_scope` MUST seed an instance method body's `ivars` from `Scope#class_ivars_for(current_class_path)`; singleton-method bodies (`def self.foo` or any def lexically inside `class << self`) MUST NOT consult the accumulator because their `self` is the class object itself.

The pre-pass types rvalues with no local bindings, so `@x = 1` records `Constant[1]` but `@x = some_local + 1` records `Dynamic[top]`.

An `Prism::InstanceVariableTargetNode` of a `Prism::MultiWriteNode` (parallel assignment, including a nested or splat target) MUST also contribute to the class's union, with the slot type `MultiTargetBinder.bind_marked(node, rhs_type, scope:, soften_slots: false)` reports for it in `Result#ivars` — the rules locals use, not a second decomposition (issue [#1110](https://github.com/rigortype/rigor/issues/1110)). The accumulator records a type and nothing else, so the binder's ADR-101 marks are dropped. Of the binder's two nil-dropping readings, the seed keeps one and declines the other. An `Array[T]` fixed slot records `T`: that is what a single `@x = xs.first` write records, so a parallel assignment is no noisier than the single-write channel it mirrors. The ADR-57 softening MUST NOT apply: a present `X | nil` tuple slot records `X | nil`, and a union member's bare `nil` stays in the join (`@status, @value = ok ? [:ok, "v"] : [:err]` seeds `@value` as `"v" | nil`). That softening is honest for a local only because the binder marks the name, which keeps `if v` / `v.nil?` from folding; without the mark, a sibling's `if @value` or `raise unless @value` would fold on a `nil` that is reachable and fire `flow.always-truthy-condition`. A `T | nil` seed was rejected: the declaration-sourced mark (ADR-58 WD1 below) gates `call.possible-nil-receiver` and `argument-type-mismatch` on that `nil`, but not every consumer — a sibling `def major = @major` against a declared `-> Integer` fires `def.return-type-mismatch`, and `rigor sig-gen` proposes `Integer?` — so the widening fires on correct programs (ADR-5). A right-hand side the binder cannot decompose records `Dynamic[top]` per slot (unknown, not `nil`). The method that performs the destructure binds the slot flow-live and marked, as above, and so keeps `@first.nil?` from folding there; a sibling method reads the unmarked seed, as it does for `@x = xs.first`.

Slice 7 phase 6 lifts the same boundary for cvars and globals. `ScopeIndexer` runs the pre-pass twice more: once per class for `Prism::ClassVariableWriteNode` rvalues, populating a `class_cvars` accumulator of the same shape, and once program-wide for `Prism::GlobalVariableWriteNode` rvalues, populating `program_globals`. `StatementEvaluator#build_method_entry_scope` MUST seed a method body's `cvars` from `Scope#class_cvars_for(current_class_path)` on BOTH instance and singleton bodies — unlike ivars, Ruby class variables are visible from each — and the indexer MUST additionally materialise `program_globals` into the top-level scope's `globals` map, so reads at file scope and in CLI probes that never enter a method body observe the precise type without consulting the accumulator on every lookup.

#### Read-before-write nil gate and additional initializers (ADR-38)

A companion pre-pass walks each instance method body in AST (execution) order and tracks the ivar names whose **first** reference is a read (a read-before-write). Those names are unioned into a class-wide `read_before_write` accumulator, and at finalisation the class contributes `Constant[nil]` for each — soundness for the "method reads `@x` before any write to `@x`" shape, where Ruby yields `nil`. A **write** for this pre-pass is any of the direct forms (`Prism::InstanceVariableWriteNode`, `…OrWriteNode`, `…AndWriteNode`, `…OperatorWriteNode`) OR an `Prism::InstanceVariableTargetNode` appearing as a target of a `Prism::MultiWriteNode` / nested `Prism::MultiTargetNode` / splat (parallel assignment, `@m, @n = …`); the right-hand side of a `MultiWriteNode` is visited before its targets, so an ivar read on the RHS still counts as read-before-write.

`initialize` is the built-in exemption: for an `initialize` body, every ivar write target — including a parallel-assignment target per the write definition above — is folded into the class's `init_writes` set **instead** of contributing read-before-write evidence, so an ivar the constructor guarantees is assigned does not get the `nil` widening in sibling readers.

ADR-38 generalises that exemption to **plugin-declared additional initializers**. `Inference::ScopeIndexer` consults the aggregated `Plugin::Registry#additional_initializers` set at this single gate: for a `def` whose name is `covers_method?` by an entry **and** whose enclosing class equals or inherits from the entry's `receiver_constraint` (matched via `Environment#class_ordering`, the same mechanism ADR-16 Tier A uses), the method's ivar writes fold into `init_writes` exactly as `initialize`'s do. This is the Ruby analogue of PHPStan's `AdditionalConstructorsExtension` — `Minitest::Test#setup`, a Rails `after_initialize`, or a DI setter that establishes ivar state the framework calls before the body runs. The value-object shape is specified in [`plugin.md`](plugin.md#rigorpluginmanifest) (`additional_initializers:`).

The lookup reads the plugin registry off the pre-pass scope's `Environment`; the engine MUST treat the whole resolution as fail-soft (any error, or an absent / empty registry, degrades to "no match"). This is sound by construction: the gate can only ever **suppress** a `nil` contribution, never add one, so a missed or over-broad match is false-positive-safe — it merely leaves an existing nil widening in place rather than ever making the analyzer stricter (ADR-38 § "Why this is FP-safe").

Slice 7 phase 3 extends `StatementEvaluator` with **compound writes** for every variable kind. The handlers cover `Prism::{Local,InstanceVariable,ClassVariable,GlobalVariable}{Or,And,Operator}WriteNode` and apply uniform semantics:

- The current type is read from the appropriate scope binding map (`local`/`ivar`/`cvar`/`global`); unbound variables read as `Dynamic[top]`.
- The rvalue is evaluated under the entry scope through `sub_eval`.
- The result type for `||=` is `union(Narrowing.narrow_truthy(current), rhs)`; for `&&=` it is `union(Narrowing.narrow_falsey(current), rhs)`; for operator forms (`+=`, `-=`, `*=`, ...) the typer dispatches `current.send(operator, rhs)` through `MethodDispatcher` and falls back to `Dynamic[top]` on a miss.
- The variable is then rebound into the post-scope through the same `with_*` builder used by the plain write handler. The expression value is the result type, matching Ruby's semantics.

#### Declaration-sourced provenance mark (ADR-58)

[ADR-58](../adr/58-ivar-field-typing.md) splits ivar-sourced optionality in two. A `nil` is **flow-live** when it is assigned or observed on a path that reaches the read inside the method under analysis (a method-local `@x = nil`, a narrowing that put nil back into the binding); it is **declaration-sourced** when its only origin is the cross-method machinery specified above — the class-ivar accumulator's constructor `@x = nil` seed, or the `Constant[nil]` the read-before-write gate contributes for a non-definitely-assigned ivar. Declaration-sourced optionality is real type information and MUST remain in the type the engine reports (`Node | nil` stays `Node | nil`), but it MUST NOT by itself be diagnostic fuel: the working program's cross-method invariant is assumed under [ADR-5](../adr/5-robustness-principle.md), and the ADR's own survey measured the alternative as the single largest false-positive class on idiomatic data-structure Ruby. The mark specified here is the one bit that carries that judgment from the seed to the rules. It is normative because leaving it to the rules produced exactly the drift an unstated contract produces: before issue #324 two rules spelled the lookup independently and disagreed about ADR-58's own motivating shape, one excusing `r = @right; r.key` while another fired on `c = @count; sink.take_int(c)`.

**Carrier and discipline.** `Rigor::Scope` carries a frozen `Set[[Symbol, Symbol]]` of `(kind, name)` refs, threaded by value through every scope transition and read through `Scope#declaration_sourced?(kind, name)`. It is a side channel in the [ADR-75](../adr/75-dynamic-provenance.md) / [ADR-82](../adr/82-dynamic-provenance-wiring.md) sense, and the same discipline binds: it MUST NOT participate in subtyping, consistency, normalization or erasure, no `Rigor::Type` MUST carry or expose it, and **no diagnostic MUST fire *from* it** — a consumer may only ever *withhold* a firing it would otherwise make, so the mark can lose precision but can never manufacture a false positive. It differs from the `dynamic_origins` / `void_origins` advisory tables of § [The `Scope#type_of(node)` Contract](#the-scopetype_ofnode-contract) in two respects a reader MUST NOT generalise away: it is an ordinary immutable scope field rather than a node-keyed table written in place, and it IS included in `Scope#==` (though not in `Scope#hash`).

**Establishment.** There are exactly two establishing transitions, one per carrier kind, and an implementation MUST NOT add a third without treating it as the decision described under *Non-transitivity* below. Issue [#667](https://github.com/rigortype/rigor/issues/667) is the worked case of taking that decision the other way: it needed a mark with an opposite join policy and a different subject, so it took a second Set of its own rather than a third kind here — see § [The truthiness withholding](#the-truthiness-withholding) ▸ *Copy provenance*.

- `:ivar` — `StatementEvaluator#seed_instance_ivars` MUST stamp every ivar it seeds out of `Scope#class_ivars_for` through `Scope#seed_declaration_sourced_ivar`, which binds the type and records the mark in one transition. The mark records the **provenance of the binding, not the presence of a nil**: every seeded entry is marked whether or not its type has a nil constituent, and pairing the mark with a nil test is the consumer's job. Because singleton bodies take no ivar seed at all, a `def self.…` body carries no `:ivar` mark. `seed_declaration_sourced_ivar` MUST be used only at method-body entry — unlike `with_ivar` it does not invalidate the indexed / method-chain narrowings keyed on the name.
- `:local` — `StatementEvaluator#eval_local_write` MUST stamp the written local through `Scope#with_declaration_sourced_local` when, and only when, the write's `value` node is a bare `Prism::InstanceVariableReadNode` whose ivar is marked in the scope reached after evaluating the right-hand side. `with_declaration_sourced_local` MUST perform the ordinary `with_local` first and re-stamp afterward (`with_local_declaration_mark`); the reverse order silently loses the mark, because `with_local` drops it unconditionally.

**Drop.** Every flow-live touch drops the mark, and the drop is implemented in the scope transitions rather than at the rules, so a new caller inherits it automatically:

- `Scope#with_ivar` drops `(:ivar, name)`. Its callers are the method-local ivar write, every `Rigor::Inference::Narrowing` rewrite of an ivar binding (truthiness, nil-guard, `is_a?`, the receiver-chain rewrite), and the mutation-widening path. A narrowing therefore un-marks the ivar even when it leaves the type unchanged.
- `Scope#with_local` drops `(:local, name)` on **any** rebinding of the name.
- `Scope#join` **intersects** the `:ivar` and `:local` refs: a ref is marked after a merge only when both branches mark it. If either path made the binding flow-live, the merge is flow-live.

**Non-transitivity, and its exact boundary.** The mark propagates across at most **one** ivar-to-local hop, because `eval_local_write` recognises exactly one right-hand-side shape: a bare `Prism::InstanceVariableReadNode`. Nothing derives a mark from another mark. An implementation MUST NOT widen this by inference at a consumer; widening it is a decision to be taken at `eval_local_write` (or at a documented successor), gated on the ADR-58 WD4 zero-new-firing protocol, and not a slip to be repaired ad hoc — ADR-58's WD1 status records the same conclusion for the broader method-return-transit shape, which was measured, scoped as WD1b, and then demand-gated rather than approximated.

The following shapes carry the mark (verified by probe — `call.possible-nil-receiver` and `call.argument-type-mismatch` both stay silent):

- `r = @x; r.foo` — the direct copy, ADR-58's motivating rotation/traversal shape.
- `r = @x; r = @x; r.foo` — each write is judged on its own right-hand side, so a rebind from the same pure read re-establishes the mark that `with_local` just dropped.
- `r = s = @x; s.foo` — the inner write's value is the bare ivar read, so `s` is marked; `r`, whose value node is a write node, is not.
- `if c then r = @x else r = @x end; r.foo` — both branches stamp `(:local, :r)` and the join's intersection keeps it.

The following carry no mark and MUST keep firing:

- `c = @x; d = c; d.foo` — the second hop. The right-hand side is a local read, not an ivar read.
- `r = @x if c` and `if c then r = @x else r = nil end` — an asymmetric join, dropped by the intersection.
- `r ||= @x` in any position, and `r = begin; @x; end` or `r = (@x)` — a compound-write node, a `Prism::BeginNode` and a `Prism::ParenthesesNode` are all "not a bare ivar read".
- `@x = nil if c; r = @x; r.foo` and `if @x then … end; r = @x; r.foo` — a preceding flow-live write or narrowing un-marked the ivar, so the copy inherits nothing.

**Consumers.** Every consumer MUST ask the question through `Rigor::Analysis::CheckRules::DeclarationSourcedGuard.marked?(node, scope)` — the single predicate that maps a Prism node to the right carrier kind (`InstanceVariableReadNode` → `:ivar`, `LocalVariableReadNode` → `:local`, everything else → false) — and MUST NOT re-derive it from `Scope#declaration_sourced?` or from a node-shape test of its own. That indirection is the fix for issue #324 and the reason this section exists. Today's consumers are four gates across two rules:

| Rule | Gate | Criterion |
| --- | --- | --- |
| `call.possible-nil-receiver` | `nil_receiver_diagnostic` | Declines on a marked receiver. The rule restricts itself to a `Prism::LocalVariableReadNode` receiver beforehand, so only the `:local` kind is reachable here. |
| `call.argument-type-mismatch` | `single_argument_mismatch` (nil channel) | Declines on a marked argument whose type is exactly nil, before the parameter is consulted. |
| `call.argument-type-mismatch` | `nil_arg_overload_mismatch` (multi-overload nil channel) | The same criterion on the per-overload path. |
| `call.argument-type-mismatch` | `declaration_sourced_nil_only_mismatch?`, via `argument_genuinely_mismatches?` | Declines only when the argument is marked **and** the rejection is caused solely by the nil constituent — the type with nil removed must be accepted in gradual mode. The argument's type is unchanged; only the firing decision is gated. |

**The `Set` is shared with a second, differently-behaved mark.** [ADR-67](../adr/67-parameter-type-inference.md) WD6b stores its inferred-parameter taint in the same `Scope` set under a third kind, `:inferred_param`, and its semantics are the opposite of ADR-58's on both axes: `Scope#join` merges it by **union** (either branch's taint survives, because firing against an open-call-site lower bound is a false positive on the path that carries it), and it is **sticky** across `with_local`, cleared only by `Scope#without_inferred_param_mark` at a genuine rewrite. A reader or maintainer of `join_declaration_sourced` MUST keep the two policies separate, and `declaration_sourced?(:inferred_param, …)` MUST NOT be used as a spelling of the ADR-67 query — `Scope#inferred_param?` is that query.

### Lexical constant lookup (Slice A constant-walk)

`ExpressionTyper#type_of_constant_read` and `#type_of_constant_path` MUST resolve a constant by walking the surrounding lexical class context, mirroring Ruby's runtime constant lookup rules at the granularity the analyzer can prove statically:

0. A reference written with a **leading `::`** (`::Foo`, `::Foo::Bar` — Prism spells the root as a `ConstantPathNode` with a nil `parent` at the LEFTMOST segment, which `Source::ConstantPath.rooted?` answers) names the top level unconditionally. Steps 1 to 3 MUST be skipped for it and only step 4's bare candidate consulted. When no top-level constant answers, the result MUST be the same as for an unknown constant (nil, and the `fallback_for` of step 6) — a lexically nearer constant of that name MUST NOT answer a rooted reference. The name handed to the resolver stays **un-rooted**: every discovered-constant table (`discovered_classes`, `in_source_constants`, the [#528](https://github.com/rigortype/rigor/issues/528) synthesized namespace prefixes, the declaration keys) is keyed without the leading `::`, so the marker MUST travel beside the name (`Reflection.resolve_constant_type`'s `rooted:` argument) rather than inside it. The same marker governs the class-membership narrowing of `is_a?` / `kind_of?` / `instance_of?`, `case`/`when`, and `Class === x`, whose class reference `Inference::Narrowing` renders through its own de-rooting walk (`static_class_name`) and then resolves lexically: a rooted reference MUST answer the top-level class, and — for `is_a?` / `kind_of?` / `instance_of?` — MUST make the rule DECLINE (both edges keep the pre-state) when no top-level class owns the name, otherwise a guard and the value it guards disagree about the same spelling, `::Foo.new` typing as `Foo` while `if x.is_a?(::Foo)` narrows to `MyApp::Foo`. `case`/`when` and `===` share the walk and the rooted opt-out but not that extra decline: an unresolved rooted name there keeps the spelling as written, which is what those shapes did before the walk reached them at all, so extending the resolution to them cannot retract a narrowing they already performed. Reaching them is itself a false-positive fix, not only a precision one — resolving nothing meant `case message when Monitor` inside `Concurrent::ErlangActor` narrowed to the stdlib `::Monitor` and reported `call.undefined-method` on the two reads that follow it, on correct code. `Narrowing.class_pattern_certainty` answers the *dead-arm* question rather than the narrowing one, and matches at the environment level on the AS-WRITTEN spelling without walking the nesting — a divergence that is not merely a loss of certainty. An unresolvable pattern name does order as `:unknown` and yield `:maybe`, but a SHADOWED name that is RBS-known at top level is perfectly resolvable, and there the value side drops a LIVE arm: `case other when Random` inside `Bar::Nested`, over a subject built from `::Random`, folds the expression to the first arm's value where Ruby takes the `else`. That is pre-existing and answers identically before and after this section's walk reached `case`/`when`; what the walk adds is a visible disagreement, the flow side now reporting the arm unreachable while the value side still folds to it. Both halves MUST eventually resolve the pattern name the same way ([#655](https://github.com/rigortype/rigor/issues/655)). Omitting the marker did not merely lose a resolution: `::Rails` inside `module MyApp` that also defines `MyApp::Rails` typed as the nested shadow — Ruby's escape hatch out of the lexical ladder answering with the very constant it escapes ([#614](https://github.com/rigortype/rigor/issues/614)).
1. `<entry>::<name>` MUST be tried for each entry of the body's **`Module.nesting`**, innermost first. The chain MUST come from `Reflection.lexical_nesting_chain`, the single owner of the question, which both this ladder and the class-membership walk below read; neither may re-derive it.
2. That chain MUST be the one **recorded as the walk entered each declaration**, carried on `Scope#lexical_nesting`. Ruby pushes exactly ONE entry per declaration keyword, qualified against the entry already on top, so a compact `class Admin::UsersController` contributes `["Admin::UsersController"]` while the nested `module Admin; class UsersController` contributes `["Admin::UsersController", "Admin"]`. The chain MUST NOT be reconstructed from `Scope#self_type`: the two spellings render the identical `class_name`, so peeling it one `::segment` at a time answers the nested chain for both, and a bare `User` in the compact form then reaches `Admin::User` where Ruby names `::User` — a wrong type on correct code, and a `call.undefined-method` at the next call ([#652](https://github.com/rigortype/rigor/issues/652)). A ROOTED header re-anchors at the top level and MUST be read through `Source::ConstantPath.rooted?`, not off the rendered name, which drops the marker by contract: `class ::Rooted::Bar` written in `module Outer` NAMES `Rooted::Bar` — so every table keyed by a declaration's qualified name, and the analyzer's own class-frame stack, MUST reset the enclosing prefix — while its `Module.nesting` is `[Rooted::Bar, Outer]`, so the pushed ENTRY is un-prefixed and the enclosing entries stay beneath it as live rungs. The single-segment case is the load-bearing one: `class ::Foo` inside `module MyApp` filed as `MyApp::Foo` is not merely mis-keyed but undiscoverable under the name every caller writes, so the receiver types opaque and the call reports NOTHING ([#708](https://github.com/rigortype/rigor/issues/708), [#638](https://github.com/rigortype/rigor/issues/638)). Only a `class` / `module` keyword pushes an entry: a `def` body, a block body (including the `class_eval`-semantics `Class.new do … end`, which pushes no cref in Ruby) and a `class << expr` body each INHERIT the enclosing chain, even where the analyzer's own class-frame stack diverges — `Inference::StatementEvaluator` resets that stack for `class << SomeOtherConstant` so a nested `def` registers against the target, and the chain MUST NOT follow it, because Ruby's nesting there is `[#<Class:Other>, …enclosing]` and reads the enclosing namespace's constants. The recorded chain is THREE-valued, and the two empty readings MUST stay distinguishable. Where NO chain was recorded the reader MUST fall back to peeling `<class_path>` (the `class_name` of `Scope#self_type` when it is a `Type::Nominal` or `Type::Singleton`) and MUST NOT synthesise an empty chain for it: the peel keeps a resolution the engine already makes, whereas an empty chain would retract it and degrade correct code to `Dynamic`. A scope built from a **self type alone** is exactly that case. Where the chain was RECORDED EMPTY the body is written at the TOP LEVEL, and that is Ruby's answer rather than the absence of one — `Module.nesting` in a top-level `def` body IS `[]`, so `def helper = Post.new` names `::Post` no matter which namespace calls `helper`. Such a scope MUST resolve `<name>` at the top level FIRST, and both caller-derived rungs — step 1's peel and step 3's ancestors — MUST be suppressed ahead of it, because Ruby's cref there is `Object` and each of them reaches for the CALLER's namespace instead. Answering step 1 alone is insufficient and leaves a second wrong answer live: a top-level helper read from inside `class Child < Base` where `Base` includes a module owning the name resolved through step 3's ancestor rung, which the empty chain does not touch. When the top level does not answer, the two caller-derived rungs MUST then be tried in their original order, BELOW the top level. That surviving fallback is unsound against Ruby — those are the reads where the name exists only under a namespace and Ruby raises `NameError` — and it is kept deliberately: it resolves 486 reads on gitlab and 33 on dependabot-core that would otherwise go opaque, Rigor reports nothing about them either way, and making them fire is a separate question with its own false-positive budget ([#716](https://github.com/rigortype/rigor/issues/716), `docs/notes/20260905-toplevel-def-cref-movable-sites.md`). The candidate SET is therefore unchanged for such a scope and only its ORDER moves, which is what makes the change non-regressive: no read that resolved before stops resolving. The four `Inference::ScopeIndexer` census scopes that type an rvalue during the discovery pre-pass — `record_constant_write`, `collect_def_ivar_writes`, `collect_block_ivar_writes` and `collect_def_cvar_writes` — MUST NOT reach that fallback: each census walk already threads the scope its rvalue is typed under, so the chain travels ON that scope — pushed by `Source::ConstantPath.pushed_nesting`, the same function the declaration walks push with — and MUST yield the same chain the declaration walk records. It MUST NOT be re-derived from the enclosing qualified prefix: a ROOTED header resets that prefix without resetting Ruby's nesting, so for a body inside `class ::Rooted` written in `module Outer` the prefix is `["Rooted"]` and `Outer` is absent from it entirely, while Ruby keeps `Outer` on the ladder as a live rung. The prefix-derived reading survives only as the fallback for a caller that threads no chain, where it is the pre-[#708](https://github.com/rigortype/rigor/issues/708) answer and never a new firing. The [#540](https://github.com/rigortype/rigor/issues/540) mutation census reads the same chain for the same reason: candidates built from a reset prefix never name `Outer::TABLE`, so a bare `TABLE[:k] = 1` there left the closed shape unwidened and `.empty?` folded to `true` on a table the program fills. A `Prism::ConstantPathWriteNode` (`Foo::BAR = …`) MUST receive the enclosing declaration prefix and the qualified name it writes as SEPARATE values. One argument carried both roles, so the path form had to pass it EMPTY to keep the caller-supplied name intact, and that lost the chain and the key's qualification together — neither of them gradually. Beyond the stamp, the entry MUST be keyed under the namespace Ruby resolves the path's own leading segments to: the first `<nesting entry>::<namespace>` naming a class or module some source declares, innermost first, and the as-written spelling when none does or when the reference is rooted (step 0 owns that answer). A target that renders no static path MUST NOT be keyed by a lenient render of its constant segments: `self::BAR = …` MUST take the key a bare `BAR = …` in the same body takes, and any other dynamic base (`klass::BAR = …`) MUST be DECLINED BY THIS CENSUS rather than recorded. `self` is not always the enclosing declaration, so that first key MUST be carried by the walk rather than read off the prefix: a `class_eval` / `module_eval` / `class_exec` / `module_exec` block runs with the RECEIVER as `self` while leaving `Module.nesting` alone, so `Other.class_eval { self::BAR = … }` inside `module Admin` MUST key `Other::BAR` while the rvalue still resolves through `Admin`, and a bare `BAR = …` in that same block still keys `Admin::BAR` — the cref did not move. The RVALUE's SELF TYPE MUST follow the rebound `self` in the same step, or fixing the key merely makes a wrong type REACHABLE: `self::REF = self` typed under the enclosing prefix answers `singleton(Admin)` and `self::V = build` dispatches `Admin.build`, both wrong on correct code and both invisible on master only because the key put them where no read arrived. The two halves therefore come from different sources at the same site — the chain from the lexical prefix, the self type from the rebound owner — and the bare `BAR = self` in that block needs the second half just as much. `Object` is the one owner whose constants the census MUST still spell BARE: they are the top-level ones, and keying `Object::T` files the write beside a sibling's `T = 2` rather than on top of it, so the conflict between them goes undetected and one of the two publishes. Where the rebound `self` reaches no class or module name the write MUST be DECLINED like any other dynamic base: a `class_eval` receiver that is not a static constant path, an `instance_eval` / `instance_exec` / `define_method` body (whose `self` is the receiver OBJECT — a module only when the receiver happens to be one, which a syntactic walk cannot tell), and a `Class.new` / `Module.new` / `Struct.new` / `Data.define` block, whose class only an enclosing constant write names ([#705](https://github.com/rigortype/rigor/issues/705)). An ORDINARY block rebinds nothing and MUST keep charging the enclosure. Recording it under the bare trailing name files a value under a name the write never touched, and since the rvalue is typed under the enclosing nesting that bare key — which outranks an RBS constant declaration in step 5 — makes a wrong receiver reachable at every reader of the top-level name. **That decline is the whole of the mechanism, and its OVER-EAGER direction is witnessed from INSIDE the writing declaration.** No other pass files a per-file type for a constant write — `Inference::StatementEvaluator`'s constant-write handler types the rvalue and binds nothing — so a fixture pins this key or nothing does. A top-level read cannot pin it: the guessed `Dyn::LATE` never sits on that reader's ladder. A read of `LATE` from inside `module Dyn` does, on step 1's INNERMOST rung, ahead of the RBS top-level `LATE` the outside reader reaches — so qualifying the key answers `singleton(Dyn::Post)` there and fires `call.undefined-method` on a correct call while every top-level arm stays green ([#705](https://github.com/rigortype/rigor/issues/705)). Step 3's ancestor rung is deliberately NOT walked for the key, so an unrecognised namespace keeps the name it had rather than moving to a guess. The [#540](https://github.com/rigortype/rigor/issues/540) mutation census MUST follow that key: it MUST record the same lexical candidates for a PATH receiver that it already records for a bare one, because a mutated constant the widener matches under no key keeps the closed empty `HashShape` / `Tuple` that census exists to retract, and `Table::ROWS.empty?` then folds to `true` on a table the module fills. It MUST follow the ROOTED carve-out with it: `::Table::ROWS[k] = 1` written in `module Admin` names the top-level constant unconditionally, so it MUST contribute the rooted candidate ALONE and leave `Admin::Table::ROWS` — a different constant the write cannot reach — with its fold. The exemption MUST be read through `Source::ConstantPath.rooted?` and not off the rendered name, which drops the marker by contract, so the two spellings are indistinguishable by name ([#703](https://github.com/rigortype/rigor/issues/703)). **The [#644](https://github.com/rigortype/rigor/issues/644) publication census is carved out of that and still renders a path write AS WRITTEN** — `ScopeIndexer#constant_path_write_name`, feeding the cross-file value publication and, through the census's declared half, `Scope#local_constant_names` — while sharing the `self::` rule above, because charging the lexical enclosure for a `class_eval` block's write gets both halves wrong at once: the name the write DID touch keeps publishing a value a second writer replaced, and the name it did NOT stops publishing one nothing conflicts with — so the two censuses key the same statement differently. For a STATICALLY NAMEABLE path the divergence costs a cross-file resolution rather than producing a wrong one: only a frozen scalar publishes and both censuses read the same rvalue, so the value published is right and only its name is less qualified than a reader's spelling. For a DYNAMIC base it is not that benign, and the site's own "over-suppressing is the safe direction" reading does not hold, because it is not suppressing at all: `[Foo].each { |k| k::X = 1 }` writes `Foo::X`, renders as the bare `X`, and PUBLISHES `Constant[1]` under a name the write cannot have created. `X == 2` then folds to `false` project-wide, and in the WRITING file — where `local_constant_names` marks `X` locally declared, so #644's own withholding guard does not exempt it — `flow.always-truthy-condition` FIRES on correct code. That is a false positive, not merely a precision defect; a reader in a sibling file sees only the wrong value, because there the guard withholds ([#705](https://github.com/rigortype/rigor/issues/705)). A write whose base is not statically nameable MUST therefore contribute NO literal to this census. It MUST still be RECORDED under the bare last segment, as unpublishable, and this is where the two censuses' rules genuinely diverge rather than merely lag: a DECLINE means opposite things on the two sides. Recording no type is gradual; recording no WRITE would leave another file's value for the name trusted, and the one class for which the bare render is not a guess at all is `Object`. The same answer covers a `self::BAR` whose `self` was rebound to something unnameable — "some class, then `::BAR`" is the same uncertainty either way — with ONE exception: where an enclosing `Klass = Class.new { … }` names that class, the write is `Klass::BAR` and this census MUST key it there, because the retraction the bare fallback buys is otherwise spent on the top-level `BAR` a SIBLING file declares, and a `Klass = Class.new { self::X = 7 }` in one file made a plain `X = 5` in another read `Dynamic[top]` ([#710](https://github.com/rigortype/rigor/issues/710)). The name MUST come from the walk's own `meta_new_block_body` recognition, threaded one hop from the constant write down to its rvalue's block. A constant PATH write MUST keep the opaque answer even though that recognition takes it: THIS census renders a path write AS WRITTEN rather than through the nesting, so naming the block's class here would publish a `self::X = …` inside it under a name Ruby does not give it, where declining merely suppresses the name. Moving it belongs with moving this census's own path key ([#703](https://github.com/rigortype/rigor/issues/703)). A name recorded through the bare FALLBACK MUST NOT reach `local_constant_names`. That set answers a different question from the census it is read off — "did this file DECLARE the name?", where the census asks "could another file's value for it be wrong?" — and `[Foo].each { |k| k::X = 1 }` answers no, having created `Foo::X`; granting the exemption un-withheld `flow.always-truthy-condition` for a name the file never wrote. The two MUST therefore be separate tables and not one richer descriptor: a file that writes the name BOTH ways still declares it, whichever write the census records last. Because the key now depends on ANOTHER file's class declarations, the probe that resolves the namespace MUST record its own ADR-46 edges when the recorder is active — a positive edge on the file declaring the namespace it resolved through, and a negative `class:<last segment>` edge on every candidate that missed. No edge the reader records covers this: a reference's negative key names the constant that failed to resolve, whereas the write's key moves because a MIDDLE segment appeared. Keying it as written filed the entry where no read of the resolved name reaches it, and the two losses compounded: `Holder::DEFAULT = Post` written inside `module Admin` answered `Dynamic[top]` for a read spelled `Admin::Holder::DEFAULT`, while the in-namespace spelling fell past step 1 to step 4, reached the mis-keyed entry, and typed as the top-level `Post` — `call.undefined-method` on a correct call to an `Admin::Post` method ([#690](https://github.com/rigortype/rigor/issues/690)). Until the four were stamped, a compact declaration's constant reference was resolved correctly by the walk that reads it and still peeled wherever the value was reached through a pre-pass table, and the two disagreed about the same expression: `DEFAULT = Post` written in a compact `class Admin::Census` is a constant read AT ITS OWN DECLARATION SITE, so it recorded `singleton(Admin::Post)` and every later read of `DEFAULT` answered a class the code never names, while the same `Post` read in a method body of that class typed as `Post`. `@post = Post.new` in an `initialize` is the same defect through the ivar table ([#681](https://github.com/rigortype/rigor/issues/681)). `Inference::ExpressionTyper#build_user_method_body_scope` rebuilds a callee's body scope from the receiver's type when inferring that callee's RETURN type, and it holds no prefix to stamp, so the chain MUST be RECORDED in the def-node index instead: `Scope::DiscoveryIndex#discovered_def_nestings` maps each declared `Prism::DefNode` to the chain in force where it is written, and the re-walk MUST stamp what it finds there. The record MUST be keyed by the def NODE and not by `(class, method)`: an inherited body is re-walked with the SUBCLASS as receiver, and its constants resolve under the declaration that OWNS it — `make` declared in a compact `class Admin::CompactBase` names `::Post` when called on a `module Admin; class Child < CompactBase`, which no receiver-keyed answer can give. Only a `class` / `module` keyword contributes an entry there too, so a `def` inside a singleton-class body, a `Class.new` block or any other block records the chain of the declaration ENCLOSING it. A top-level `def` MUST record the EMPTY chain rather than nothing, and the table MUST keep "present with `[]`" distinct from "absent": it is keyed by node identity and populated by the declaration walk alone, so `[]` means "walked, and top level" while an absent entry means no walk built the scope and the peel above still owns it. Recording nothing left the re-walk peeling the CALLER's qualified name, so a top-level `def helper = Post.new` answered `Admin::Post` when read from inside `module Admin` ([#716](https://github.com/rigortype/rigor/issues/716)). A body reached through an ADR-85 seed bundle — an unchanged file on the incremental path, whose table entry is an `Inference::DefHandle` rather than the node the re-walk is handed — MUST record, within the resolver's per-run memo scope, the SAME chain a cold run records for it, and the record MUST travel ON the handle: the index is keyed by node identity and `Inference::DefNodeResolver` mints the node from its own parse, so no entry the discovery walk keyed can reach it, and the bundle serialises the table's VALUES rather than its keys. The resolver MUST re-attach the handle's chain to the node it mints, and the re-walk MUST read the two through ONE reader — the index first, the rehydration second. That order MUST rest on OBJECT PROVENANCE: the resolver MUST parse separately from every walk the analyzer runs and both tables MUST be keyed by object identity, so no node is a key in both; and the bundle MUST be gated on the file's CONTENT digest, so where the two answer for one def through different objects they answer the same chain. **The file-level reading of that argument is false**: an unchanged file re-analysed as a DEPENDENT is served from its bundle by the cross-file fold and walked live for its own per-file index in the SAME run, contributing to both tables at once, so a change here MUST preserve the separate parse rather than any one-branch-per-file property. The rehydration is populated only within the resolver's per-run memo scope; where that scope is absent the recorded chain is unavailable and the reader MUST fall back to the peel exactly as it does for an unrecorded def — so this requirement binds the analysis paths that enter it, and every entry point that CONSUMES a handle MUST do so inside one. A chain recorded on the handle MUST NOT be treated as optional for the SCHEMA: a row lacking it destructures as nil, which is a reading the analyzer assigns its own meaning, so an older bundle MUST be REJECTED by the schema gate rather than read as one whose defs record no chain ([#707](https://github.com/rigortype/rigor/issues/707)). The handle MUST likewise carry a RECORDED EMPTY chain as `[]` and the rehydration MUST file it, or a bundle-served top-level `def` peels the caller's namespace on a warm run where a cold run resolves at the top level; because that changes what an existing row MEANS without changing its shape, the schema gate MUST reject a bundle written before it ([#716](https://github.com/rigortype/rigor/issues/716)). Until it was carried, an `--incremental` recheck and a full run answered the same expression differently for a callee in a file the recheck did not re-read — the warm arm keeping the pre-[#681](https://github.com/rigortype/rigor/issues/681) peel, so `Post.new` in a compact `class Admin::CompactMaker` typed as `Admin::Post` and `call.undefined-method` fired on a correct call — and `--verify-incremental`, whose whole job is comparing the two, reported an incremental-only diagnostic on a project with compact declarations.
3. The **ancestors of the innermost cresting scope** MUST then be tried, before the bare name: for each project class or module in `<class_path>`'s ancestor chain, the candidate `<ancestor>::<name>`. The order MUST be breadth-first with included / prepended modules ahead of the superclass at each level, mirroring Ruby's ancestor order; `<class_path>` itself is excluded because step 1 already covered it. The walk MUST terminate on a cyclic `discovered_superclasses` / `discovered_includes` graph. Only project ancestors participate: `Scope#superclass_of` / `#includes_of` carry as-written names, each MUST be resolved against the `Module.nesting` the SUBCLASS'S DECLARATION HEADER is written in — innermost first, then the bare name — and a name that resolves to no discovered project class or module MUST be dropped — so an RBS-known ancestor contributes no candidate and a constant it owns is reachable only if the bare name reaches it at step 4. Omitting this step does not merely lose a resolution: when the same name also exists at top level, step 4 answers a lookup Ruby gives to the ancestor, so `KEY` inside `class Sub < Base` types as the top-level constant rather than `Base::KEY` — a wrong type on correct code ([#354](https://github.com/rigortype/rigor/issues/354)).
4. The bare `<name>` MUST be tried last, preserving the pre-walk top-level behaviour.
5. For each candidate, the typer MUST first consult `Environment#singleton_for_name(candidate)` (resolves a class object → `Type::Singleton[candidate]`), then `Environment#constant_for_name(candidate)` (resolves a non-class RBS constant declaration to its translated `Rigor::Type`). The first hit wins; the walk continues only when both miss for that candidate.
6. If no candidate resolves through either query, the engine MUST fall through to `fallback_for(node, family: :prism)` exactly as before.

### Cross-file value constants ([#644](https://github.com/rigortype/rigor/issues/644))

The `in_source_constants` table step 5's `constant_type_at` consults is the **merge of two producers**: the analysed file's own constant walk, and a project-wide table the cross-file discovery pre-pass publishes. The per-file half MUST win on collision — the declaring file is the most specific authority for its own name.

The project-wide half is normative as follows.

#### The publication census

- The pre-pass MUST census, per file, **every** constant assignment under its qualified name, recording for each a **descriptor**: the folded literal, or *unpublishable*. Every assigning form counts, not only the plain `ConstantWriteNode` / `ConstantPathWriteNode` that can carry a value — the operator / `&&=` / `||=` writes, a constant target under a multiple assignment, the inner write of a chain (`C = D = :x`), and a `self::X =` whose target renders no qualified name, each censused unpublishable. A form the census cannot see does not lose precision: it **bypasses the conflict rule below** and publishes a value the program does not have.
- A write whose target names no namespace — `k::LIMIT = 7`, or a `self::LIMIT =` inside a block whose `self` is opaque — MUST be censused under a **wildcard key for its last segment**, which MUST retract every censused name carrying that segment, the bare one included ([#668](https://github.com/rigortype/rigor/issues/668)). Such a write creates `<some namespace>::LIMIT` and can never create the top-level `LIMIT`, so filing it under the bare last segment suppressed the one name the form cannot write while leaving published every name it can — this census's own stale-value failure, reached through the fallback meant to be its safe direction. The wildcard is an over-approximation in the withholding direction: the analyzer cannot know which namespace the receiver denotes, so it MUST assume every one. The retraction MUST stay scoped to that last segment rather than widening to the table, the key's own last segment MUST be the segment itself (so the `constant:` edge and the producer diff below key on it unchanged), and the key MUST NOT be spellable as a Ruby constant name, so it can never collide with one. It contributes nothing to the local-declaration exemption of § [The truthiness withholding](#the-truthiness-withholding): that asks whether the reading file DECLARED the name, and a file did not declare what it could not name.
- A name MUST publish **only** when exactly one file censuses it, that file's descriptor is a literal, and the literal is a **frozen scalar** — a Symbol, Integer, Float, `true`, or `false`. It publishes the value: `Type::Constant[v]`.
- Every other case MUST publish nothing, leaving the reader at `Dynamic[top]`:
  - **Reassignment.** Two files assigning the same qualified name, or one file assigning it twice: the surviving value is decided by load order, so the name stays gradual.
  - **A mutable literal.** `String`, `Array`, `Hash`. The value a table pinned can be moved by a mutation in a file the declaring file's `widen_mutated_constants` census cannot see, and the composite two additionally arrive as a closed `HashShape` / `Tuple` at readers whose author never opened the declaration.
  - **`nil`.** At declaration position it is a placeholder for a value assigned later far more often than it is a genuine `NilClass`.
  - **Any non-literal rvalue.** A method call, a constant alias, a `Data.define`. The pre-pass types nothing, so an unfoldable rvalue is not a guess to be made — it is a decline.
- The `pre_eval:` publication ([ADR-17](../adr/17-monkey-patch-pre-evaluation.md)) is the other cross-file constant producer: it describes the same assignments through a **typed** walk and erases each value to its class. Where both answer, the literal table MUST win — a listed file's `INT_LIT = 42` publishes `42`, not `Integer`. This supersedes `pre_eval:`'s "publish the widened type, never the value-pinned one" rule for the assignments the literal table covers, and only for those.

  Why a literal assignment may pin where a pre-evaluated one may not: `pre_eval:` publishes what an rvalue *types to* after its walk evaluates it, so widening is what keeps it honest about a basis it cannot fully see; the literal table publishes only a **syntactic frozen scalar, written once, in one file**, which is a strictly narrower and more certain basis. `PreEvalConstants`' own rationale names exactly that case — "value-pinning a *provably* frozen single-write literal cross-file is a strictly later question; it needs its own FP measurement" — as deferred rather than forbidden. Further, the hazards the widening was written against are the composite and mutable literals (a closed `HashShape` making `CONFIG.fetch(:b)` fire, a `Tuple` displacing the RBS overload a call site relied on), every one of which the literal table declines, so widening its output would spend no false-positive budget and buy nothing.

  The converse precedence MUST NOT be adopted: standing the literal table down for a listed file would make `INT_LIT` read `Integer` in a project that lists it and `42` in one that does not, so an opt-in whose purpose is to add cross-file knowledge would remove some.

  A `pre_eval:` publication MUST be retracted when the write census attributes its name to any file that is not itself a listed `pre_eval:` file ([#663](https://github.com/rigortype/rigor/issues/663)). Answering from the listed file while an unlisted one assigns the same name a different value is a confident WRONG type rather than lost precision — at runtime the winner is load order — and the opt-in loses nothing to the rule: a name only listed files write is untouched, and where the literal table also publishes it already wins. The conflict MUST be read off the write census rather than off the publishable table, so an unlisted `X += 1` or `A, X = 1, 2` retracts as readily as a plain reassignment, and it MUST be asked as "is any writer outside the listed set" rather than as "is there more than one writer": the second question retracts an agreeing pair of LISTED files, whose widen-then-compare rule above deliberately keeps publishing, and misses an unlisted writer entirely where the listed file is kept out of `paths:` ([ADR-17](../adr/17-monkey-patch-pre-evaluation.md) WD5 permits that, and such a file contributes no censused name of its own). Among listed files the widen-then-compare rule is unchanged.

#### The truthiness withholding

A published value is real, and dispatch, argument typing and `call.undefined-method` MUST use it. A rule MUST NOT *conclude* from it: `if MODE == :production` in a file that does not declare `MODE` folds to a constant only because the project seeded one, and `flow.always-truthy-condition` there fires on correct code — on the idiom whose whole point is a project-wide constant that gets branched on. A configuration constant read in ten files would put the warning in all ten.

- `Scope#published_constant?(reference)` MUST answer true only when the project published the reference's last segment and the **analysed file does not itself assign it**. A constant the reader's own file declares is one its author can see, and every rule MUST keep firing on it. The two halves match at different granularities, and the asymmetry is normative: the published half matches the **last segment** and so over-answers, which only ever withholds; the local half is an exemption, so over-answering there would *un*-withhold. The exemption MUST therefore match a **suffix relation on qualified names** — a local assignment exempts a reference when it equals it or ends with `::` plus it — which is what a lexically relative spelling resolves to (inside `module AppConfig`, `Nested::X` is the file's own `AppConfig::Nested::X`) and which subsumes the bare case without matching an unrelated `Local::MODE` against a read of `AppConfig::MODE`.
- The file's own assignments MUST be read from the same publication census the cross-file table is built from, never from the typed per-file constant table: that table cannot see a multi-assign / `self::` / operator-write target, so an exemption derived from it would be a second source of truth blind to exactly the forms the census exists to catch.
- Every consumer MUST ask through `Rigor::Analysis::CheckRules::PublishedConstantGuard.rooted?(node, scope)` and MUST NOT re-derive the question, the same single-predicate rule ADR-58's `DeclarationSourcedGuard` carries and for the same reason. The guard walks a predicate's receiver, arguments, `&&` / `||` / parentheses / `rescue` composition, and **one** interprocedural hop into a project predicate method whose body reads such a constant. The callee's owner MUST come from the receiver's inferred **type**, never from the name it was spelled with: `Inner.production?` inside `module Outer` is `Outer::Inner`, so keying the table on the bare `Inner` both misses it (a new warning on ordinary code) and, where a top-level `Inner` also exists, reads the wrong module's methods — the defect family [#635](https://github.com/rigortype/rigor/issues/635) fixed in `Narrowing`. Going through the type covers every spelling that names the same owner (`production?`, `self.prod?`, `AppConfig.production?`, a relative `Inner.production?`) and a call-chain receiver (`KlassConfig.new.production?`, a `Nominal` whose instance table answers). The hop is deliberately coarse and bounded; ADR-58's *Non-transitivity* passage is the precedent for stopping there rather than threading provenance through the return memo. The guard also READS the copy provenance specified below, for a bare local or instance-variable predicate root; it MUST NOT derive that mark, only consult it. A value reaching the predicate through **two hops** stays out of scope by the same passage.
- The consumer set is exactly `flow.always-truthy-condition` today, and the guard MUST run only once the predicate has folded to a `Type::Constant` — it is the one gate that can resolve a def and walk its body, and a predicate that does not fold was never going to fire. The [ADR-75](../adr/75-dynamic-provenance.md) / ADR-82 side-channel discipline binds it as it binds the ADR-58 mark: no `Rigor::Type` carries it, it takes no part in subtyping, consistency, normalization or erasure, and a consumer may only ever **withhold** a firing — never make one.

##### Copy provenance ([#667](https://github.com/rigortype/rigor/issues/667))

A reference's spelling is the whole basis of the two name sets above, and a **copy has no spelling**: `m = AppConfig::MODE; m == :production`, `@mode = AppConfig::MODE` in a constructor read from a sibling method, and a same-file alias `MODE2 = AppConfig::MODE` all fold for a reason the reading file's author cannot see, and all three warned. The provenance is therefore stamped where the copy happens and travels with the value, which is ADR-58's `r = @x` shape applied to a different question.

**Carrier.** `Rigor::Scope` carries a SECOND frozen `Set[[Symbol, Symbol]]` of `(kind, name)` refs, `published_constant_sourced`, read through `Scope#published_constant_sourced?(kind, name)` and stamped through `Scope#with_published_constant_mark(kind, name)`. It MUST NOT be folded into the ADR-58 `declaration_sourced` set. That set's *Establishment* clause reserves a third kind as the decision its *Non-transitivity* passage describes, and this mark would not merely be a third kind: it joins by **union** where ADR-58's two kinds intersect, and it answers what a value's *constancy* rests on rather than what a binding's *optionality* rests on, for a different consumer. Sharing one Set across three kinds and two join policies would make every later edit to either mark a decision about both. The ADR-75 / ADR-82 side-channel discipline binds it exactly as it binds the ADR-58 mark, including "a consumer may only ever **withhold** a firing".

**Establishment.** Three transitions, all of them a copy:

- `StatementEvaluator#eval_local_write` and `#eval_ivar_write` MUST stamp the written name when the write's value type is a `Type::Constant` AND `PublishedConstantGuard.rooted?` holds for the rvalue under the post-rhs scope. The `Type::Constant` pre-gate is normative, not an optimisation: the mark exists to withhold a rule that fires only on a folded predicate, and it keeps the guard's interprocedural hop off every `x = foo(y)` in a project that publishes anything.
- `StatementEvaluator#seed_instance_ivars` MUST stamp the ivars `Scope#published_constant_ivars_for(class_name)` names. The write and the read sit in different method bodies, so no flow edge connects them; `ScopeIndexer` censuses the fact per class, gated on the class-ivar accumulator holding a `Type::Constant` for the name, and the seed carries it the way ADR-58's nil seed carries its own.

**Drop and join.** `Scope#with_local` / `#with_ivar` drop the ref, so any rebinding is flow-live and the rule returns. `Scope#join` **unions** the refs. Union is the withholding-safe merge — a mark can only remove a firing, so keeping it where either arm copied the constant is FP-safe — and it is the same direction ADR-67 WD6b's `:inferred_param` taint takes for the same reason.

**The alias is not flow.** A constant write is not a flow edge, so `MODE2 = AppConfig::MODE` MUST NOT ride the carrier above. `ScopeIndexer`'s per-file publication census records `{qualified target => the constant reference its rvalue names}` for a plain constant-reference rvalue and derives `published_constant_alias_names`, the last segments of those targets whose SOURCE is published and not declared by this file. `Scope#published_constant?` answers true for a reference matching that set, ahead of the local-declaration exemption that would otherwise release it. Matching on the last segment over-answers in the withholding direction, which is the safe one; the source's own foreignness is asked through the same suffix relation on qualified names the exemption uses, so a same-file `SECOND = FIRST` chain stays fully reportable, and a name written twice retracts its alias record exactly as it becomes unpublishable.

#### The ADR-46 edges

Three, and each is load-bearing for soundness rather than speed. The published answer for a name is a function of the **whole project's write set for it**, not of the file that currently wins, which is what makes the first of the three name-keyed rather than file-keyed.

- **Name.** A constant reference MUST record `constant:<last segment>` **once per reference, before the resolver ladder runs**, so the edge does not depend on which resolver answered. Recording it only on a miss leaves a reader that resolved with no edge to a *second* declarer appearing elsewhere, and the appearance of that declarer is what drops the name to `Dynamic`. Recording it only on an in-source hit leaves the same hole one resolver over: a reference the RBS environment or the class registry answered is equally dependent on the project's write set, because a project assignment wins over both — `Math::PI.upcase` re-checked against an RBS `Float` stays stale when a project file later assigns `Math::PI`.
- **Positive (file).** When a candidate resolves through `in_source_constants`, the reader MUST additionally record a file-granularity dependency on every file `constant_sources` attributes the name to — the conservative backstop, in ADR-46's over-record-never-under-record direction.
- **Producer.** A recheck MUST widen its closure by the negative-dependents of every constant whose **publication** could have moved: the names whose per-file census descriptor differs between the before- and after-state (`Incremental.changed_constant_publications`). Descriptors MUST be compared with `eql?`, not `==`: `[1] == [1.0]` is true, so an `==` diff calls `LIMIT = 1` becoming `LIMIT = 1.0` unchanged while the published type moved. Diffing assigned NAMES is insufficient and MUST NOT be used — a value edit, a write becoming unpublishable or publishable again, and a second declarer appearing or going away are all publication changes at an unchanged name set. The diff MUST cover **removed** files as well as changed and added ones: deleting a second declarer restores the precise answer, and no other producer input can see that.
- A file's **declaration signature** ([ADR-89](../adr/89-semantic-propagation-gates.md) WD1) MUST include its whole census, descriptors and all. Without the descriptors, `FOO = :sym` becoming `FOO = :other` leaves the file declaration-stable, its file-level dependents are dropped from the closure, and the reader is served the pre-edit answer.

`Environment#constant_for_name(name)` MUST consult the attached `RbsLoader` and return `nil` when the loader is absent or the name has no constant decl. `RbsLoader#constant_type(name)` MUST translate `RBS::AST::Declarations::Constant#type` through `Rigor::Inference::RbsTypeTranslator.translate` and return the resulting `Rigor::Type`, or `nil` when translation produces `Type::Bot` (an empty type). The query MUST NOT raise on malformed inputs; the loader stays fail-soft.

**The predefined-constant refinement tier is a closed table.** `Environment#constant_for_name` consults `Builtins::PredefinedConstantRefinements.lookup(name)` ahead of that RBS table, and the lookup MUST answer only out of tables enumerated in Rigor's own source — the exact-value fold set, and a list of String constants each read ONCE at load time. Admission to that list requires the constant to be non-empty in every build AND present in every process that can run `rigor` at all: the interpreter's own `RUBY_*` / `Ruby::*` / `File` / `Encoding` constants qualify, and so does `Gem::VERSION`, which rubygems versions independently of the interpreter but which is loaded before Rigor's first line either way. A constant that is merely *usually* loaded does not qualify, because whether it answers would then depend on what Rigor itself happens to require. It MUST NOT resolve a name taken from the analysed program against the analyzer's own object space, by `const_get` or by any other means; the same prohibition binds `Inference::VersionGuard`, whose readable-operand sets are closed for the same reason. `const_defined?(name, false)` is NOT a sufficient guard for such a walk and MUST NOT be treated as one: it answers true for a REGISTERED-BUT-NOT-YET-TRIGGERED autoload, so `const_get` executes the target file inside the analyzer, and the target is arbitrary — analysing CRuby's own `lib/prism` reached `prism/translation/ruby_parser.rb`, whose top-level `exit` raised a `SystemExit` that neither this walk's rescue nor the runner's per-file rescue catches, ending the run with no diagnostics and no summary. Wherever such a walk survives — the load-time build of the table, `VersionGuard#runtime_value` — it MUST decline on `Module#autoload?` before resolving (the only predicate that separates a pending autoload from a constant genuinely in memory), and it MUST rescue at least `StandardError`, `ScriptError` and `SystemExit`, because refining a constant is a precision win and no failure of it may stop the run. `Interrupt`, `SignalException` and `NoMemoryError` MUST stay uncaught. Closing the table is what makes the property structural rather than a guard someone has to maintain: no name the analysed program can spell reaches a resolution at all. It costs no measured precision — over GitLab's `app` + `lib` (11,189 files, 184,965 constant references) the open walk answered for five names and ten references, every one of them a core interpreter constant the table lists, against 17 references that would have autoloaded `ipaddr`; everything it answered for beyond the list was a constant that happened to be in **Rigor's own** bundle, which made identical source type differently depending on how the analyzer was installed ([#680](https://github.com/rigortype/rigor/issues/680)). `Inference::Acceptance#resolve_class` conforms to the same walk: it resolves a class name taken from the analysed program (needing the real class object for `Module#<=`, which no table can supply) through `const_defined?(part, false)` and `return nil if mod.autoload?(part)`, rescuing `StandardError`, `ScriptError` and `SystemExit`, so it resolves only classes genuinely loaded and declines pending autoloads without triggering them ([#680](https://github.com/rigortype/rigor/issues/680), [#689](https://github.com/rigortype/rigor/issues/689)).

**A multi-segment reference is relative too.** `Inference::Narrowing`'s own lexical walk (`resolve_class_name_lexically`, shared by every class-membership shape above) MUST apply the step-1 / step-2 candidate ladder to a PATH as well as to a bare name: `Type::Nominal` written inside `module Rigor` names `Rigor::Type::Nominal`, because Ruby anchors a path's FIRST segment through `Module.nesting`, which is the chain the ladder walks (the paragraph below). A candidate MUST be adopted only when `Environment#class_known?` or `Scope#discovered_classes` answers it, and the as-written spelling MUST remain the fallback, so a genuinely absolute path still resolves to itself. Reading any embedded `::` as "already qualified" is not a lost resolution but a wrong name: the guard narrows its receiver to a nominal no environment knows, `class_ordering` answers `:unknown`, and every reader called on the guarded receiver degrades to `Dynamic[top]` — including readers a hand-written `.rbs` declares precisely, and ~300 such sites in Rigor's own `lib/` ([#635](https://github.com/rigortype/rigor/issues/635)).

**The chain the walk is given is `Module.nesting`, wherever one was recorded.** Both this narrowing walk and the step-1 ladder above are handed the chain `Reflection.lexical_nesting_chain` owns, and they MUST read it from there rather than deriving one of their own — a constant read and a guard written beside it over the same spelling MUST name the same constant. The chain is RECORDED as the analyzer enters each declaration (step 2 above); it was previously DERIVED from `Scope#self_type`, and that derivation could not exist: `class Admin::UsersController` and the nested spelling of the same class render the identical `class_name`, so peeling it yielded `["Admin::UsersController", "Admin"]` for both while Ruby's nesting in the compact form is `["Admin::UsersController"]` alone. A bare `User` written there names `::User`, and the derived chain reached `Admin::User` — a wrong type on correct code ([#652](https://github.com/rigortype/rigor/issues/652)). Because the defect lived in the derivation it was shape-independent, and repairing it closed `is_a?` / `kind_of?` / `instance_of?`, `case`/`when`, `===` and the constant typer at once; the corollary binds going forward, so a change to how the chain is built MUST be made in `lexical_nesting_chain` and MUST keep every shape in agreement. Widening the walk to a shape that previously resolved nothing does not license a divergence from Ruby's nesting for that shape, and MUST NOT be treated as a reason to keep a shape unresolved. The claim is scoped to a RECORDED chain, and the peel fallback of step 2 is NOT `Module.nesting`: it answers the NESTED chain for both spellings, so wherever it is still reached a compact declaration resolves as though it had been written nested. Nothing in `lib/` now builds a scope from a self type alone: the callee re-walk named in step 2 was the last, and it reads the chain the def-node index records, so a value's type no longer depends on whether it was read on the line that writes it or through the return-inference re-walk of the method that produced it ([#681](https://github.com/rigortype/rigor/issues/681)). What still reaches the peel FIRST is a scope no declaration walk built AND no recorded chain covers — a plugin-constructed scope, a callee body re-entered through `Scope#evaluate` — and for those the stale-but-gradual rung is the deliberate answer, not a residue. A top-level `def` body is no longer one of them: its chain is RECORDED as `[]`, so the constant ladder resolves it at the top level and reaches the peel only below that ([#716](https://github.com/rigortype/rigor/issues/716)). The narrowing walk reads the same recorded `[]` and therefore answers the bare name for a class guard written in such a body, which is what keeps a constant read and an `is_a?` beside it naming the same class. A callee restored from an ADR-85 seed bundle is NOT one of them WHERE THE RESOLVER'S PER-RUN MEMO SCOPE IS IN FORCE: its chain is carried on the `Inference::DefHandle` and rehydrated onto the node the resolver mints, so a warm `--incremental` recheck and a cold run answer the same constant for the same body. Resolved OUTSIDE that scope it rejoins the list above and keeps the peel, which is why every entry point that consumes a handle is required to enter one ([#707](https://github.com/rigortype/rigor/issues/707)).

### Reachability report tiers (ADR-102)

`rigor unused` reports on a reference graph built by `Analysis::Reachability::Scan` (a standalone Prism walk, NOT the typing path) and swept by `Analysis::Reachability::Graph`. The output tiers are normative:

1. **`candidates`** — project-owned declarations no reachable declaration references. Mark-and-sweep, not reference counting: an edge MUST propagate reachability only when its source is itself reachable, so a cluster of mutually-referencing dead declarations MUST still be reported.
2. **`undecidable`** — a declaration something can name at runtime. A `constantize` / `safe_constantize` / `const_get` whose subject is a **literal** string or symbol MUST resolve to that exact constant and contribute an ordinary reference; only a non-literal subject demotes. An interpolated subject with a literal head (`"Foo::#{k}"`) MUST taint `Foo` and everything beneath it and nothing else; a subject with no literal head MUST taint **nothing** — poisoning the whole project would empty the report. A data-file match MUST taint **only the name it matched**, never that name's descendants: an interpolated site can *construct* any name under its head, whereas a data file merely *contains* one, which is evidence about that declaration alone. (Read as a namespace taint, the Afrikaans word "Administrasie" demoted 18 unrelated `Admin::*` rows on Mastodon and the word "Redmine" in a YAML file demoted 47 `Redmine::*` rows out of `candidates` — issue #370.) A declaration whose fully-qualified name appears as a string in a template or data file (`.erb`, `.haml`, `.slim`, `.yml`, `.yaml`, `.json`) MUST demote to this tier rather than count as a reference: a data-file match is weaker evidence than a constant node, and treating it as proof would hide real dead code. Every row MUST carry the reason it was demoted. The demotion applies to a `test_only` declaration as well as an unreached one, so this tier is NOT a subset of the unreached: `test_only` asserts that no production caller exists and a data-file mention is evidence against that assertion, exactly as it is evidence against `candidates`. (Read as unreached-only, the rule left a job named in `config/recurring.yml` and referenced from its spec reporting as a dead production path while it ran every three minutes — issue #370.)
3. **`test_only`** — reachable, but only through edges whose referring file has the `:test` role, AND carrying no evidence that demotes it to `undecidable` (tier 2). Reported separately from both other tiers (ADR-102 WD8). The section asserts that no production caller exists, so a row MUST NOT appear here when the analysis holds evidence against that.
4. **`namespaces`** — an unreached declaration under which some *reachable* declaration lives. Excluded from `candidates`, because nothing references an intermediate namespace segment by itself. A namespace whose contents are **all** unreachable MUST remain a candidate.

Ownership: a declaration is project-owned only when it is declared in an analysed file AND the name is unknown to an environment built **without** the project's own `signature_paths`. Reopening a gem or stdlib class MUST NOT make it a candidate.

Constant resolution inside the report MUST follow the same candidate order as `Reflection.resolve_constant_type` (nesting, then ancestors, then bare name). `Scan` already records the nesting in force at each reference as a stack of DECLARATION names and `Graph#resolve` pops one frame at a time, so the report has always had Ruby's semantics for a compact declaration; keeping it that way is normative, and popping `::segment`s here would import the defect [#652](https://github.com/rigortype/rigor/issues/652) fixed on the typing side. One addition to the shared order: when a name resolves to no declaration, the trailing `::segment` MUST be peeled and retried, so a reference to `Foo::BAR` counts as a reference to `Foo`. The report carries the rooted marker of step 0 above: `Scan::Reference` carries `rooted` (populated by `Source::ConstantPath.rooted?`), and `Graph#resolve` skips lexical nesting and ancestor scopes when set, answering the top-level declaration directly (or peeling member segments). A `::Foo` reference inside a shadowing namespace therefore resolves to top-level `Foo` rather than the shadow, avoiding the false `candidates` rows that divergence manufactured ([#625](https://github.com/rigortype/rigor/issues/625)).

### Declaration-position overrides (Slice A-declarations)

`Rigor::Scope` carries a `declared_types` table — an identity-comparing `Hash[Prism::Node, Rigor::Type]` that overrides `ExpressionTyper#type_of` for specific node identities. Since [ADR-53](../adr/53-scope-discovery-index-separation.md) it is one of the [Discovery Index](#discovery-index-adr-53-track-a) tables (read through the `Scope#declared_types` delegate, seeded through `Scope#with_discovery`); the default value is a frozen empty hash. `Scope#with_local`, `Scope#with_fact`, `Scope#with_self_type`, and the join helpers MUST carry the index — and so the table — through by reference.

`ExpressionTyper#type_of(node)` MUST consult `scope.declared_types[node]` BEFORE any other dispatch. When a value is present, the typer MUST return it as-is and MUST NOT record a fallback event.

`Rigor::Inference::ScopeIndexer.index(root, default_scope:)` MUST populate the table for declaration-position nodes:

- `Prism::ModuleNode#constant_path` MUST map to `Singleton[<qualified-path>]` where `<qualified-path>` is the join of every enclosing `ModuleNode`/`ClassNode` declaration name.
- `Prism::ClassNode#constant_path` MUST map to the corresponding `Singleton[<qualified-path>]`.
- The override MUST cover the OUTERMOST `constant_path` node only. For `class Foo::Bar`, the inner `Foo` reference remains a real lookup (resolved through the lexical walk).
- A **compact header written inside an enclosing namespace** (`class Outer::Leaf` in `module Wrap`) resolves its LEADING segment the way any other constant reference resolves: through the nesting, falling through to the top level when the nesting supplies no such namespace. The declaration MUST therefore be keyed `Outer::Leaf`, not `Wrap::Outer::Leaf`, whenever the project declares no `Wrap::Outer` AND does declare a top-level `Outer`; when `Wrap::Outer` exists the header reopens `Wrap::Outer::Leaf` as before. This is the ONE place declaration keying is not a per-node function of the header and its enclosing prefix, so `Source::ConstantPath.declaration_prefix` MUST keep answering per-node and the re-anchoring MUST be adjudicated once against the whole project's declared names (`ScopeIndexer.compact_header_renames`, applied to the folded discovery tables and to each file's own declaration table). Both halves of the condition are load-bearing: a `Wrap::Outer` that merely never appears in project source (a gem, an RBS-only class) is a namespace that exists at runtime, so re-anchoring on its absence alone would answer with a wrong class where declining answers with silence ([#722](https://github.com/rigortype/rigor/issues/722)). A declaration nested inside such a header moves with it. The re-keying MUST be a MERGE, not a replacement: a rename lands a declaration on a key the table may already hold — `class Outer::Leaf` written at the top level and again as a compact header inside `module Wrap` is ONE class with both bodies. Most class-keyed tables combine the two contributions per entry key, which is right where those keys are distinct declaration sites. Two tables MUST NOT: `parameter_envelopes` folds with `Source::ParameterEnvelope.merge`, since two bodies disagreeing is exactly what makes a name opaque ([#992](https://github.com/rigortype/rigor/issues/992)), and `header_nestings` is keyed by the raw ancestor NAME rather than by site, so both bodies' `include Mixin` land on the key `Mixin`. Its colliding entries MUST be kept SIDE BY SIDE as alternative chains, and the choice deferred to `Scope#ancestor_name_candidates`, which MUST decline outright — an empty candidate list — when two alternatives resolve the name to two DIFFERENT project classes. Neither replacing one chain with the other nor unioning them is sound: at runtime both `include`s run and which same-named module lands nearer in the MRO is the files' load order, so a pick is a WRONG ancestor, and two such modules declaring one method at different arities makes `call.wrong-arity` fire on a correct program. Declining costs a resolution and reports nothing, which is the side this engine errs on. The re-anchored bucket MUST also be filed under the name the declaration was WRITTEN with, because a body inside the compact header keeps the per-node `Singleton[Wrap::Outer::Leaf]` self and the per-file ancestry tables laid over the project seed are keyed that way too: without the alias that body saw its own site's chain alone, and the collision's false positive fired inside the very declaration that causes it. Where the alternatives AGREE, or only one of them resolves to a project class at all, there is nothing to adjudicate and the answer MUST be the union of their chains, most-qualified first — the list a class whose sites needed no rename gets — so an unambiguous collision is unchanged and an EXTERNAL ancestor keeps the full candidate list the gem / RBS probe reads. The decline is per ancestor NAME and MUST NOT silence a rule for the whole receiver: a rule that reports on a METHOD (`call.wrong-arity`) MUST read both ambiguous classes as ancestors — both `include`s do run — so that a method only one of them declares keeps its verdict and only a method they disagree about is unanswerable ([#986](https://github.com/rigortype/rigor/issues/986)).

The seeded scope produced by `index` MUST carry the populated table so the StatementEvaluator's class-body and method-body fresh scopes (`Scope.empty(environment: ...)` followed by `with_self_type` and `with_discovery`) propagate the override into nested bodies. Indexer-produced scopes MUST be used by `Rigor::Scope#type_of` callers (CLI probes, test fixtures) so the override actually fires; bare `Rigor::Scope.empty` scopes consciously preserve the empty-table behaviour for test isolation.

Top-level scopes (no `self_type` set) MUST yield only the bare candidate so the pre-walk behaviour is observable for tests that do not configure a class context. The walk MUST NOT mutate the receiver scope, MUST NOT raise on names that fail to resolve, and MUST NOT traverse the singleton ancestry chain — that refinement is a future slice.

### Join with Nil-Injection

`Scope#join` drops names bound in only one receiver (per the [Immutable Scope Discipline](#immutable-scope-discipline) above). The statement-level evaluator's branch-merge MUST instead inject `Constant[nil]` for half-bound names so the joined scope sees them as `T | nil`:

- For names bound in `scope_a` but not `scope_b`: bind those names to `Constant[nil]` in `scope_b` before joining.
- For names bound in `scope_b` but not `scope_a`: bind those names to `Constant[nil]` in `scope_a` before joining.
- Then call `Scope#join` on the augmented scopes; the result MUST contain every name from either side, with the union including `Constant[nil]` for names bound in only one side.

This is the contract that the Slice 3 phase 1 [Immutable Scope Discipline](#immutable-scope-discipline) defers to the statement-level evaluator. N-ary branch merges (case/when, begin/rescue chain) reduce by repeated pairwise join-with-nil-injection; the reduce order does not affect the result because nil-injection commutes with union under `Scope#join`.

### Per-Node Scope Index

`Rigor::Inference::ScopeIndexer.index(root, default_scope:)` is the canonical surface that converts a Prism program subtree into a per-node scope lookup. It MUST satisfy:

- The return value MUST be an identity-comparing `Hash{Prism::Node => Rigor::Scope}`. Looking up a node not contained in `root`'s subtree MUST yield the *seeded* scope through the `Hash#default` slot — `default_scope` after the indexer's own declaration-override, class-ivar, class-cvar, program-global, in-source-constant and discovered-method seeding passes have been applied to it, never the bare `default_scope` the caller handed in. A miss therefore observes the same ambient discovery context as a hit.
- For every Prism node the StatementEvaluator visits during `evaluate(root)`, the indexer MUST record the entry scope observed at that visit. Visits are fired through the `on_enter:` callback the indexer wires onto a fresh evaluator (the StatementEvaluator therefore stays state-free; the indexer carries the table).
- For every Prism node in `root`'s subtree the StatementEvaluator does NOT visit (expression-interior children of nodes that the evaluator's default branch fell through on), the indexer MUST set the recorded scope to the nearest recorded ancestor's scope. The DFS pre-order propagation is a contract: a child MUST observe an entry scope at least as informative as its parent's, never weaker.
- The indexer MUST run its internal StatementEvaluator with `tracer: nil`. CLI callers that want fail-soft fallback events MUST attach their tracer only to the post-index `type_of` probe, so the events come exactly from the second pass and are not double-recorded by the indexer's own typing of the program tree.

The CLI commands `rigor type-of` and `rigor type-scan` MUST consult the index when typing nodes from a parsed file, so locals bound earlier in the program flow into the scope used to type later nodes. Both commands look up `index[node]` and then run `node_scope.type_of(node, tracer:)`. The contract above is what makes this composition correct.

### Cross-File Method Discovery (ADR-24)

To resolve implicit-self calls against user-defined classes that carry no RBS, `Rigor::Inference::ScopeIndexer` runs a bounded project pre-pass and threads the discovered tables through derived scopes. `Rigor::Scope` exposes them as pure queries keyed by qualified class name:

- `Scope#user_def_for(class_name, method_name)` — the `Prism::DefNode` for an instance method, or `nil`.
- `Scope#user_def_site_for(class_name, method_name)` — the defining location as `"path:line"` when the cross-file pre-pass populated it (so `CheckRules` can point a cross-file monkey-patch diagnostic at the defining file), or `nil`.
- `Scope#top_level_def_for(method_name)` — the `Prism::DefNode` for a file-scope (top-level) `def`, or `nil`. The table is project-wide, and this accessor is the *suppression* surface: a name the project defines at the top level MUST NOT be reported by `call.unresolved-toplevel` / `call.undefined-method`, whatever the binding gate below decides.
- `Scope#bindable_top_level_def_for(method_name)` — the confidence-gated companion, and the ONLY accessor type inference may bind an implicit-self call through. It MUST return `nil` (decline to bind; the call widens to `Dynamic[top]`, and no diagnostic is traded in) exactly when BOTH hold: the call site sits inside a block whose `self` is unmodelled (`Scope#opaque_block_self?`) with no narrowed `self_type`, AND the `def` was recorded from a different file than the call site's `source_path`. A top-level `def` is a private method on `Object`, so it is callable from any `self`; what the analyzer cannot see is whether the block's real `self` gained a PUBLIC same-named method by `include` / `extend`, which wins the MRO — a project's `def output` versus RSpec's `output` matcher. Both conditions are required, so a top-level helper called from genuine top-level code keeps resolving cross-file, and a `def` collocated with its DSL-block call site keeps resolving. When the pre-pass recorded no source for the name, or the scope carries no `source_path`, the file test is unanswerable and the accessor MUST bind.
- `Scope#superclass_of(class_name)` — the as-written superclass name from `class Foo < Bar`, or `nil`.
- `Scope#ancestor_name_candidates(class_name, raw_ancestor)` — the ordered candidate names that as-written ancestor spelling can denote, most-qualified first and the bare name last. The SINGLE owner of that order: the ADR-24 method walk, the constant ladder's step-3 ancestor rung and the ADR-35 override-visibility rule MUST all read it, and none may re-derive it. The entries MUST come from the `Module.nesting` the SUBCLASS'S DECLARATION HEADER is written in — recorded per declaration by the discovery pre-pass as `Scope::DiscoveryIndex#discovered_header_nestings`, and equal to the body's chain minus the declaration's own entry, because Ruby evaluates a superclass expression BEFORE entering the body. It MUST NOT be reconstructed by peeling `class_name` one `::` segment at a time: that peel is the NESTED spelling's chain given to both spellings, so a compact `class Admin::Widget < Base` written at the top level searched an `Admin::Base` Ruby never looks at — losing a method the top-level `Base` owns, and answering the step-3 constant rung from the wrong class outright ([#682](https://github.com/rigortype/rigor/issues/682)). It MUST NOT be read off the READER's `Scope#lexical_nesting` either: the chain that governs an ancestor name is a property of the declaration, so past the first hop of the ancestor BFS it would describe the wrong class, and the run-scoped ancestor memos (`Inference::ExpressionTyper#class_graph_buckets`, `Reflection.ancestor_constant_scopes`) key on the class name alone precisely because this walk is a pure function of the frozen discovery tables. Only a site that WRITES an ancestor name — a superclass in its header, or a mixin call whose `self` is the declaration itself — MUST contribute a header nesting; a site that names no ancestor has none for its cref to govern, and recording it anyway let `class ::Foo` written in `module Outer` resolve `Foo`'s superclass `Base` as `Outer::Base`, a class Ruby never looks at, ahead of the right one. The mixin test MUST stop at every construct that rebinds `self` (a nested declaration, a `class << self` body, and the block forms `rebound_block_self` classifies), since an `include` written in one of those attaches elsewhere. This is also what protects a class reopened under two spellings: rails declares `ActiveRecord::Relation` inside `module ActiveRecord` and reopens it compactly in a test file that names no ancestor, so the reopen no longer competes with the declaration carrying the nine included modules — by the recording rule rather than by a merge rule. The recorded chain MUST be keyed by the ancestor NAME the site wrote, not by the class alone: Ruby resolves each ancestor name in the cref of the site that wrote it, and a class's sites need not share one. A rooted reopen that genuinely NAMES a mixin is recorded, so a per-class union then hands its chain to the other sites' ancestors too — `class Foo < Base` at the top level plus `class ::Foo; include Helper; end` inside `module Outer` resolved `Base` as `Outer::Base`, the same wrong class the recording rule above removes for a reopen that names nothing ([#728](https://github.com/rigortype/rigor/issues/728)). Two sites that write the SAME name are unioned, most-qualified first — EXCEPT where the compact-header re-keying above landed them on one key from different crefs, which is kept as alternatives and declined rather than unioned ([#986](https://github.com/rigortype/rigor/issues/986)). A single unkeyed chain, the union over every ancestor-naming site, MUST also be recorded and MUST answer an ancestor name no site recorded under its own key — a mixin the includes walk attributes to a class from outside its declaration (`Recv.class_eval { include M }`), or a dynamic mixin argument — so such a name keeps the per-class answer rather than a shorter one. The table MUST also travel in the ADR-85 seed bundle, so a warm incremental file resolves its ancestor names where a cold walk of it does. Where no header nesting was recorded for `class_name` the peel MUST survive as the fallback — it is the answer the walk already gave, so an unrecorded class is unchanged rather than degraded. An include / prepend name is written INSIDE the body, where Ruby also tries `<class_name>::<raw>` first; that rung is deliberately NOT offered, matching the peel it replaces.
- `Scope#includes_of(class_name)` — the array of module names included/prepended by the class, as written, in instance-ancestor SEARCH order ([#1173](https://github.com/rigortype/rigor/issues/1173)): prepended modules first (Ruby puts them ahead of the class itself), then includes nearest-first — `include A; include B` searches B before A, while `include A, B` keeps `["A", "B"]`, one statement's arguments landing as a unit ahead of the earlier statements'. A re-`include` of an already-carried name is a runtime no-op and MUST NOT re-position it. Before #1173 the list was call order — `include M1; include M2` answered M1's `def`, a divergence from Ruby's later-include-wins — and the change is what lets the include-edge dispatch arm adopt the declaration Ruby actually selects. The table MUST also travel in the ADR-85 seed bundle in this order (the `IncrementalSnapshot::SCHEMA` bump is what keeps a pre-change blob a cold rebuild rather than a warm run reading the old call order); used to resolve implicit-self calls through the mixin chain. Across files the fold approximates load order as later-file-nearer, so a LATER file that re-includes an already-carried name keeps it nearest where the runtime's re-include no-op would leave it farthest — the same file-order approximation the extends table has carried since #1123, accepted because static load order is unknowable.
- `Scope#user_def_through_ancestors(class_name, method_name)` — the ADR-24 user-side ancestor walk ([#1123](https://github.com/rigortype/rigor/issues/1123)). At EVERY class the walk visits it MUST search that class's prepend wedge BEFORE the class's own `def`s: each module the class prepends (`discovered_prepends`, recorded for the in-body `prepend M` and the `Recv.prepend(M)` call form alike), in instance-ancestor search order — a later `prepend` statement nearer, one statement's arguments in call order — each expanded to its own prepend wedge, itself, then its includes. Ruby inserts the prepended module and its whole sub-chain ahead of the class, so a class-own `def` found first is the method the program does NOT run: a wrong precise claim, not lost precision. The include half follows `includes_of`'s search order since #1173 — an included module still sits after the class — and `includes_of` keeps listing prepended names ahead of them, since its consumers ask which modules a class carries as well as in what order. The singleton-side prepend (`class << self; prepend M`) is not ordered by this table; it stays folded into `discovered_extends`.
- `Scope#discovered_method_visibility(class_name, method_name)` — `:public` / `:private` / `:protected` for a user-defined method, or `nil`; consumed by the `def.method-visibility-mismatch` and `def.override-visibility-reduced` (ADR-35) rules.

These tables live on the scope's [Discovery Index](#discovery-index-adr-53-track-a); a seeded index threads them forward through derived scopes via `Scope#with_discovery`.

**The top-level binding is LAST in the implicit-self order, not first.** A top-level `def` is a private method on `Object`, the last link of every MRO, so a class that carries the name answers the call and the top-level body is never reached at runtime. `ExpressionTyper` MUST therefore decline the bind — the call falls through to the ordinary dispatch pipeline — whenever `scope.self_type` names a class that answers the name itself, whatever `Scope#bindable_top_level_def_for` returns. For a `Nominal[X]` self (and for the `StructInstance` / `DataInstance` carriers, which additionally answer from their own member map) that is any of: an entry in the discovered-methods table (`def` / `attr_*` / `define_method` / `alias`) of `X` **or of any project ancestor of `X`** (`Scope#discovered_method_through_ancestors?`), a `Struct.new` / `Data.define` member accessor recorded in `X`'s member layout, a `def` reached by the ADR-24 ancestor walk (`Scope#user_def_through_ancestors`), or an RBS instance method whose owner PRECEDES `::Object` in `X`'s instance MRO. For a `Singleton[X]` self (a class body) the singleton twins apply, each following the superclass chain because that is the whole shape of class-method inheritance: the discovered singleton methods of `X` or a superclass, `Scope#singleton_def_through_ancestors`, or an RBS singleton method declared on `X` itself. **The instance RBS arm's cut-off MUST be `::Object`, not the own class.** A top-level `def` is `Object`'s own private instance method, so an owner before `::Object` — `Exception#message` for a `StandardError` subclass, `Array#first`, `Comparable#clamp` — wins the MRO at runtime, while a name owned by `Object` or `Kernel` themselves sits at or after the top-level `def`'s rung and MUST NOT retract the binding this tier exists for. Where `X` is absent from the RBS environment (the usual case for a project class) the arm MUST ask the same question of each ancestor the project does NOT declare — the `< StandardError` superclass, the `include Comparable` mixin — reached through `Scope#external_ancestor_name_candidates`; each such ancestor is before `::Object` in `X`'s MRO by construction. Issue #633: the own-class-only reading left `attr_*` / `define_method` inherited from a project superclass or module, every RBS method on a pre-`::Object` ancestor, and the entire singleton ancestor chain binding a top-level `def` ahead of what Ruby dispatches to. A `nil` `self_type` (genuine top level, or a block whose `self` is unmodelled) is out of scope for the veto, so the confidence gate above stays the only thing deciding those. Issue #618: without this precedence a top-level `def text` typed the member read inside `class Line < Struct.new(:text); def shout; text.upcase; end; end` as the def's `nil` and reported `undefined method 'upcase' for nil` on correct code.

**A plugin-supplied member is a veto source of its own.** Every source above is one the engine walks; a member a plugin contributes is not, and Ruby dispatches to it ahead of `Object`'s private top-level `def` exactly as it does to an `attr_reader`. `ExpressionTyper` MUST therefore ALSO decline the bind when a plugin answers the name on the call's own `self`, and it MUST establish that by asking the same two tiers `MethodDispatcher#resolve` consults rather than by reconstructing plugin knowledge in the veto: the gated `dynamic_return` walk (`MethodDispatcher#try_plugin_contribution`, with `scope.self_type` as the receiver type), and the ADR-16 synthetic-method index — Tier C `heredoc_templates` emissions today, and the Tier B `Plugin::Macro::TraitRegistry` explosions that share its table once #476 threads a real environment into the pre-pass that builds it (the pre-pass passes `environment: nil`, and the scanner short-circuits to an empty index when only trait registries contribute, so no trait member is reachable here yet). The question asked is MEMBERSHIP, not the type: the veto only stops the top-level bind, after which the call falls through to the ordinary dispatch pipeline where the tier that answered here answers again. #618's confidence gate is unchanged and applies first — a `nil` `self_type` does not participate, so the receiver the veto would otherwise hand a plugin is never the synthetic `Object` stand-in a top-level call substitutes. Issue #963 item 2: without this a project's top-level `def name` in a script or spec-support file bound ahead of a rigor-activerecord column reader and typed `name.upcase` inside the model's own `def` as the def's `nil`. The member has to reach a tier to be seen — a plugin that answers only a WRITTEN receiver contributes no evidence about the implicit-self spelling, which is why `rigor-activerecord` answers an implicit-self column / association / `column?` read `untyped` (it knows the member exists and declines to type it there; contributing the column's real type was measured to cost new `flow.always-truthy-condition` and `call.possible-nil-receiver` firings on the corpus, and is a separate precision question).

**Singleton-class bodies opened on a constant.** A `class << X` body registers its `def`s on the `:singleton` side of the constant `X` names, under that constant's *unqualified* rendering (`Foo`, `A::Foo` and `::Foo` all render as written, independent of the enclosing lexical prefix; `class << Foo` directly inside `class Foo` collapses onto the enclosing prefix, since it is then a spelling of `class << self`). The operand MAY be a constant *write* (`class << Foo = <expr>`, the private-singleton-object idiom): Ruby evaluates the assignment and then opens the singleton of the resulting object, which is the object the constant now holds, so the write spelling MUST register on the same key as a body opened on a later plain read of that constant. Any other operand (a local variable, a method call) is not statically resolvable to a constant and MUST leave the body unregistered.

When the constant names a class or module, a read of it types as `Singleton[X]` and the dispatcher recovers `X` from the receiver type. When it holds an ordinary object the read types as `Nominal[Object]` and the name is not in the type, so `ExpressionTyper` MUST additionally resolve such a call from the receiver *syntax*: for a call whose receiver is a constant reference and whose receiver type is a `Nominal` (never a `Singleton` — the class/module path above owns those), the singleton def table MUST be consulted under the constant's name, and a hit MUST re-type the body with the call's argument types bound. `call.undefined-method` MUST apply the same recovery as a suppression probe. Both are scoped to names the table actually records, so a method absent from the singleton body still fires.

`Scope#opaque_block_self?` returns `true` inside a block body. Ruby gives a block no `self` of its own — the yielding method decides, and `instance_eval` / `instance_exec` (the mechanism behind every `self`-rebinding DSL) is indistinguishable from `Array#each` without knowing the callee — so both block-entry paths (`StatementEvaluator#build_block_entry_scope` and `ExpressionTyper#block_return_for`) MUST set the mark via `Scope#entering_opaque_block`. A lambda literal's body enters through the first of those and therefore carries the mark too: Ruby does give it the lexical `self`, but `lambda { … }` is the same object under another spelling and has always been marked, and the two MUST agree. The mark is inherited by every scope derived inside the block and MUST NOT leak past it.

**`define_method`'s block body is the instance side of the class.** `Module#define_method` installs its block as an INSTANCE method and runs it with `self` bound to the receiving instance, while the block would otherwise inherit the class body's `Singleton[X]` carrier — the other side of the same class. A block on a `define_method` call whose receiver is the enclosing body's own `self` (implicit, or written `self`) MUST therefore enter with `self_type` narrowed to `Nominal[X]` when that body's `self` is `Singleton[X]` — on BOTH block-entry paths, so the return-typing pass cannot record a carrier the statement evaluator disagrees with. A project-declared generic `define_method` makes that value observable, so the agreement is not academic. The opaque mark above still applies: the narrowing changes which class the own-method veto asks about, not whether the block's real `self` is modelled, and `Scope#bindable_top_level_def_for`'s confidence gate is untouched because it fires only on a `nil` `self_type`. Nor does the narrowing apply to a call on any other receiver, which is not the lexical class.

**The one exclusion is the `class << ...` body itself.** There `self` is the singleton class and the same call defines a CLASS method — an instance reader is not in that MRO, MRI itself reaches the top-level `def`, and Rigor MUST answer the same. The exclusion is the BODY, not the singleton frame: a `def` reached from that body (`class << self; def install; define_method(:shout) { ... }; end; end`) has the class object as its `self`, so the call defines an instance method there and the narrowing MUST apply. A `Singleton[X]` carrier cannot tell the two apart — a `class X` body and a `class << X` body both produce it — so `Scope#singleton_class_body?` MUST carry the distinction: stamped at singleton-class-body entry, inherited by every scope derived inside it (blocks included), cleared by construction at a `def` body, which starts from a fresh scope, and cleared explicitly for a meta-class body, which is a class body of its own. Carrying it on the scope rather than on the evaluator's frame stack is what lets both block-entry paths apply the identical exclusion. Issue #963: without it a top-level `def text` bound ahead of the member in `class Line < Struct.new(:text); define_method(:shout) { text.upcase }; end` and reported `undefined method 'upcase' for nil` on correct code.

`Scope#toplevel?` returns `true` when the scope has no enclosing class/module body (`self_type` is `nil`). It gates the toplevel-only `call.unresolved-toplevel` rule (ADR-34): an unresolved implicit-self call at the top of a file warns, while the same miss inside a class/`def` body stays lenient per ADR-24 WD3.

### `Rigor::Inference::StatementEvaluator#initialize(on_enter:)`

The third constructor keyword on `StatementEvaluator` is the hook the ScopeIndexer drives. It MUST satisfy:

- `on_enter:` defaults to `nil`. When `nil`, no callback fires and the evaluator's behaviour MUST be observably identical to a slice 3 phase 2 evaluator constructed without the keyword.
- When non-`nil`, the callback MUST be called exactly once at the start of every `evaluate(node)` call, before the handler dispatch, with `(node, scope)` as the arguments — `node` is the Prism node being entered and `scope` is the entry scope (`@scope` at that recursion level).
- The callback MUST be threaded through every recursive `sub_eval` so that nested invocations on forked scopes still report their own entries.

### Method Parameter Binding

`Rigor::Inference::MethodParameterBinder.new(environment:, class_path:, singleton:)` is the canonical surface that builds the method-entry scope from a `DefNode`. It MUST satisfy:

- `bind(def_node)` MUST return an ordered `Hash{Symbol => Rigor::Type}` of parameter name to bound type, in the order the names appear in the def's parameter list.
- Anonymous parameters (`*` and `**` without an identifier) MUST be skipped silently because there is no local name to bind.
- When `class_path:` is `nil`, when the environment has no RBS loader, or when the resolved class/method is unknown to RBS, every parameter MUST default to `Dynamic[top]`. The binder MUST NOT raise on RBS misses; the fail-soft contract from the Slice 1 fail-soft policy applies at the binding boundary too.
- When the RBS lookup succeeds, every parameter slot MUST be bound to the *union of the matching RBS parameter types across every overload that has that slot*. Overloads that omit the slot (e.g., `Array#first`'s `()` overload, vs the `(?int)` overload that the `n` parameter of `def first(n)` matches) MUST be skipped silently rather than contributing a `Dynamic[top]` (so the binding is the most informative type the signature provides without having to know which overload the caller will pick).
- Positional slots (required, optional, rest, trailing) MUST be matched by *position* into the matching RBS positional list. Keyword slots (required, optional) MUST be matched by *name* across both the required and optional keyword maps so a `def foo(by:)` redefinition picks up an `?by:` keyword in the RBS overload (or vice versa).
- A `*rest` parameter's bound type MUST be `Nominal["Array", [T]]` where `T` is the translated rest element type. A `**kw_rest` parameter's bound type MUST be `Nominal["Hash", [Nominal["Symbol"], V]]` where `V` is the translated rest-keyword value type. The binder MUST NOT bind a rest parameter to a single element type — the local actually holds the array/hash.
- When `def_node.receiver` is a `Prism::SelfNode` OR `singleton:` is `true`, the binder MUST consult `RbsLoader#singleton_method` (the immediate enclosing lexical scope is a singleton class). Otherwise it MUST consult `RbsLoader#instance_method`. The translator's `self_type:` and `instance_type:` keywords MUST be set to `(Singleton[C], Nominal[C])` for the singleton route and `(Nominal[C], Nominal[C])` for the instance route.
- **Path-scoped protocol contracts — the *provide* side (ADR-28).** When the binder runs with a non-`nil` source path and a loaded plugin contributes a `Plugin::ProtocolContract` (via `Environment#plugin_registry.contracts_for_path`) whose `path_glob` matches the file, whose `method_name` matches the `def`, and whose `singleton` flag matches the def's singleton-ness, the binder MUST replace each contracted positional slot's binding with the contract's declared parameter type. The type name resolves through `Environment#nominal_for_name` **lazily, at binding time**; an unresolvable name (the protocol's RBS not loaded) MUST fall through to whatever the prior tiers bound — fail-soft, never raising. This is how a path-conventional method (a `lib/controller/**/*.rb` action whose `request` parameter is implicitly a `Rack::Request`) is analysed with its protocol type even though no RBS or argument annotates it. The companion **check** side — confirming the method exists and its inferred return conforms to `return_type_name` — is not an engine rule but the contributing plugin's own `#diagnostics_for_file` responsibility; the value-object shape is in [`plugin.md`](plugin.md#rigorpluginmanifest) (`protocol_contracts:`).

### Call-Site Argument Shapes (issue [#1125](https://github.com/rigortype/rigor/issues/1125))

The binder above is the RBS-driven one. The **call-site** binder is `ExpressionTyper#call_arg_types`, which types a
call's argument list for inter-procedural return inference and for every dispatch tier; `#bind_params_from_call_types`
then binds a user `def`'s parameters from that list. Two call shapes it used to decline now carry types. Both are
precision-only: a parameter type derived from a call site is a LOWER BOUND, so no negative rule reads it and a wrong
binding cannot manufacture a diagnostic inside the callee's body.

- A keyword-hash argument built ENTIRELY from a double splat (`f(**h)`) whose value's type is a CLOSED `HashShape`
  with Symbol keys MUST be typed at the call site as that shape, so `f(**h)` binds the callee's named keyword
  parameters by name exactly as the literal form `f(a: 1, b: 2)` does. The shape MUST be carried in the argument list
  itself rather than passed alongside it, because the ADR-84 return memo keys on `(def_node, receiver, arg_types)`.
- Every other keyword-hash argument MUST keep its own pre-existing type, and so keep the pre-#1125 answer: a MIXED hash
  (`f(a: 1, **h)` — the literal pairs and the splatted shape are not merged), an OPEN shape (unknown extras make every
  missing-keyword answer a guess rather than a read), a shape with a non-Symbol key (Ruby itself rejects those as
  keywords), a shapeless `Hash[Symbol, V]`, and any other value. The binder then declines the call, which answers
  `Dynamic[top]` exactly as before.
- A named `**rest` parameter MUST bind the CLOSED `HashShape` of the pairs no named keyword parameter consumed, with
  each pair's value type. With no keyword shape, an OPEN shape, or no pair left over it MUST keep `Dynamic[top]`: the
  last case is what leaves the literal form's existing binding untouched (`def target(a:, b:, **rest)` called
  `target(a: 1, b: 2)` still binds `rest` to `Dynamic[top]`), while a caller that leaves keys over — the only shape
  where the parameter holds something to report — gets them typed.
- `def m(...)` MUST NOT be declined by the call-site binder. Its NAMED parameters (a leading `def m(a, ...)`
  required) bind as before, and nothing is bound for the forwarding slot, which is not a binding at all.
- A `f(...)` call inside a `def m(...)` body MUST expand to the argument types of the call that entered the frame, so
  the callee's parameters bind from the forwarding method's own call site. The frame's list is installed per
  user-method inference frame and is the callee's call-site `arg_types` — which is what keeps the return memo's key
  complete for a forwarding def — and it MUST be restored on exit like the yield value beside it. `...` is therefore
  threaded ACROSS a chain, not one level: each frame installs its own list, so `forward -> middle -> target`
  re-expands at every hop, bounded by the ordinary recursion guard / return memo.
- The forwarded list MUST exclude the positionals the forwarding method's own named parameters consumed
  (`def forward(a, ...) = target(a, ...)` re-supplies the tail, not `a`) and MUST keep a trailing keyword shape, which
  `takes_keywords?` reads as the keyword tail rather than as a positional. A call that does not even satisfy the
  forwarding method's own required positionals MUST decline: it raises at runtime and its body is not worth
  re-typing.
- `target(*args)` and `target(a, &blk)` MUST stay declined, and the decline is recorded here rather than left
  implicit. A `Prism::SplatNode` argument types as `Dynamic[top]`, so the callee's required positionals cannot be
  counted; expanding a `Tuple`-typed rest into positional slots is a positional-correspondence slice of its own. A
  `&blk` parameter is bound `Dynamic[top]` by design, and the frame's `yield` type names the frame's own block rather
  than a `&blk` local's Proc. Block forwarding through `...` is declined with them: the forwarding call node carries
  no `Prism::BlockNode`, so the callee sees no block.

### Multi-Target Binder (Slice 5 phase 2 sub-phase 2)

`Rigor::Inference::MultiTargetBinder` is the canonical surface for decomposing a tuple- or array-shaped right-hand side type against a Prism multi-target tree. It is a pure module-function module (no state) and MUST satisfy:

- `MultiTargetBinder.bind(target_node, rhs_type, scope: nil)` — `scope` is the scope the destructure is evaluated in, which answers the `[rhs]` wrap's question for a class outside the core list below; every production caller MUST pass it, and without one only the core list wraps. Accepts either a `Prism::MultiWriteNode` (statement-level `a, b = rhs`) or a `Prism::MultiTargetNode` (nested `(a, b)` form). Returns an ordered `Hash{Symbol => Rigor::Type}` whose keys are the named locals bound by the destructuring, in declaration order.
- When `rhs_type` is a `Type::Tuple`, the binder MUST decompose the elements into the front (`lefts`), middle (`rest`), and back (`rights`) regions. Front targets at index `i` MUST bind to `tuple.elements[i]` or `Constant[nil]` when the index is past the tuple's bounds. The rest target (a `Prism::SplatNode` with a `LocalVariableTargetNode` expression) MUST bind to `Type::Tuple[*middle]` (with `middle` empty when the source has no surplus elements). Back targets MUST bind to the elements at the corresponding tail offsets (or `Constant[nil]` when out of bounds).
- When `rhs_type` is an `Array[T]` carrier — `Nominal["Array", [T]]`, or a `Type::Refined` / `Type::Difference` whose base is one, so `first, *rest = xs` after `return if xs.empty?` (`non-empty-array[T]`) decomposes through the base — every front and back target MUST bind to `T` and the rest target to `Nominal["Array", [T]]` (issue [#1093](https://github.com/rigortype/rigor/issues/1093)). A short array pads the fixed slots with `nil` at runtime, so the strict type is `T | nil`; the binder binds `T` for the reason `Array#[]` / `Array#first` read as `T` (§ "That deferred-to answer is nil-free for a lookup that can miss", above) and under the same bet, so every fixed-slot name it binds from such a carrier MUST be reported as optimistic, and a caller that applies the bindings to a scope MUST record each through `Scope#with_optimistic_local` with `OptimisticOrigin::IMPLICITLY_RETURNS_NIL` after the `with_local` (which drops any earlier mark). The rest is an `Array` even when the source is short and MUST NOT be marked; the fixed slots of a `Type::Tuple` MUST NOT be marked. `MultiTargetBinder.bind_marked(target_node, rhs_type, optimistic: false, scope: nil, soften_slots: true)` returns both halves as a `Result` (`types`, `optimistic`, and the instance-variable pair `ivars`, `optimistic_ivars`), and `Result#apply_to(scope)` is the one place that applies them; `bind` returns `bind_marked(...).types`, which never holds an ivar. Both `StatementEvaluator#eval_multi_write` and the `for a, b in …` index binding MUST go through `apply_to`.
- The carrier test (`MultiTargetBinder.array_element_type`) MUST decline raw `Array`, an element that is `Dynamic` or `Top` (`Array[untyped]`), and every `Type::Dynamic` wrapper: `Dynamic[Array[T]]` is gradual, and projecting its static facet would hand the slot a bare `T` that licenses the negative rules ([ADR-5](../adr/5-robustness-principle.md)). A declined carrier, and anything else that neither this rule, the `Type::Tuple` rule, the union rule nor the `[rhs]` wrap below decomposes, binds every slot (fronts, rest, backs) to `Type::Combinator.untyped` (`Dynamic[top]`).
- When `rhs_type` is a `Type::Union`, the binder MUST decompose each member separately against the same target tree (the same front / back / rest counts, and every nested target) and bind each name to the join of its per-member types (issue [#1094](https://github.com/rigortype/rigor/issues/1094)): `e, *f = [1, "s", :t] | [1.0]` binds `e` to `1 | 1.0` and `f` to `["s", :t] | []`. A name that ANY member binds to `Dynamic[top]` — every name, for a member no rule decomposes — MUST bind `Dynamic[top]` for the whole union; the member MUST NOT be dropped from the join, since the precise members would then stand for a value nothing is known about. The join is per name, so a member that decomposes at the top but not at a nested slot costs only that slot's inner names. A member that binds a name to bare `Constant[nil]` — a `nil` element, a slot past a short member, or a `nil` member's `[nil]` wrap — MUST be left out of that name's join when another member binds it to a value, and the name MUST then be reported optimistic. This is the ADR-57 slot softening above, applied across members: which member arrived is correlated with the other slots, so `k, v = hash.find { … }; v.first if k` and `status, value = ok ? [:ok, v] : [:err]; value.upcase if status == :ok` are correct programs, and joining the `nil` in fires `call.possible-nil-receiver` on the guarded read (measured on this repository's own `lib`: `class_name, kind = case … else [nil, nil] end` in `ExpressionTyper#unresolved_call_origin`). The mark is what keeps the softening honest — the slot IS `nil` at runtime for that member, so `if v` / `v.nil?` MUST NOT fold, exactly as for a short `Array[T]`. So `a, b = ints[1..]` (`Array[Integer] | nil`) binds `Integer` to each slot, marked, the answer a short `ints` gets. A name bound to `nil` by every member stays `nil`, and a member's own nil-bearing binding (`Array[Integer | nil]`'s `Integer | nil`) is not softened. A name MUST also be reported optimistic when any member reported it — the rule `Scope#join` applies to the same mark at a control-flow merge — so `a, b = cond ? ["x", "y"] : xs` over `Array[String]` keeps `b.nil?` from folding although the tuple member's slot is present.
- When `rhs_type` provably has no implicit array conversion, the binder MUST decompose it as the one-element tuple `[rhs]` — the value to the first front slot, `nil` to every other fixed slot, `Tuple[]` to the rest — because Ruby's multiple assignment converts through `rb_check_array_type` and wraps a value it cannot convert (issue [#1094](https://github.com/rigortype/rigor/issues/1094)): `a, b = 1` binds `1, nil`, `c, d = { k: 1 }` binds the hash and `nil`, `e, f = nil` binds `nil, nil`. The wrap is exact rather than a bet, so it MUST NOT mark. "Provably" is `MethodDispatcher::RbsDispatch.array_conversion_free?`, read off the class the value's type names (a `Constant`'s value class, a `Nominal`, `Hash` for a `HashShape`, `Integer` for an `IntegerRange`, the base of a `Refined` / `Difference`; any other carrier, `Singleton` and `Intersection` included, declines):
  - The conversion calls `to_ary` when the value defines it and otherwise asks `respond_to_missing?`, dispatching to `method_missing` when that answers true, so a definition of ANY of the three outside `BasicObject` / `Object` / `Kernel` (whose declarations are the defaults) makes the value convertible. `Delegator` / `SimpleDelegator` are the canonical case: core RBS declares both overrides on `Delegator`, and `a, b = SimpleDelegator.new([1, 2])` binds `1, 2` at runtime. A wrong wrap binds `nil` to a slot holding a value, so every doubt MUST decline.
  - `Integer`, `Float`, `Symbol`, `String`, `Hash`, `Range`, `Regexp`, `Proc`, `NilClass`, `TrueClass` and `FalseClass` are conversion-free without an environment. Any other class MUST be one the RBS environment knows, MUST be a class rather than a module, MUST NOT be `Object` or `BasicObject` (the classes `Array` inherits from, whose values are routinely arrays), and its built RBS instance ancestry MUST define none of the three outside the default owners. This is [ADR-43](../adr/43-rbs-complete-ancestor-resolution.md)'s reading of a closed ancestry, stated beside its `ALLOWED_RBS_COMPLETE_ANCESTORS`: the RBS of a class the environment knows is the method set every negative rule already trusts for a `Nominal` of it (`call.undefined-method` fires on it), and a class the environment does not know — a Ruby-source class, whatever it inherits — is an open hierarchy and declines.
  - The project's own source outranks RBS it did not write: a `def` of any of the three that the project adds within [ADR-17](../adr/17-monkey-patch-pre-evaluation.md)'s boundary — in the analysed file (`Scope#discovered_method*`, through its source ancestry) or in a `pre_eval:` file (`Environment#project_patched_methods`) — on the class, any of its RBS ancestors, or `Object` / `Kernel` / `BasicObject` MUST decline, the core list included. A monkey-patch in a file outside that boundary is invisible here as it is to every other rule.
  - Known limitation: `case v when nil` over a slot softened by the union rule above still drops the `nil` arm, because `value_pattern_certainty` does not read the mark. That costs precision in the arm only and fires no diagnostic.
  - `Dynamic`, `Top`, `Bot` and a union's undecomposable members keep `Dynamic[top]`.
- Nested `Prism::MultiTargetNode` targets MUST recurse with the slot's type as the new right-hand side. This lets `a, (b, c) = [1, [2, 3]]` bind `a -> 1`, `b -> 2`, `c -> 3` when both nesting levels are tuple-shaped. A nested target under an optimistic slot MUST inherit the mark for every name it binds, whatever the slot's carrier, because destructuring a `nil` slot binds `nil` to each inner name; `(p, q), r = pairs` over `Array[[Integer, String]]` binds `Integer`, `String`, `[Integer, String]`, all three marked. For the same reason a nested rest under an inherited mark MUST NOT be a `Type::Tuple`: `(p, *q), r = pairs` binds `q` to `Array[String]` (the union of the middle elements, `Array[Dynamic[top]]` for an empty middle), because a short outer array makes `q` the empty array.
- An `InstanceVariableTargetNode`, as a fixed slot, a splat's expression, or inside a nested target, MUST bind by every rule above and MUST be reported in `Result#ivars` / `Result#optimistic_ivars` rather than with the locals (issue [#1110](https://github.com/rigortype/rigor/issues/1110)); `Result#apply_to` binds it with `with_ivar` and records its mark with `with_optimistic_ivar`.
- With `soften_slots: false` the binder MUST NOT apply the ADR-57 softening: a present nil-bearing tuple slot keeps its `nil`, and a union member's bare `nil` stays in its name's join and marks nothing. The `Array[T]` rule, its mark, the rest, the `Dynamic[top]` floor and the `[rhs]` wrap are unchanged. This is for a consumer that drops the marks: the class-ivar seed (§ Slice 7 phase 2 above).
- Other non-local targets (`ClassVariableTargetNode`, `GlobalVariableTargetNode`, `ConstantTargetNode`, `IndexTargetNode`, `CallTargetNode`, `ConstantPathTargetNode`, `ImplicitRestNode`, anonymous splat without an expression, ...) MUST be silently skipped: they have no observable contribution to the scope the StatementEvaluator threads.
- The binder MUST NOT raise on any well-formed Prism input and MUST NOT mutate its arguments.

### Pattern Binding (`case/in`, issue [#1122](https://github.com/rigortype/rigor/issues/1122))

`StatementEvaluator#apply_in_pattern_bindings` is the surface that builds an `in` clause's entry scope. Every name a pattern captures MUST be bound against the **subject's** type, taken from the `case` predicate's own type (`nil` when the `case` carries no predicate, which leaves every name at the `Dynamic[top]` floor). It MUST satisfy:

- A positional pattern (`Prism::ArrayPatternNode`, `Prism::FindPatternNode`) MUST decompose the subject through `MultiTargetBinder.decompose_slots(subject_type, front_count:, back_count:, rest_present:, scope:, soften_slots: true)`, which shares `bind_marked`'s carrier rules — a `Type::Tuple` element-wise with the per-slot softening, an `Array[T]` binding `T` per slot, the `Dynamic[top]` floor for every carrier no rule decomposes — with two statement-only properties removed: the multi-assign `[rhs]` wrap MUST NOT apply (an array pattern matches through the subject's `deconstruct` / `to_ary`, and a subject with neither raises `NoMatchingPatternError` rather than destructuring as `[value]`), and no optimistic mark is reported (the pattern's own match guarantees every fixed slot it named, so the ADR-101 short-array bet has nothing to guard, and the slots carry the statement form's softening without it).
- A named rest MUST bind the decomposition's own rest (`Type::Tuple[*middle]` for a tuple subject, `Nominal["Array", [T]]` for an `Array[T]`), or `Nominal["Array", [Dynamic[top]]]` when the subject did not decompose. A find pattern's requireds MUST each bind the union of every position they could occupy — Ruby matches them at the earliest position the surrounding splats allow but a required that fails there slides right, so `[*, middle, *]` over `[1, "a", 3]` binds `1 | "a" | 3` — and its `*pre` / `*post` splats MUST bind `Array` of the element union (or `Array[T]`), because the surrounding region's position is not statically known.
- A hash pattern MUST read its values through the subject's `deconstruct_keys` view: a `Type::HashShape` answers per key (a key the shape does not carry answers the floor — the pattern cannot match), a `Nominal["Hash", [K, V]]` answers `V` for every key, and a key the AST does not pin (an interpolated or computed key) answers the floor. `**rest` MUST bind `Nominal["Hash", [Nominal["Symbol"], V]]` with the view's own value type (`Hash[Dynamic[top]]` when the view carries none).
- The `deconstruct` / `deconstruct_keys` view MUST come from the subject's own carrier where the engine already projects it precisely: a `Type::DataInstance` (frozen, so the dispatcher's fold is sound — `Tuple` of the member values / `HashShape` of the members), a `Type::StructInstance` (mutable, so it MUST fold only when the subject EXPRESSION provably just materialised it — `StructMaterialization.materialization_call?` asked with the subject node, because the pattern's subject node IS the `.new` call the dispatcher's own gate expects as its receiver), a class whose RBS declares `deconstruct` / `deconstruct_keys`, and a project-defined method (`Scope#user_method_return`, the answer a resolved call site gets). A view that is neither a `Tuple` nor an `Array[T]` / `HashShape` / `Hash[K, V]` — `Struct#deconstruct`'s RBS `Array[untyped]` for a class whose members are not known, an absent method, a `Dynamic` answer — MUST leave the names at the floor.
- A pattern's own class constraint (`in Point[x, y]`, `in Foo{...}`) MUST narrow an OPAQUE subject (`Dynamic` / `Top`, which no `is_a?`-style narrowing can refine) to `Nominal[C]` before the decomposition, because the pattern's `C === subject` test has just established the class. A subject whose class is already known keeps its own, more precise type.
- A capture pattern (`pattern => target`) MUST bind its target to the pattern's own constraint when it names a class (`Integer => i` answers `Nominal[Integer]` — which is what makes a constrained slot bind on an opaque subject), to the literal's own type for a value pattern (`1 => i` answers `1`), and to the subject otherwise (`[a, b] => whole` binds `whole` to the whole subject), AND MUST collect the captured pattern's own bindings.
- A `Type::Union` subject MUST distribute over the pattern: each member walks the same pattern and each name binds the join of its per-member types, a member that binds a name to `Dynamic[top]` (or does not bind it at all) floors that name for the whole union, and a member that PROVABLY cannot match the pattern contributes nothing instead of flooring — `case maybe in [a, b]` over `Tuple[1, "a"] | nil` binds `1` / `"a"`, because a `nil` subject raises `NoMatchingPatternError` rather than reaching the body. "Provably" is the `deconstruct` / `deconstruct_keys` dispatch finding no rule on a class the RBS environment knows, whose method set is closed (`array_conversion_free?`'s rule, [ADR-43](../adr/43-rbs-complete-ancestor-resolution.md)); any carrier the check cannot prove negative about (a `Dynamic`, a project class) answers false and keeps the conservative floor.
- An alternation pattern MUST merge its alternates' bindings by name, unioning a name both contribute.
- A `Prism::CaseMatchNode` with no `else` clause MUST NOT contribute the "nothing matched" arm to the case's result: CRuby raises `NoMatchingPatternError` when no clause matches, so the continuation is reached only through a matched clause, and the shared `else` arm would type the case expression `T | nil` and nil-inject every pattern-bound name (`case [1, "a"] in [i, s] then i end; i + 1` read `i` as `1 | nil` and drew a false `call.possible-nil-receiver`). A `case/when` with no `else` keeps the arm — there a subject matching no clause really does fall through as `nil` — and a `case/in` WITH an `else` keeps it too, because that path can be reached without any pattern matching.
- The one-line forms MUST bind the same way: `Prism::MatchPredicateNode` (`expr in pattern`, a boolean) and `Prism::MatchRequiredNode` (`expr => pattern`, `nil`, raising on a mismatch) bind every captured name into the post-scope WITHOUT nil-injection, because a name read on the truthy side is a name the pattern matched — the shape `return unless config in {timeout: Integer => t}` and `if config in {…} then t + 1` depend on.
- Unrecognised pattern nodes MUST contribute no bindings (fail-soft), and no binding MUST introduce a diagnostic on a correct program.

### Block Parameter Binding (Slice 6 phase C sub-phases 1 and 2)

`Rigor::Inference::BlockParameterBinder` is the canonical surface that builds the entry scope augmentation for a `Prism::BlockNode`. It MUST satisfy:

- `BlockParameterBinder.new(expected_param_types:)` accepts an ordered array of `Rigor::Type` values, one per positional block parameter as supplied by the receiving method's RBS signature. Indices the binder cannot fill from this array (the array is shorter than the parameter list, or the slot is a kind that is not driven by the array) MUST default to `Dynamic[top]`.
- `bind(block_node)` MUST return an ordered `Hash{Symbol => Rigor::Type}` of parameter name to bound type, in declaration order. Anonymous parameters MUST be skipped silently. `Prism::MultiTargetNode` destructuring slots (the `|(a, b), c|` form) MUST be expanded through `Rigor::Inference::MultiTargetBinder` against the slot's expected type (Slice 6 phase C sub-phase 2): a `Type::Tuple` slot decomposes element-wise, an `Array[T]` slot binds `T` per inner name with the optimistic mark, and any other carrier collapses every inner local to `Dynamic[top]`. The inner targets are `Prism::RequiredParameterNode` instances (block-side encoding); `MultiTargetBinder` MUST treat them uniformly with `Prism::LocalVariableTargetNode` for binding purposes.
- Block auto-splat (`Rigor::Inference::BlockAutoSplat`, which the binder delegates the whole rule to): when the receiver yields exactly one value (`expected_param_types.size == 1`) and the parameter list is one CRuby splats — a mandatory positional (`requireds + posts > 0`) or more than one optional, except a bare single required parameter with no optional and no rest (`|a|`, and likewise `|a, &b|` / `|a, k: 1|`); so `|k, *r|`, `|*r, v|`, `|a = 1, b = 2|` and the trailing-comma `|k,|` (Prism's `ImplicitRestNode`) splat while `|*r|` and `|a = 1, *r|` do not — a `Type::Tuple` value MUST be spread across the positionals — leading positionals (required, then optional) from the head and, when a rest is present, trailing positionals from the tail with the rest absorbing the middle (the `a, *r, b = tuple` split, so `|*r, v|` over `[K, V]` binds `v` to `V`), a slot past the tuple defaulting to `Dynamic[top]` — and an `Array[T]` value (the same carrier test as `MultiTargetBinder.array_element_type`) MUST bind `T` to every required and trailing positional, `Dynamic[top]` to every optional positional (a short array hands it its default, not `nil`), and `Nominal["Array", [T]]` to a named rest (issue [#1093](https://github.com/rigortype/rigor/issues/1093): `ints.each_slice(2) { |g, h| }` binds `g`, `h` to `Integer`, not `g` to the whole `Array[Integer]`). A multi-value yield (`each_with_index`) MUST NOT splat. A `Type::Union` value whose EVERY member is one of those two carriers MUST splat member by member and bind each position to the join of the members' types — `Dynamic[top]` where any member leaves the position unfilled or `Dynamic[top]`, and without a member's bare `nil` where another member fills the position with a value (the statement form's cross-member softening, the position then optimistic) — marking a position any member's `Array[T]` arm marked, and binding a named rest to the join of the members' rests only when every member supplies one (`Array[Dynamic[top]]` otherwise); this is the statement form's union rule on this surface (issue [#1094](https://github.com/rigortype/rigor/issues/1094)). A carrier the binder cannot decompose MUST NOT cancel the splat — the parameter list alone decides it, so every member contributes a per-position table and the join above applies unchanged (issue [#1116](https://github.com/rigortype/rigor/issues/1116)). An **opaque array carrier** — a raw `Array`, an `Array[untyped]` / `Array[top]`, a `Refined` / `Difference` over either, or a `Dynamic` over any `Array`, however precise (`Dynamic[Array[Integer]]`, `Dynamic[[Integer, String]]`, `Dynamic[Array[Integer] | nil]`) — MUST contribute `Dynamic[top]` to every position, unmarked, and MUST leave a named rest at the `Array[Dynamic[top]]` default. A `Dynamic` is floored rather than projected because `MultiTargetBinder.array_element_type` declines every `Dynamic` wrapper on purpose — the value is gradual, and projecting its static facet would hand each position a bare `T` that licenses the negative rules (issue [#1093](https://github.com/rigortype/rigor/issues/1093), ADR-5) — but that is a reason to floor the positions, not a reason to leave the whole value on the first parameter, so the facet decides only whether CRuby would splat at all. The floor is what `MultiTargetBinder` already binds for the same undecomposable right-hand side, and binding the whole value to the first parameter instead manufactures a precise wrong type there (`[1, 2].tap { |a, b| a.succ }` saw `a` as the raw `Array` that the `-> self` widening of [#1092](https://github.com/rigortype/rigor/issues/1092) produces, and fired `call.undefined-method`). A bare `nil` member MUST contribute `nil` to every position: `nil` has no `to_ary`, so CRuby passes it as the one argument and `|a, b|` sees `nil, nil`, which is also what the wrap `[nil]` pads to — the two readings agree there, and the union join then softens that `nil` out of any position another member fills, marking it (`[[1, "a"], nil].each { |a, b| }` binds `a` to `Integer` and `b` to `String`, both optimistic). Every other member MUST take the same `Dynamic[top]` floor as the opaque one, because it is the member the union knows least about and joining it as a value puts a nil-bearing element beside a nil-free one: `String#scan`'s `String | Array[String?]` yield would join a capture's `String?` against the whole match's `String`, and `refinements[name.to_sym]` — whose two groups always participate — would fire `call.possible-nil-receiver` (ADR-5, and it does fire on this repository's own `lib`). The splat MUST require at least one `Type::Tuple`, `Array[T]` or opaque-array member; a carrier with none of them (`String`, a lone `nil`, `"x" | "y"`) MUST bind exactly as it did before the rule looked at it — the value at position 0 and `Dynamic[top]` after. So a lone value with no `to_ary` MUST NOT be wrapped as `[value]` the way `a, b = value` is, because auto-splat's one-value premise is the RBS block signature's arity, which the binder cannot check against the actual yield, so a signature that under-declares a multi-value yield would turn the wrap into `nil` on a parameter that receives a value. A nested `|(g, h)|` destructures the one value the signature already placed at its position and MUST go through `MultiTargetBinder` with the entry scope, so it wraps as the statement form does (`[[1, 2]].each { |(a, b), c| }` binds `1, nil, 2`).
- Every name bound from an `Array[T]` slot — an auto-splatted positional, or an inner name of a `|(g, h)|` destructure — MUST be reported in `#optimistic` after `bind`, and `#bind_onto(block_node, scope)` MUST apply the types and then record each such name through `Scope#with_optimistic_local`, exactly as the statement form does. Every `bind` MUST start from the constructor's `expected_param_types:`, so a binder reused across blocks never carries one block's auto-splat into the next. Every block entry-scope builder (`StatementEvaluator#build_block_entry_scope` and the `ExpressionTyper` block-return, captured-exit and per-element passes) MUST build through `bind_onto`, so a block body's `if h` / `h.nil?` keeps the arm a short final slice takes.
- A `*rest` parameter MUST be bound to `Nominal["Array", [Dynamic[top]]]`, except under an `Array[T]` auto-splat as above. A `**kw_rest` parameter MUST be bound to `Nominal["Hash", [Nominal["Symbol"], Dynamic[top]]]`. An explicit `&block` parameter MUST be bound to `Nominal[Proc]`. Keyword parameters (required and optional) MUST be bound to `Dynamic[top]` because Slice 6 phase C sub-phase 1 does not introspect the receiving method's block keyword signature.
- `NumberedParametersNode` (the implicit-`_1` form) MUST yield bindings for `:_1`, `:_2`, ... up to `numbered_node.maximum`, each driven by the same per-position `expected_param_types:` array used for explicit parameters. Slots past the array's length MUST default to `Dynamic[top]`. This is the Slice 6 phase C sub-phase 2 contract; the previous slice's "no-bindings" behaviour is superseded. For auto-splat and the optimistic marks the block MUST be read as the explicit list of `maximum` required positionals — CRuby's own reading (`proc { _2 }.parameters` is `[[:opt, :_1], [:opt, :_2]]` and `lambda { _2 }.arity` is `2`) — so a block referencing `_2` or higher splats a single yielded Tuple or `Array[T]` exactly as `|a, b|` would (`h.each { _1; _2 }` binds key and value; `ints.each_slice(2) { _1 + _2 }` binds `Integer` to both, optimistic), while a block referencing only `_1` reads as `|a|` and MUST NOT splat (issue [#1108](https://github.com/rigortype/rigor/issues/1108)). An `ItParametersNode` (`it`) block MUST bind `:it` to the first expected type and MUST NOT splat.
- The binder MUST NOT raise on any well-formed Prism block node and MUST NOT mutate its input.

`Rigor::Inference::MethodDispatcher.expected_block_param_types(receiver_type:, method_name:, arg_types:, environment:)` is the canonical query that supplies the binder's `expected_param_types:` array. It MUST satisfy:

- It MUST return an ordered `Array<Rigor::Type>` of the positional block parameters (`required_positionals` + `optional_positionals`) declared by the selected RBS overload. Block-only keyword parameters and rest forms MUST be excluded from the returned array; the binder handles those slots independently.
- It MUST select the overload through `OverloadSelector.select` with `block_required: true`, so a block-bearing call (`Array#each { ... }`) does not accidentally bind through the no-block overload (`Array#each() -> Enumerator`).
- It MUST consult the same shape/generic-substitution machinery that `RbsDispatch.try_dispatch` uses, so generic block parameters resolve through the receiver's `type_args` (a `Tuple[Constant[1], Constant[2]]` receiver makes `Array#each`'s `Elem` block parameter resolve to `Constant[1] | Constant[2]`).
- It MUST show a `self`-receiving block parameter (`Object#tap`) the receiver's type arguments under the same `MethodDispatcher::SelfSubstitute` keep-vs-degrade verdict the return path applies ([#1130](https://github.com/rigortype/rigor/issues/1130)), with the receiver's OWN type arguments preserved — the probe reuses the verdict but NOT the return path's value-pin widening, so `ints.tap { |a| }` binds `Array[Integer]` while `[1, 2].tap { |a, b| }` binds the pinned element union `1 | 2` per slot. A verdict decline (an element-changing mutator) MUST keep the raw nominal. The two paths therefore share ONE substitution decision; only the return path widens.
- It MUST return an empty array when the environment, RBS loader, receiver descriptor, method definition, selected overload, or block clause is missing or untyped. The binder MUST treat the empty array as "no information" and default every parameter to `Dynamic[top]`.
- For `Union` receivers it MUST take the per-member answers and return them only when every member yields the structurally equal block parameter list; otherwise it MUST return the empty array. Mixed-arity unions therefore degrade to `Dynamic[top]` rather than producing a non-deterministic block binding.
- It MUST NOT raise on any well-formed input. Defensive `rescue StandardError` around RBS' `DefinitionBuilder` is permitted to keep the probe fail-soft.

`Rigor::Inference::StatementEvaluator` MUST consume both surfaces through a `Prism::CallNode` handler:

- The handler MUST evaluate the call expression as a pure value (delegating to `Scope#type_of` so the existing dispatch chain and shape tier still apply) and MUST return the receiver scope unchanged. Block effects MUST NOT leak into the post-call scope; locals bound exclusively inside a block MUST NOT be observable on the outer side of the call.
- When `node.block` is a `Prism::BlockNode`, the handler MUST build the block's entry scope by augmenting the *receiver's outer scope* with the bindings produced by `BlockParameterBinder.bind`. The block body inherits the outer scope's locals (Ruby's lexical scoping rule), with the block parameters layered on top.
- The handler MUST `sub_eval` the `BlockNode`, threading the block's entry scope through the body so the per-node scope index sees the parameter bindings. The block's `Prism::BlockNode` MUST itself have a handler that delegates to `sub_eval(body, scope)` so the body's statement chain is visited under the augmented scope.
- The handler's exception envelope MUST treat a probe failure as "no expected types"; the binder still runs and defaults every parameter to `Dynamic[top]`.
- Block-aware result typing (Slice 6 phase C sub-phase 2) lives in `Rigor::Inference::ExpressionTyper#call_type_for`: when the call carries a `Prism::BlockNode`, the typer MUST build the same block-entry scope (`outer-scope + BlockParameterBinder.bind`), type the block's body under that scope, and pass the body's value type as `block_type:` into `MethodDispatcher.dispatch`. This is the exact mechanism that makes `[1, 2, 3].map { |n| n.to_s }` resolve to `Array[String]` from any call site (CLI `type-of`, ScopeIndexer, plain `Scope#type_of`) without requiring the StatementEvaluator to be in the loop. The StatementEvaluator's CallNode handler MUST stay aligned: it delegates to the same `Scope#type_of` for the result type and only re-evaluates the block body for the per-node scope index.

`Prism::LambdaNode` MUST have a statement handler of its own, and it MUST answer as the `lambda { … }` spelling of the same object does. `->() { … }` builds exactly what `Kernel#lambda` returns, so the two MUST NOT type differently: the handler MUST build the body's entry scope through the same augmentation a block gets (`outer-scope + BlockParameterBinder.bind`, with `self` entered opaque — a lambda literal carries no receiving method, so every parameter defaults to `Dynamic[top]`), MUST `sub_eval` the body under it so the body's own writes are observable to the statements that follow them INSIDE the body, and MUST return the lambda's expression type with the escaping-closure continuation effects applied to the receiver scope. A lambda literal is a value that outlives the expression, so its captured-local treatment MUST be the escaping one — the narrowing of every outer local the body can rebind is dropped and every content-mutated one is floored — and MUST NOT be [ADR-56](../adr/56-block-captured-local-mutation.md)'s non-escaping write-back. Without the handler the body was typed as an expression alone: reads and literal receivers still reported through the scope index's nearest-ancestor fallback, while a write inside the body joined no scope, so a later read of that local in the body kept its pre-write type and the loss followed the spelling rather than the semantics ([#878](https://github.com/rigortype/rigor/issues/878)).

### Boundaries

Slice 3 phase 2 does NOT thread scope through the *interior* of arbitrary expressions: `foo(x = 1)` and `[1, x = 2]` do not propagate `x` to the post-scope, because the recursive descent stops at expression-level children that the evaluator's catalogue does not cover. This is a deliberate Phase 2 simplification; later slices may expand the catalogue to thread scope through call arguments and array/hash elements. Statement-y constructs at the top level (assignments, ifs, cases, begins, loops, parens) propagate as specified above.

Slice 3 phase 2 narrowly limits the *expressivity* of the parameter binding too: the binder picks the union across overloads at each slot, but does NOT yet refine the binding by argument-call-site type the way `MethodDispatcher::OverloadSelector` does for return types. RBS interface types (`int`, `_ToS`, ...) and aliases still degrade to `Dynamic[top]` through the existing `RbsTypeTranslator` translator, so `def first(n)` redefinitions where the only overload's parameter is `int` MUST observably bind `n` to `Dynamic[top]`. This matches the existing translator's gradual-typing posture.

## Narrowing (Slice 6 phases 1 and 2)

Slice 6 phase 1 adds the first edge-aware refinement surface to the engine. It is exposed through `Rigor::Inference::Narrowing`, a pure module consumed by `Rigor::Inference::StatementEvaluator` to refine the `then` and `else` scopes of `Prism::IfNode`/`Prism::UnlessNode` (and the RHS-entry scope of `Prism::AndNode`/`Prism::OrNode`). Slice 6 phase 2 extends the catalogue with class-membership predicates (`is_a?`, `kind_of?`, `instance_of?`) and trusted equality/inequality predicates while keeping the same consumption contract.

### Type-level narrowing primitives

The module MUST expose the following module functions, each producing a fresh `Rigor::Type` value and never mutating its input:

- `Narrowing.narrow_truthy(type)` — the truthy fragment of `type`. `Constant[v]` collapses to `Bot` when `v` is `nil` or `false` and is preserved otherwise; `Nominal[NilClass]`/`Nominal[FalseClass]` collapse to `Bot` and other `Nominal` carriers are preserved; `Union` recurses element-wise; `Top`, `Dynamic[T]`, `Bot`, `Singleton`, `Tuple`, and `HashShape` flow through unchanged.
- `Narrowing.narrow_falsey(type)` — the falsey fragment of `type`. `Constant[nil]`/`Constant[false]` and `Nominal[NilClass]`/`Nominal[FalseClass]` are preserved; other `Constant`/`Nominal` carriers collapse to `Bot`; `Union` recurses element-wise; `Singleton`/`Tuple`/`HashShape` collapse to `Bot` (their inhabitants are truthy); `Top`/`Dynamic[T]`/`Bot` flow through unchanged because the analyzer cannot prove the falsey side empty.
- `Narrowing.narrow_nil(type)` — the nil fragment of `type`. `Constant[nil]` and `Nominal[NilClass]` are preserved; non-nil `Constant`/`Nominal` carriers collapse to `Bot`; `Union` recurses element-wise; `Top`/`Dynamic[T]` MUST narrow to the canonical `Constant[nil]` so downstream dispatch resolves through `NilClass`; carriers that never inhabit nil (`Singleton`, `Tuple`, `HashShape`) collapse to `Bot`; `Bot` is its own nil fragment.
- `Narrowing.narrow_non_nil(type)` — the non-nil fragment of `type`. Mirror of `narrow_nil`: nil-only carriers collapse to `Bot` and non-nil carriers are preserved; `Top`/`Dynamic[T]`/`Singleton`/`Tuple`/`HashShape` flow through unchanged; `Union` recurses element-wise.
- `Narrowing.narrow_equal(type, literal)` (Slice 6 phase 2 sub-phase 2) — the equality fragment of `type` against a trusted `Type::Constant` literal. String, Symbol, and Integer literals MUST narrow only when `type` is already a finite trusted literal domain (`Constant` or a `Union` of trusted constants). Nil, true, and false are singleton values and MAY be extracted from mixed domains such as `Integer | nil`, but MUST NOT narrow `Dynamic[top]` into the compared literal. Float literals MUST NOT narrow. Untrusted inputs return `type` unchanged.
- `Narrowing.narrow_not_equal(type, literal)` (Slice 6 phase 2 sub-phase 2) — the domain-relative complement of `narrow_equal`. It removes the compared literal from finite trusted literal domains and removes nil/true/false singleton members from mixed domains when present. It MUST NOT create an unbounded difference type for broad domains such as `String` or `Dynamic[top]`.
- `Narrowing.narrow_class(type, class_name, exact: false, environment: Environment.default, scope: nil)` (Slice 6 phase 2 sub-phase 1) — the class-membership fragment of `type`. The `class_name` argument is the qualified name of the asked class as it appears in source (`"Integer"`, `"Foo::Bar"`); `exact: false` models `is_a?`/`kind_of?` (subclass-inclusive) and `exact: true` models `instance_of?` (exact). The carrier rules MUST be:
  - `Constant[v]` — preserved when `v.class` satisfies the predicate (subclass-or-equal of the asked class under `exact: false`; equal under `exact: true`). It MUST collapse to `Bot` only on a KNOWN-disjoint ordering: `Bot` is the assertion "this can never match", and an `:unknown` verdict is the environment declining to decide rather than evidence for it. Under `exact: false` an `:unknown` ordering MUST yield `Dynamic[top]` — the same join `Nominal` takes, and for the same reason (keeping the old bound licenses `call.undefined-method` on the branch the guard just proved). An in-source `include` into a core class never reaches the ordering, so the collapse reported `case 1 when Taggable` unreachable on an arm MRI takes ([#657](https://github.com/rigortype/rigor/issues/657)). `exact: true` MUST still collapse, because `instance_of?` compares the exact class and a module is never an object's class.
  - `Nominal[C]` — when the bound `C` is the same as the asked class (or already its subclass under `exact: false`) it is preserved. When the asked class is a subclass of `C` under `exact: false` the type narrows DOWN to `Nominal[asked]` (e.g., `Nominal[Numeric]` under `is_a?(Integer)` becomes `Nominal[Integer]`). Disjoint hierarchies under `exact: false` and any non-equal class under `exact: true` collapse to `Bot`. When either class name does not resolve through the supplied analyzer `Environment`, the result MUST stay conservative and preserve the input type.
  - `Union` — recurses element-wise, dropping disjoint members.
  - `Tuple[*]`/`HashShape{*}` — projected uniformly through `"Array"`/`"Hash"` against the asked class, under the same `:unknown` decline as `Constant`: a project that reopens `Array` or `Hash` to include a module leaves that ordering undecidable exactly as `Integer` does.
  - `Singleton[C]` — projected uniformly through `"Class"` against the asked class (the inhabitants are class objects), under the same `:unknown` decline. The projection is silent about `extend`, which puts a module in the class object's SINGLETON ancestry and so makes `Widget.is_a?(Comparable)` true where the `Class` projection answers `:disjoint`; a `Bot` under `exact: false` MUST therefore additionally be declined (yielding `Dynamic[top]`) when either singleton-ancestry record for `C` holds a module ordering `:equal`, `:subclass` or `:unknown` against the asked class ([#898](https://github.com/rigortype/rigor/issues/898), [#915](https://github.com/rigortype/rigor/issues/915)). The two records are read as one union: the supplied `scope`'s source-side `extend` record for `C` — its own, or one inherited up the as-written superclass chain — and the environment's declaration-side answer, the MODULE names RBS puts in `C`'s singleton ancestry (`Environment#singleton_extended_modules`), which is how an `extend` declared only in a project's own `sig/` reaches this edge. `:superclass` and `:disjoint` verdicts support nothing and MUST keep the collapse, so `case Widget when Integer` still reports on a `Widget` that extends `Comparable`. The record is evidence FOR a singleton ancestor only: it MUST NOT be read on the negative edge and MUST NOT preserve `Singleton[C]` on the positive one, because the walk that builds it cannot observe a runtime `extend` and so can never establish absence. A nil `scope` (the entries that carry an environment alone) reads as an empty source-side record, and a class the environment does not know reads as an empty declaration-side one.
  - `Narrowing.narrow_not_class` takes the same optional `scope` for signature symmetry and MUST ignore it.
  - `Top`/`Dynamic[T]` — narrow to `Nominal[asked]` so downstream dispatch can resolve through the asked class.
  - `Bot` — preserved.
- `Narrowing.narrow_not_class(type, class_name, exact: false, environment: Environment.default)` (Slice 6 phase 2 sub-phase 1) — the falsey fragment of the same predicate. `Constant`/`Nominal`/`Union`/`Tuple`/`HashShape`/`Singleton` carriers that DO satisfy the predicate collapse to `Bot`; carriers that do NOT satisfy it are preserved unchanged (for `Nominal` this means `Nominal[Numeric]` under `!is_a?(Integer)` stays `Nominal[Numeric]`, since the analyzer cannot prove the disjunction without a richer carrier). `Top`/`Dynamic[T]`/`Bot` flow through unchanged.

These primitives MUST be deterministic and structurally pure: two calls with structurally-equal inputs produce structurally-equal outputs, and calling them never alters the input.

### Predicate-level narrowing

`Narrowing.predicate_scopes(node, scope)` MUST return an `[truthy_scope, falsey_scope]` pair. When `node` is `nil` or its shape is not in the recognised catalogue the pair MUST be `[scope, scope]` so the caller observes "no narrowing" without a special return value. The recognised Slice 6 phase 1 catalogue is:

- `Prism::ParenthesesNode` — recurse into the body when present.
- `Prism::StatementsNode` — analyse the last statement; earlier statements MAY have scope effects, but the StatementEvaluator has already produced the post-predicate scope before calling `Narrowing`, so the analyser does NOT thread additional effects.
- `Prism::LocalVariableReadNode` — when the local is bound in `scope`, narrow truthy → `narrow_truthy(local)` and falsey → `narrow_falsey(local)`. Unbound locals fall through to the no-narrowing fallback.
- `Prism::CallNode` — the catalogue covers six predicate shapes, all rejected silently when the call has a block or its receiver is `nil`:
  - `recv.nil?` (no positional/keyword argument): narrow the receiver-local through `narrow_nil`/`narrow_non_nil`.
  - unary `!recv` (`name == :!`, no positional/keyword argument): analyse `recv` and swap the resulting pair.
  - `recv.is_a?(C)` / `recv.kind_of?(C)` / `recv.instance_of?(C)` (Slice 6 phase 2 sub-phase 1): require the receiver to be a `Prism::LocalVariableReadNode` and the single argument to be a static constant reference (`Prism::ConstantReadNode` or `Prism::ConstantPathNode`). The qualified name MUST be rendered via the parent-walk `Foo::Bar` form. The truthy edge rebinds the local through `narrow_class(local, class_name, exact:, environment: scope.environment)` (`exact: true` only for `instance_of?`); the falsey edge rebinds through `narrow_not_class(local, class_name, exact:, environment: scope.environment)`. Anything else (a local-only argument, a method-call argument, multiple arguments) MUST fall through to the no-narrowing branch.
  - `local == literal` / `literal == local` and the `!=` mirror (Slice 6 phase 2 sub-phase 2): require one side to be a `Prism::LocalVariableReadNode` and the other side to be a static trusted literal (`String`, `Symbol`, `Integer`, `true`, `false`, or `nil`; not `Float`). The truthy edge of `==` rebinds the local through `narrow_equal`; the falsey edge rebinds through `narrow_not_equal`. `!=` swaps those edges. Each recognised equality predicate MUST also attach a `FactStore::Fact`: use the `local_binding` bucket when the local type changed, otherwise the `relational` bucket so broad or dynamic domains retain the relation without unsound positive narrowing.
  - `recv.empty?` / `recv.any?` / `recv.none?` (no block, no argument) on an `Array`-typed receiver-local (ADR-47 §4-4): narrow to `non-empty-array[T]` on the edge that implies at least one element — the **false** edge of `empty?`, the **true** edge of `any?`, the **false** edge of `none?`. The opposite edge is the conservative no-op.
  - `local < lit` / `local <= lit` / `local > lit` / `local >= lit` (and the literal-on-the-left mirror, transposed), `local.between?(lit, lit)`, and the zero-class predicates `positive?` / `negative?` / `zero?` / `nonzero?`, where `lit` is a `Prism::IntegerNode` or `Prism::FloatNode`: the Integer-rooted members of the local narrow on both edges through `narrow_integer_comparison` (an Integer literal only); the Float-rooted members narrow on the **truthy edge only** through `narrow_float_comparison` (`Float[c..]`, `Float[...c]`, `Float[..c]`; ADR-109 WD5) and keep the entry type on the falsy edge, which admits `NaN`. `between?` narrows its truthy edge only for both classes; the zero-class predicates model `Integer` only.
  - `local.nan?` / `local.finite?` (no argument): `nan?` narrows the **falsey** edge of the Float-rooted members to `non-nan-float` and leaves the truthy edge alone; `finite?` narrows the **truthy** edge to `finite-float` and leaves the falsey edge alone. Non-Float members are untouched on both edges.
  - `recv.respond_to?(sym)` with a single statically-known `Symbol`/`String` argument (template-corpora survey): the truthy edge removes `nil` from the receiver-local through `narrow_non_nil` (a truthy `respond_to?` proves the receiver was not `nil`), UNLESS `sym` is a method `NilClass` itself defines (`:to_s`, `:inspect`, `:nil?`, …), in which case it declines. The falsey edge is always the no-op, and narrowing never promotes a non-nil type.
  - `subject =~ pattern` / `pattern =~ subject` (regex match-data globals; the binding contract is [`control-flow-analysis.md`](../type-specification/control-flow-analysis.md#regexp-match-predicate-narrowing)): exactly one operand MUST resolve to a regex pattern — a syntactic `Prism::RegularExpressionNode`, or a `Prism::ConstantReadNode`/`Prism::ConstantPathNode` whose type resolves (through `Reflection.resolve_constant_type`, the shared lexical-constant owner) to a value-pinned `Type::Constant` wrapping a `Regexp`. The analyser MUST decline (both edges = the entry scope) when neither operand resolves to a regex, when both do, when a constant operand types as a `Type::Union`, or when the resolved pattern is extended-mode (`RegularExpressionNode#extended?` / `Regexp#options & Regexp::EXTENDED`) — the light char-scan participation walker miscounts a comment `(` as a capture group, so its indices are untrustworthy. On the truthy edge `$~` binds to `Nominal[MatchData]`, `$&`/`` $` ``/`$'` to `Nominal[String]`, and each *unconditional* numbered group `$N` (per `unconditional_capture_groups`: no zero-permitting quantifier `?`/`*`/`{0,…}` on the group or an ancestor, no enclosing alternation; `(?:…)`/lookaround do not capture) to `Nominal[String]`; on the falsey edge those same globals bind to `Constant[nil]`. `$+` (the last matched group) is gated on the participation set exactly as `$N` is: it binds only when at least one group is unconditional, and otherwise stays unbound (RBS `String?`) on both edges, because a zero-group or all-optional-group pattern leaves `$+` nil even on a successful match. Conditional groups' `$N` are left unbound on both edges. The globals are `global_storage` facts invalidated by any intervening match-capable call (`Scope#forget_match_globals`); a later `Regexp.last_match` fold (`MethodDispatcher::RegexpFolding`) consults the same proven-match bindings rather than re-deriving participation.
- `recv.foo(arg)` with **RBS::Extended predicate annotations** (Slice 7 phase 15): when the receiving method's RBS signature carries `%a{rigor:v1:predicate-if-true <target> is <Class>}` or `%a{rigor:v1:predicate-if-false <target> is <Class>}` annotations on its `RBS::Definition::Method`, the analyser MUST narrow the matching binding on the corresponding edge through `narrow_class`. The parser recognises a strict shape: `<target>` is a Ruby parameter name (matched against the selected overload's `required_positionals` / `optional_positionals`) or `self`; `<Class>` is a single optionally-namespaced class identifier (`String`, `Foo::Bar`, `::Foo`). For parameter targets, narrowing applies only when the matching call argument is a `Prism::LocalVariableReadNode`. For `self` targets, four receiver shapes participate (v0.1.1 Track 1 slice 3): `Prism::LocalVariableReadNode` and `Prism::InstanceVariableReadNode` rebind through `Scope#with_local` / `with_ivar`, and both implicit-self (nil receiver) and `Prism::SelfNode` rebind through `Scope#with_self_type`. The implicit-self path requires `Inference::Narrowing#analyse_call` to allow nil-receiver shapes through to the RBS::Extended path; `resolve_rbs_extended_method` consults `scope.self_type` instead of `scope.type_of(node.receiver)` when the receiver is nil. Other receiver shapes (method chains, expressions) still fall through.
- `recv === local` (Slice 7 phase 4): the case-equality predicate is recognised for three receiver shapes:
  - **Class / Module receiver** (a static `Prism::ConstantReadNode` or `Prism::ConstantPathNode`) — isomorphic to `local.is_a?(receiver)`. The truthy and falsey edges are produced through `class_predicate_scopes`, identical to `is_a?`/`kind_of?`.
  - **Range literal receiver** (`Prism::RangeNode`, optionally wrapped in `Prism::ParenthesesNode`) — narrows `local` on the truthy edge to `Numeric` for integer/float endpoints and to `String` for string endpoints. The falsey edge keeps the entry type because `Range#===` returns false both for non-coercible types and for in-range failures.
  - **Regexp literal receiver** (`Prism::RegularExpressionNode` / `Prism::InterpolatedRegularExpressionNode`) — narrows `local` on the truthy edge to `String`. Same falsey rule as Range.
  Anything else (dynamic receiver, custom `===` method, non-local LHS) MUST fall through to the no-narrowing branch (preserving the entry scope on both edges).
- `Prism::AndNode` — `a && b` narrows the truthy edge with `b`'s truthy scope under `a`'s truthy scope; the falsey edge unions `a`'s falsey scope (b skipped) and `b`'s falsey scope (b ran but returned falsey) via `Scope#join`.
- `Prism::OrNode` — `a || b` narrows the truthy edge with `Scope#join` of `a`'s truthy scope and `b`'s truthy scope (under `a`'s falsey scope); the falsey edge is `b`'s falsey scope under `a`'s falsey scope.
- `Prism::IfNode` / `Prism::UnlessNode` in condition position (issue [#1017](https://github.com/rigortype/rigor/issues/1017)) — `p ? q : r` (an `unless` swaps its arms; an `elsif` is the nested conditional itself; an absent or empty arm is `nil`) MUST NOT have a combinator of its own. Each arm's edges MUST be taken under the predicate's edge, the `&&` step: `q` under `p`'s truthy scope, `r` under `p`'s falsey scope. The truthy edge MUST be the `Scope#join` of the two arms' truthy scopes, and the falsey edge the join of their falsey scopes, the `||` merge. An arm whose type `Narrowing.predicate_certainty` settles under that edge MUST contribute only its live edge, so a literal `false` / `nil` / `true` arm or an absent arm needs no rule of its own and `p ? false : q` narrows as `!p && q`. The settlement MUST decline when `OptimisticOrigin.resolve` marks the arm optimistic (ADR-101, issue #313). The predicate's own certainty MUST NOT drop an edge: the post-predicate scope has already joined the inner conditional's arms, and a carrier every arm narrowed has lost its optimistic mark there. When the conditionals stacked in the guard, counted through parentheses, a body's last statement, `&&` / `||`, `!`, a predicate and an arm, exceed `Narrowing::CONDITIONAL_GUARD_DEPTH` (2), the guard MUST fall through to the no-narrowing branch; each level analyses the predicate and both arms, and the cap keeps that from multiplying without limit.

The analyser MUST NOT raise on unrecognised predicate shapes, MUST NOT thread any tracer (predicate analysis is a pure query that consults already-typed scope information), and MUST NOT mutate the receiver scope.

### StatementEvaluator integration

`Rigor::Inference::StatementEvaluator` MUST consume the predicate analyser as follows:

- `Prism::IfNode` — after evaluating the predicate to obtain `post_pred`, call `Narrowing.predicate_scopes(node.predicate, post_pred)` to derive `(truthy_scope, falsey_scope)`. The `then` branch MUST be evaluated under `truthy_scope`; the `else` branch (or an absent else, which contributes `Constant[nil]` and the predicate's post-scope) MUST be evaluated under `falsey_scope`. The branch types are unioned and the post-scopes are merged through the existing nil-injection rule.
- `Prism::UnlessNode` — same shape as `IfNode`, but the `then` branch (which runs when the predicate is falsey) MUST be evaluated under `falsey_scope` and the `else` branch under `truthy_scope`.
- **Value position (both nodes).** `ExpressionTyper` MUST type an `IfNode` / `UnlessNode` — the ternary `c ? a : b`, a modifier `a unless c`, or any conditional reached through `Scope#type_of` as an argument, a receiver, a literal element, or a write's value — by delegating to `StatementEvaluator#evaluate` and reading the resulting value, never by typing the arms itself. The narrowing application, the branch elision below, and the terminating-arm rule then have exactly one implementation, so the value of a conditional MUST NOT depend on whether it sits in statement or value position. Issue [#1003](https://github.com/rigortype/rigor/issues/1003): a second typer that unioned both arms under the entry scope read `f.finite? ? f : 0.0` as `0.0 | Float` while the statement form bound `0.0 | finite-float`.
- **Version-guard precedence (both nodes).** Before the carrier-certainty verdict, `live_branch_for_if`/`#live_branch_for_unless` MUST consult `Rigor::Inference::VersionGuard.verdict(predicate)` — a pure, scope-free function of the AST that decides a version guard from literals the analyzer can read (normative surface: [control-flow-analysis.md § Version-guard condition folding](../type-specification/control-flow-analysis.md#version-guard-condition-folding)). A `:truthy`/`:falsey` verdict MUST elide the dead arm exactly as a `Constant[true]`/`Constant[false]` predicate does, and MUST take precedence over the [ADR-101](../adr/101-optimistic-carrier-branch-elision.md) optimistic-carrier decline, which guards an RBS-derived judgment and has no bearing on a literal one. A `nil` verdict MUST fall through to `Narrowing.predicate_certainty` unchanged. The expression form (`RUBY_VERSION >= "3.1" ? a : b`) reaches the same method through the value-position rule below, so it and the statement form cannot disagree about which arm survives. Because the guard's own expression type stays `bool`, `flow.always-truthy-condition` never sees it — that is the mechanism, not a separate suppression. Eliding the arm silences no diagnostic on its own (the `CheckRules` walk visits untyped nodes too); `CheckRules::DeadVersionGuardArms` re-asks the same `VersionGuard.verdict` at diagnosis time and drops the diagnostics inside the dead arm, so the two readers cannot disagree about which arm is dead.
- `Prism::AndNode`/`Prism::OrNode` — after evaluating the LHS to obtain `left_scope`, call `Narrowing.predicate_scopes(node.left, left_scope)`. The RHS MUST be evaluated under the LHS's truthy scope for `&&` and the LHS's falsey scope for `||`. The post-scope MUST still be the join-with-nil-injection of `left_scope` and the RHS's post-scope (modelling "RHS sometimes ran") so half-bound names from the RHS continue to nil-inject. The result type MUST be `union(narrow_falsey(left_type), right_type)` for `&&` and `union(narrow_truthy(left_type), right_type)` for `||` (less the constant short-circuit in § Statement-Level Evaluation).
- **Value position (`AndNode` / `OrNode`).** `ExpressionTyper` MUST type an `&&` / `||` reached through `Scope#type_of` — an argument, a receiver, a literal element, or a write's value — by delegating to `StatementEvaluator#evaluate` and reading the value, exactly as the conditional rule above. The RHS narrowing, the constant short-circuit and its issue #313 optimistic-carrier decline then have one implementation, so the value of `x.finite? && x` MUST NOT depend on its position. Issue [#1016](https://github.com/rigortype/rigor/issues/1016): a second typer typed the RHS in the entry scope (`Float | false` where the statement bound `false | finite-float`), carried the short-circuit the statement lacked, and resolved the #313 mark against the entry scope, so `(v = MAP[key]) || key` still discarded the fallback in value position.

### Boundaries

Slice 6 phase 1 + phase 2 binds local-variable narrowing for truthiness, `nil?`, class-membership predicates, and trusted equality/inequality predicates. The following surfaces are deliberately deferred to a follow-up:

- Equality narrowing is intentionally narrow: it does not promote user-defined equality, `eql?`, `===`, Float literals, broad `String`/`Symbol`/`Integer` domains, or `Dynamic[top]` into precise literal domains. Those comparisons may carry relational facts, but value narrowing waits for RBS/plugin-declared effects.
- Closure-captured locals are treated as ordinary locals at narrowing time. Slice 6 phase C sub-phase 3a introduces `Rigor::Inference::ClosureEscapeAnalyzer.classify(receiver_type:, method_name:, environment:)`, a pure query that returns `:non_escaping`, `:escaping`, or `:unknown` for a block-accepting call. Sub-phase 3a is RBS-blind: the analyzer ships a hardcoded catalogue covering core iteration methods (`Array`/`Hash`/`Range`/`Set`/`Enumerator`/`Enumerator::Lazy` Enumerable methods, `Hash#each_pair`/`each_key`/`each_value`/`transform_keys`/`transform_values`, `Range#step`, `Integer#times`/`upto`/`downto`, `Object#tap`/`then`/`yield_self`) as `:non_escaping` and a small set of known retainers (`Module#define_method`, `Class#define_method`, `Thread.new`/`start`/`fork`, `Fiber.new`, `Proc.new`) as `:escaping`. `Tuple` receivers project to `Array`, `HashShape` to `Hash`, and `Constant[v]` projects through the value's class. `Top`, `Dynamic[T]`, `Union`, and any uncatalogued `(class, method)` pair return `:unknown`. The analyzer MUST NOT mutate scope or raise on unrecognised inputs; consumers MUST treat `:unknown` as conservatively as `:escaping` for fact retention. The analyzer is a pure query in sub-phase 3a.
- Slice 6 phase C sub-phase 3b wires `ClosureEscapeAnalyzer` into `StatementEvaluator#eval_call`. When a `Prism::CallNode` carries a `Prism::BlockNode` and the analyzer classifies the call as `:escaping` or `:unknown`, the evaluator MUST attach a `FactStore::Fact` to the post-call scope with `bucket: :dynamic_origin`, `predicate: :closure_escape`, `target: Target.new(kind: :closure, name: <method symbol>)`, `payload: { method_name:, classification: }`, and `stability: :unstable`. A `:non_escaping` classification (or any block-less call) MUST leave the post-call `Scope#fact_store` unchanged. Sub-phase 3c additionally drops the narrowed type of every captured outer local that the block body can rebind, replacing it with `Dynamic[top]` through `Scope#with_local` (which also invalidates the local's `local_binding` facts). The "captured outer local" set is computed by walking `BlockNode#body` for `Prism::LocalVariableWriteNode`s whose name (a) appears in `Scope#locals` of the call-site scope and (b) is NOT introduced by the block itself (block parameters from `BlockParameterBinder.bind`, plus the `;`-prefixed block-locals on `BlockParametersNode#locals`). Locals the block only reads MUST stay narrowed; writes to a name shadowed by a block parameter MUST NOT count. The conservative drop replaces the type with `Dynamic[top]` and applies to the `:escaping` / `:unknown` path only. [ADR-56](../adr/56-block-captured-local-mutation.md) supersedes the drop for the `:non_escaping` path: `StatementEvaluator#eval_call` instead writes the block's captured-local rebindings back through a capped body-fixpoint join (`write_back_block_captures` / `content_writeback_block_captures`, sharing the `Inference::BodyFixpoint` helper with the loop-body fixpoint), so a non-escaping `each` / `times` / `upto` loop that rebinds or content-mutates an outer local keeps the joined post-state rather than the pre-call binding.
- Issue #1095 — `Rigor::Inference::BlockCallTiming::EXACTLY_ONCE_IMMEDIATE` is the built-in block call-timing table for callees that yield immediately, exactly once, before returning: `Kernel#tap`, `Kernel#then`, `Kernel#yield_self`, keyed by declaring owner so a later `RBS::Extended` call-timing effect can absorb it alongside `ClosureEscapeAnalyzer`'s catalogue. `BlockCallTiming.exactly_once_call?(receiver_type:, method_name:, scope:)` answers true only when every receiver member resolves the name to a `Kernel` declaration: a project `def` on the class or a project ancestor (`Scope#discovered_method_through_ancestors?`), a top-level `def`, a project patch on `Object` / `Kernel` / `BasicObject` or on any RBS ancestor of the receiver's class (plus `Module` / `Class` for a singleton receiver), a signature whose `defined_in` is not `Kernel`, a carrier naming no class, or a project class reaching an ancestor no signature describes all answer false; a singleton receiver is answered only through its RBS singleton definition. `ExpressionTyper#call_dispatch_type_for` consults it after the #853 break-arm collection: for a `Prism::BlockNode` block with a body, no arguments, a catalogued call, a syntactic proof that the body cannot complete normally (`BlockCallTiming.never_completes_normally?`: every path ends in a block-level `break` / `return` / `redo` / `retry` or a Kernel-spelled `raise` / `fail` / `throw` / `exit` / `exit!` / `abort` that no project `def`, discovered method on any class or module, or `pre_eval:` patch redefines), AND a block-return pass (`block_return_type_for`) answering exactly `bot` — the pass alone is insufficient because a declared `-> bot` (a project signature, or `Kernel#loop` before #1107) makes it answer `bot` for a body that completes — the call's type is the union of the break arms alone (`bot` when none) instead of the dispatch result unioned with them. The block body is re-typed for that check, so the pre-gates run name-first.

The classification is only as complete as the argument list it reads: every caller feeding an index-write node (`StatementEvaluator#index_write_arg_types` for the straight-line `a[0, 1] += v` / `a[i] ||= v` forms, `#index_write_block_arg_types` for the block-content scan) MUST pass ALL of the node's index arguments ahead of the stored value's type, because a two-index compound write whose second index is dropped classifies as a scalar store and the splice evidence never reaches the join. The block-path seam previously contributed nothing for index-writes at all; it MUST emit the same `[index_type..., stored]` shape, where `stored` is what the write stores through `[]=` — for a compound write the dispatched compound result (`a[i] op= v` stores the `receiver[i] op v` dispatch, `a[i] ||= v` / `a[i] &&= v` store `truthy(read) | v` / `falsey(read) | v`, the read typed as the `[]` dispatch on the receiver refined by a recorded indexed narrowing), never the rvalue the node itself types as; a multi-assign `IndexTargetNode` stays `Dynamic[top]` because the binder does not decompose its per-slot value. The straight-line `eval_index_or_write` / `eval_index_write` handlers MUST type their expression result and joined evidence through the same compound result.
- Issue #643 — a content mutator whose RECEIVER is an element read (`c[0] << 5`, `b[0][0] << 1`, `xs.first << 3`, `ys.dig(0, 0) << 6`) mutates an rvalue temp, so no binding is named and the rules above record nothing. `Inference::ElementReadWidening.widen_element_read` MUST resolve a receiver built solely from `[]` (single argument), argument-less `first` / `last`, and `dig` reads rooted at a `Prism::LocalVariableReadNode` — a block on any hop, an arity that returns a sub-array (`first(2)`, a `[]` slice), or a root that is anything but a local MUST decline — then widen the element the path selects through `MutationWidening.widen_for_mutator` and write the rebuilt container back to that local. - Issue #580 — the straight-line widening is NOT a one-way door. `Inference::MutationWidening.widen_for_mutator` MUST accept a `Nominal[Array, [E]]` / `Nominal[Hash, [K, V]]` pre-state whose element / key / value parameter already carries a `Dynamic` arm, and re-join the mutator's added content into THAT parameter through the same `join_added_elements` / `join_added_pairs` the literal arms use; a parameter with no gradual arm MUST survive the re-join untouched, and a carrier with no gradual parameter at all MUST be declined outright. `MutationWidening.joinable_receiver?` MUST accept such a carrier too, or the seam never types the arguments the arm reads and the door closes itself. A re-join MUST carry the per-slot `receiver[key] ||= default` narrowings keyed on the rebound name across the rebind: the binding still names the same object and only the summary of what it holds grew, so `Scope#with_local`'s ordinary drop (which assumes a DIFFERENT object) does not apply. Method-chain narrowings are not carried. `a = []; a.push(1); a.push("s")` therefore types `Array[Dynamic[top] | Integer | String]`, and `h = {}; h['a'] = {}; h['b'] = "s"; h['c'] = []` carries all three stores' value arms, while `temple = [:multi]; temple << [:static, "x"]` still answers `Array[:multi | Dynamic[top]]` and `Hash.new(0)`'s proved value parameter still reads `Integer` after `h[:x] += 1`.

- Issue #617 — the three remaining ways a block-return answer could still be the pre-state rather than the value, and the straight-line carrier the mutation seam did not respond to.
  - **A compound write as an expression.** `ExpressionTyper` MUST type `v += x` / `@v ||= x` / `$v &&= x` as the value it STORES — `union(narrow_truthy(current), rhs)` for `||=`, `union(narrow_falsey(current), rhs)` for `&&=`, and the operator dispatched on the current binding otherwise — never as `rhs` alone when the target is BOUND. An UNBOUND `||=` / `&&=` target MUST read as `rhs`: nothing wrote the variable on any path the analyzer saw, which is the memoization idiom (`@default ||= new`), and the ADR-5 optimistic reading is what lets `sig-gen` type every memoized singleton; an unbound operator-write target reads `Dynamic[top]`. This is `StatementEvaluator#compound_result_type`'s algebra, and the two MUST agree: the expression form is what a block body typed WITHOUT the evaluator reads, so `total = 0; [1, 2].map { total += 1 }` typed `[1, 1]` and fired a `flow.always-truthy-condition` on `r.last == 1`, which is `2` at runtime. Constant and index targets keep the rvalue reading — `IndexOperatorWriteNode` is typed through `Scope#type_of`'s own indexed path.
  - **The `find` / `detect` / `find_index` / `index` family under the per-element fold.** When the fold has typed every position and the assembler still declines — which happens only because some position's predicate is not a `Constant` — the fold MUST answer a floor rather than fall through to the dispatcher: `union(<receiver elements>, nil)` for `find` / `detect`, `Integer?` for `find_index` / `index`. Falling through hands the answer to `BlockFolding`, which reads ONE block-return type computed from the call's ENTRY scope and short-circuits the whole call to `nil` on a provably-falsey block, so `seen = 0; [1, 2].find do |e| seen += 1; seen == 2 end` answered `nil` where Ruby answers `2`. No other method in the fold's set takes a floor: `map`'s assembler cannot decline, and the filter family's fall-through is merely wider.
  - **Above the per-element threading arity cap.** A position is typed tail-only there, and for a tail that observes a name the body's prefix binds or mutates in place, tail-only is the ENTRY binding the prefix has already falsified. The fold MUST floor every position to `Dynamic[top]` when the tail depends on such a name that the captured-local fixpoint does NOT answer — a mutated block PARAMETER (`([[]] * 9).map do |a| a << 1; a end` answered nine provably-empty `[]`) or a mutated outer local the block never rebinds. Names the fixpoint covers MUST NOT be floored, since its cost is independent of the arity; the dependency predicate MUST be the same one that gates the threading itself, so "would threading have changed this tail" and "is tail-only untrustworthy here" stay one question.
  - **`Constant[String]` under a String mutator.** `MutationWidening.widen_for_mutator` MUST widen a String-valued `Constant` to the bare `String` nominal for every receiver-mutating String method (`<<`, `concat`, `insert`, `prepend`, `replace`, `clear`, `[]=`, `slice!`, `force_encoding`, and the bang forms of the transformers), and `MutationWidening::SHAPE_MUTATORS` MUST be derived from that table alongside the Array and Hash ones so the block-return threading scan and the widening it predicts cannot drift apart. Only the pinned VALUE is at stake, so there is no `values: :keep` half to preserve. Non-mutating siblings (`upcase` vs `upcase!`) MUST stay precise. A `non-empty-string` `Difference` MUST be retracted only by the mutators that can leave the receiver empty (`replace`, `clear`, `slice!`, `[]=`, `sub!`, `gsub!`, `delete!`, `squeeze!`, and the strip / chomp / chop family); an appender or a same-length rewrite leaves the refinement provable. `s = +"ab"; s << "c"` therefore types `s` as `String`, so `s == "ab"` no longer folds always-truthy on correct code — the ADR-56 block-capture path already widened the same binding, and the two seams MUST NOT disagree about one carrier.
- Instance-, class-, and global-variable narrowing was originally out of scope; the `0.1.x` cycle added targeted instance-variable narrowing (e.g. the `return if @ivar.nil?` ivar-guard) on top of the local-variable predicate catalogue. The general predicate-narrowing catalogue still centres on `Prism::LocalVariableReadNode` receivers. (Slice 7 phase 1 binds the **type** of ivar/cvar/global writes through `Scope#with_ivar` / `#with_cvar` / `#with_global`.)

The `0.1.x` cycle also added two `Scope`-carried refinement maps for collection-element and receiver-chain precision (originally tracked under ROADMAP "Future cycles"). They are immutable, thread through derived scopes, and invalidate on receiver rebind like ordinary locals:

- `Scope#indexed_narrowing(receiver_kind, receiver_name, key)` / `#with_indexed_narrowing(...)` — records the element type after a `receiver[key] ||= default` when the receiver is a local/ivar and `key` is a literal Symbol/String/Integer. The record is only made for a SINGLE-index `||=`; a multi-index form (`a[0, 1] ||= v`) addresses a splice region rather than the slot its first index names, so keying the `||` result on that index would claim a non-nil `a[0]` for `a[0, 1] ||= []`, which splices nothing in and leaves `a[0]` nil at runtime (issue #1140).
- `Scope#method_chain_narrowing(receiver_kind, receiver_name, method_name)` / `#with_method_chain_narrowing(...)` — records the narrowed type of a stable single-hop, no-argument method chain (e.g. `x.last` after `if x.last.is_a?(Array)`).

These boundaries MUST NOT silently degrade Slice 6 phase 1 callers: predicates that fall outside the recognised catalogue MUST observe the entry scope on both edges, preserving the Slice 3 phase 2 behaviour.

## Environment Surface

`Rigor::Environment` is the engine's view of the type universe outside the current scope: nominal classes, RBS definitions, plugin-supplied facts (Slice 6+), and any other module-level information. The minimum public surface that Slice 1 binds is:

- `Rigor::Environment#class_registry` — returns a `Rigor::Environment::ClassRegistry` that can resolve a Ruby `Class` or `Module` object to a `Rigor::Type::Nominal`.
- `Rigor::Environment::ClassRegistry#nominal_for(class_object)` — returns the registered `Rigor::Type::Nominal` for a registered class, or raises if the class is not registered.
- `Rigor::Environment::ClassRegistry#registered?(class_object)` — returns `true` or `false` for whether the class is registered.
- `Rigor::Environment::ClassRegistry#nominal_for_name(name)` — returns the registered `Rigor::Type::Nominal` for a Symbol/String class name, or `nil` when the name is unknown.

Slice 4 introduces:

- `Rigor::Environment#rbs_loader` — returns the `Rigor::Environment::RbsLoader` attached to the environment, or `nil` for an "RBS-blind" environment (test fixture).
- `Rigor::Environment::RbsLoader#class_known?(name)` — returns `true` when the RBS environment defines a class or module by that name; nil-safe and string/symbol tolerant.
- `Rigor::Environment#class_ordering(lhs, rhs)` — Slice 6 phase 2 sub-phase 2. Returns `:equal`, `:subclass`, `:superclass`, `:disjoint`, or `:unknown` by consulting the static registry first and then the RBS loader. This is the class-membership narrower's hierarchy oracle; it MUST NOT rely on ad hoc `Object.const_get` at the predicate site.
- `Rigor::Environment::RbsLoader#class_ordering(lhs, rhs)` — returns the same ordering vocabulary by comparing `RBS::Definition#ancestors` for the two names. Unknown or malformed names return `:unknown`.
- `Rigor::Environment::RbsLoader#instance_method(class_name:, method_name:)` — returns the resolved `RBS::Definition::Method` for the given instance method, or `nil` when the class or method is unknown. Inherited methods MUST be visible through this call (the loader uses `RBS::DefinitionBuilder#build_instance` which walks the ancestor chain).
- `Rigor::Environment::RbsLoader#singleton_method(class_name:, method_name:)` — Slice 4 phase 2b. Returns the resolved `RBS::Definition::Method` for the given *class method*, or `nil` when the class or method is unknown. Inherited class methods MUST be visible (e.g. `Class#new`, `Module#name`); the loader uses `RBS::DefinitionBuilder#build_singleton`. The instance and singleton namespaces MUST be disjoint — for example `Module#instance_methods` resolves on the singleton side and is silently absent on the instance side.
- `Rigor::Environment::RbsLoader.new(libraries:, signature_paths:)` — Slice 4 phase 2a. Lets callers extend the loader past RBS core: `libraries` is an array of stdlib library names accepted by `RBS::EnvironmentLoader#add(library:, version:)`; `signature_paths` is an array of `Pathname`-or-`String` directories of additional `.rbs` files. Unknown library names MUST fail-soft (the loader skips them via `RBS::EnvironmentLoader#has_library?`); non-existent signature paths MUST be silently dropped at build time. `RbsLoader#libraries` and `#signature_paths` expose the configured values for round-trip and observability.
- **Shadowed-library elision.** `RBS::EnvironmentLoader` resolves a library name to an installed gem's `sig/` in preference to rbs's own `stdlib/` copy, so two library names in one list can resolve to two declarations of the same module. Where that is known and unconditional, `RbsLoader.build_env_for` MUST drop the shadowed entry before adding libraries, because the alternative is not a diagnostic but silence: `RBS::DefinitionBuilder` raises `DuplicatedMethodDefinitionError`, Rigor fails soft, and every call on the module degrades to `Dynamic[top]`. One pair is elided today — `bigdecimal-math` is dropped when the resolved `bigdecimal` library already ships `big_math.rbs` — and the elision MUST be conditional on that resolution, never unconditional, so a host whose `bigdecimal` carries no `sig/` still gets `BigMath` from rbs's stdlib copy. The elision applies to the effective loader list only; `Environment::DEFAULT_LIBRARIES` and the `merged_libraries` set that feeds coverage reporting and the discovery skip-lists are unaffected.
- **Unsound upstream core shims.** A library's `sig/` can carry shims written for that library's own type-check rather than as a contract about Ruby. Where such a shim reopens a core class with overloads CRuby contradicts, `RbsLoader.build_env_for` MUST unload that file after `RBS::Environment.from_loader`, so core's declaration is the one dispatch reads. One file is unloaded today — `sig/shims/enumerable.rbs` of the `rbs` library (issue #1109), whose `(2) -> Enumerator[[Elem, Elem], void]` overload of `Enumerable#each_slice` typed every blockless `each_slice(2)` as a fixed pair although the last slice can be shorter, and whose block overload returned `void` instead of the receiver. The set is normatively `RbsLoader::UNSOUND_CORE_SHIMS`, resolved against the directory the library actually loaded from; the library's other shims (`bundler.rbs`, `rubygems.rbs`) only add missing declarations and stay. The unload MUST fail soft to the env as built when the shim is relocated or absent or the rbs environment API has an unexpected shape; it MUST work on both supported rbs lines (4.x lists sources through `Environment#each_rbs_source`, 3.x keys `Environment#signatures` by buffer). Because the fail-soft path rescues errors, a broken unload is silent at run time: the guard spec `spec/rigor/environment/rbs_loader_spec.rb` is what catches it, and it MUST stay green on both lines of the CI RBS compatibility matrix.
- **Library-gated bundled supplements.** Rigor's bundled RBS (`data/vendored_gem_sigs/`, `data/core_overlay/`) loads unconditionally into every environment, with one exception: a bundled source that SUPPLEMENTS a stdlib library's own declarations — re-opening a class the library declares with a mixin, a superclass, or an `| ...` overload continuation — MUST be loaded only when that library actually resolved on the loader (`has_library?` passed for the effective, post-elision list). Loading it without the library does not fail the env build; `RBS::DefinitionBuilder` raises later (`NoMixinFoundError` / `NoSuperclassFoundError` / `InvalidOverloadMethodError`), Rigor fails soft, and the whole re-opened class silently degrades to `Dynamic[top]` — real methods and typos alike stop being witnessed. The gated set is normatively `RbsLoader::LIBRARY_SUPPLEMENT_VENDORED_DIRS` + `LIBRARY_SUPPLEMENT_CORE_OVERLAYS`; membership is decided by where the base declaration lives, not by the file's subject (`core_overlay/pathname.rbs` carries an `| ...` continuation yet stays unconditional, because its base is in rbs *core* on every supported rbs release). Every gating library MUST remain in `Environment::DEFAULT_LIBRARIES`, so a production `for_project` environment is unaffected; the gate exists for explicitly-narrowed `RbsLoader.new(libraries:)` environments. Guard spec: `spec/rigor/environment/bundled_rbs_definition_build_spec.rb`.
- `Rigor::Environment#nominal_for_name(name)` — consults the class registry first, then the RBS loader (when present); returns the `Rigor::Type::Nominal` for the first hit, or `nil` when no hit. This is the construction helper for "an *instance* of class `name`".
- `Rigor::Environment#singleton_for_name(name)` — Slice 4 phase 2b. Returns the `Rigor::Type::Singleton` for the constant's class object, or `nil` when no class with `name` is known to either the registry or the RBS loader. This is the canonical entry point for typing `Prism::ConstantReadNode`/`Prism::ConstantPathNode`; `ExpressionTyper` MUST route through it so the result is the class object's type, not the instance type.
- `Rigor::Environment#class_known?(name)` — Slice 4 phase 2b. Convenience predicate that returns `true` when the registry or the RBS loader knows `name`. Useful for callers that need a presence check without materialising a carrier.
- `Rigor::Environment.for_project(root:, libraries:, signature_paths:)` — Slice 4 phase 2a. Factory that builds a project-aware Environment. Auto-detects `<root>/sig` as the default signature path when `signature_paths` is `nil` and the directory exists; uses an empty list otherwise. Callers MAY override the auto-detection by passing an explicit `signature_paths` array (including `[]` to disable). The factory MUST return a fresh Environment instance — it MUST NOT memoize or share with `Environment.default`, because project-aware loaders depend on the caller's working directory and configuration. Slice A stdlib expansion: the factory MUST merge `Environment::DEFAULT_LIBRARIES` ahead of the caller's `libraries:` argument and de-duplicate the result while preserving order. That set is a curated slice of the stdlib a Ruby program is likely to import, plus the analyzer-adjacent gems shipping their own RBS in this bundle (`prism`, `rbs`); it is normatively the constant itself in [`lib/rigor/environment/default_libraries.rb`](../../lib/rigor/environment/default_libraries.rb), which this document deliberately does not restate — the list runs to several dozen names and grows. Unknown libraries MUST stay fail-soft; `RbsLoader#build_env` already filters through `RBS::EnvironmentLoader#has_library?`.

The `0.1.x` cycle added these read-side accessors (all seeded through `Environment.new` / `for_project` keyword arguments and exposed as `attr_reader`s; each defaults to an empty/`nil`-safe value so an environment that omits the corresponding pre-pass behaves as before):

- `Rigor::Environment#project_patched_methods` — the `Rigor::Inference::ProjectPatchedMethods` registry populated from the project's `.rigor.yml` `pre_eval:` list ([ADR-17](../adr/17-monkey-patch-pre-evaluation.md)). Consulted by the dispatcher's project-patched-methods tier; defaults to `ProjectPatchedMethods::EMPTY`. The registry's read surface is `#lookup(class_name:, method_name:, kind:)` and `#empty?`.
- `Rigor::Environment#dependency_source_index` — the opt-in gem-source catalog ([ADR-10](../adr/10-dependency-source-inference.md)), consulted by the dependency-source inference tier.
- `Rigor::Environment#synthetic_method_index` — the ADR-16 / ADR-18 substrate emit table, consulted by the synthetic-method tier.
- `Rigor::Environment#plugin_registry` — the loaded `Rigor::Plugin::Registry` for the run (also the source of plugin-contributed `signature_paths:` merged into the RBS loader, per [ADR-25](../adr/25-plugin-contributed-rbs.md), and `open_receivers:` / `protocol_contracts:` consulted by `CheckRules` and the binder). `open_receivers:` is NOT the only source `CheckRules#unbounded_receiver_surface?` consults for the "unsound to flag" verdict: `Rigor::Analysis::CheckRules::GEM_OVERLAY_OPEN_RECEIVERS` (issue #632, tracked further by #660) is a second, plugin-independent list for a class Rigor's own bundled gem-overlay RBS (`data/gem_overlay/`, ADR-72) declares knowing the declaration is partial — an auto-applied overlay has no plugin manifest for an `open_receivers:` entry to live on. Membership there is gated on `Rigor::Environment::RbsLoader#signature_paths` actually including, this run, a directory carrying one of Rigor's own partial declarations of the gem — either the auto-applied overlay (`RbsLoader.under_gem_overlay_root?`) or the bundled plugin twin's own `sig/` (`RbsLoader.gem_overlay_twin_signatures_loaded?`, the route a project takes when it wires that `sig/` through `signature_paths:` instead of `plugins:`; issue #672). Either arm satisfies the gate, so the exemption is active exactly when the RBS it protects is (ADR-26 WD1), not merely because some project somewhere owns a class of the same name.
- `Rigor::Environment#hkt_registry` — the lightweight-HKT type-function registry ([ADR-20](../adr/20-lightweight-hkt.md)), consulted by the HKT-builtin-return dispatcher tier. It MUST be the merge, **in this order** (last-write-wins): the bundled `Builtins::HktBuiltins.registry` base, then the plugin overlay (`Plugin::Registry#hkt_overlay_registry`, which aggregates every loaded plugin's `hkt_registrations:` / `hkt_definitions:` in registration order, reading each plugin's manifest inside a rescue that re-raises with that plugin named so the failure row can say which plugin to remove), then any user `.rbs` overlay on top. The getter is memoised and MUST return `HktRegistry::EMPTY` when nothing contributes, so a registry-free run skips the merge. The user `.rbs` overlay input includes the implicit-sugar scan (ADR-20 slice 5): a `type` alias in the loaded RBS env is registered as an HKT constructor only when it is parameterized and its body contains a self-application carrying at least one type argument (`type json::value[K] = ... | Array[json::value[K]]`). A non-recursive alias, or a self-reference with no type arguments (malformed for a parameterized alias), contributes nothing. A `%a{rigor:v1:hkt_register / hkt_define}` directive the parser declines contributes nothing either, and MUST be recorded on the run's `RbsExtended::Reporter` (`#record_hkt_error`, position flattened to `(path, line, column)` so the entry crosses the pool drain's Marshal channel and dedups across workers) so the run surfaces it as `dynamic.rbs-extended.hkt-directive-invalid` `:info` — normative in [diagnostic-policy.md](../type-specification/diagnostic-policy.md) § `rbs_extended.*`; the duck-typed `#record` / `#<<` the parser wrote to before [#785](https://github.com/rigortype/rigor/issues/785) is a surface the production reporter does not have, so it MUST NOT be the only arm. The scan MUST NOT be aborted by an alias it cannot model — it degrades the unmodellable subterm to a leaf and moves on — but an exception raised inside the scan is an analyzer defect and MUST propagate, never be swallowed into a silent skip. It propagates to the seam, not into per-file analysis ([#784](https://github.com/rigortype/rigor/issues/784)): the registry is a shared, memoised build first demanded from inside a file's analysis, so `Environment#hkt_registry` MUST rescue the scan, record `[error_class, first_message_line, raw_frame, stage]` on the Environment (`Environment#hkt_scan_failure`, first-write-wins), and return the pre-scan registry (bundled builtins merged with the plugin overlay) so analysis proceeds over a degraded universe. **The plugin-overlay merge MUST be inside the same seam** ([#791](https://github.com/rigortype/rigor/issues/791)) with stage `:overlay`, falling back to the bundled base alone and still running the `type`-alias scan on top of it, so a plugin defect costs the plugin's registrations and not the project's own: it runs plugin-authored code, and because the getter memoises only on success and the run demands it at sites with no rescue above them (below), a raise there escaping the getter aborts the run rather than degrading it. The recorded stage is what the row is worded from — the scan wording would point a user at their `.rbs` for a plugin's defect — and it is the only thing that distinguishes the two, since both surface under the one `rbs.coverage.hkt-scan-failed` id. The recorded failure MUST be drained out of every pool worker and snapshotted by the coordinator AFTER the file loop, and MUST surface exactly once per run as the `:error` `rbs.coverage.hkt-scan-failed` diagnostic (normative in [diagnostic-policy.md](../type-specification/diagnostic-policy.md) § `rbs.coverage.*`); the per-file `internal analyzer error` row MUST NOT be the way a scan failure reaches the user. The seam is demand-driven, so every run MUST demand `Environment#hkt_registry` once on its own behalf — after the file loop on the sequential paths, at drain time in each pool worker, and when the analyze set is empty from an environment already in hand or, when the project has files, one resolved for the purpose; every environment the per-file analysis builds — on every backend, in every pool worker, and on the degraded and fallback paths — MUST be built over the project's whole file list, never the narrowed analyze set, so a subset run carries the same plugin-synthesized RBS the full run does (#793; a project with no files builds nothing — keyed on the project's files, not on `analyze_only`; the `effects.check` envelope loader (`Runner#envelope_rbs_loader`) and the ADR-89 WD2 return-type re-evaluation probe (`Runner#evaluate_return_types_setup`, reached in editor-buffer mode) resolve a SEPARATE environment from the per-file analysis one and so needed their own fix to the same rule, #795). Because a narrowed run then regenerates every run-level row — including the ones positioned at project files (`effect.annotations-unchecked`, `source-rbs-*`) — `IncrementalSession` MUST cache only `Runner#per_file_diagnostics` (the `analyze_files` stream, severity-resolved as the run's stream is and sliced to the analysed files — the cache serves reused files without re-stamping), never the run's full stream, and an empty-closure recheck MUST take from the environment it resolves everything the sequential path takes from its own (the project-signature state, the effect-annotation carrier, the definition-build failures the conformance scan's `conforms-to` demands produced, the HKT-scan outcome — in that order, the sequential path's; the analysis-demanded part of the definition-failure set is what an empty closure cannot regenerate, [#796](https://github.com/rigortype/rigor/issues/796)), and the Ractor backend's in-process re-analysis of a dead worker's files MUST demand and record the HKT outcome of the local environment it builds (that worker never drains) — so the row is a property of the run and not of whether any analysed file happened to call a `Klass.method`, nor of whether the caller supplied an environment (a `--verify-incremental` partition and an incremental recheck's closure routinely do not). Each worker-pool backend's OWN coordinator-side environment MUST take the same project-signature state, and the effect-annotation carrier beside it (the inline stratum of `effect.annotations-unchecked`, normative in [diagnostic-policy.md](../type-specification/diagnostic-policy.md) § `effect.*`), before any worker is dispatched — the fork pool's pre-fork `WorkerSession#environment` (its children copy-on-write inherit whatever it already demanded, so every child's own drain reports it too) and the Ractor pool's cache-prewarm environment (returned rather than discarded, since a Ractor worker builds its own isolated Environment and inherits nothing from the coordinator's) — unconditionally, never gated on whether `RunStats` telemetry (`--no-stats`) is being collected, because no per-worker drain otherwise produces it ([#798](https://github.com/rigortype/rigor/issues/798)). For that carrier to say anything, the Ractor pool's cache-prewarm environment MUST be built with the loaded plugin registry over the project's whole file list, exactly as its workers build theirs — `Environment.for_project` collects plugin-synthesized RBS only when handed both, so an environment built with neither (as it was) has an empty carrier on every project — and MUST withhold the run's reporter accumulators: an environment build records a synthesizer's parse failures and unhonoured annotations on the `source_rbs_synthesis` reporter, every worker builds the same environment with reporters of its own and drains them back through the coordinator's replay, which appends that stream without dedup, so a coordinator-side reporter on the prewarm build would count each entry once more than the drains already do ([#813](https://github.com/rigortype/rigor/pull/813)).

### Plugin-contributed environment inputs (ADR-16 Tier A / ADR-32)

Two plugin-declared manifest surfaces are consumed by the engine outside the dispatcher tiers; their value-object shapes are in [`plugin.md`](plugin.md#rigorpluginmanifest) / [`macro-substrate.md`](macro-substrate.md) and their engine consumption is normative here.

- **`source_rbs_synthesizer:` per-file synthesis (ADR-32).** At env-build time, for every analysed source file × every loaded plugin's synthesizer callable, `Environment.collect_virtual_rbs` (a private class method on the `Environment` singleton, invoked from the `for_project` factory — not an instance method reachable from a built environment) invokes `callable.call(path)`. A returned RBS String is merged into the analysis environment under the virtual name `virtual:<plugin id>:<path>`; a `nil` or empty return contributes nothing; a `[:error, message]` tuple is routed to the synthesis reporter rather than raised (fail-soft). Each `(file, plugin)` call is memoised through `Cache::Store` keyed on the file's content SHA composed with the plugin's `PluginEntry` (id + version + config_hash), so a content or config change invalidates exactly that entry. Distinct from `signature_paths:` (static bundled RBS): the synthesizer derives RBS from project source on each run.

- **`block_as_methods:` self-type narrowing (ADR-16 Tier A).** When `ExpressionTyper` types a call that carries a block, it consults `Inference::MacroBlockSelfType.narrow_self_type_for(scope:, call_node:, receiver_type:)`. The match contract is narrow: the call's receiver type MUST be `Singleton[X]` (a class-level DSL call — implicit-self in a class body, or an explicit `App.get(...)`), `X` MUST equal or inherit from a registered entry's `receiver_constraint` (via `Environment#class_ordering`), and the call's method name MUST be in that entry's `method_names`. On a match the block body is typed with `self_type` narrowed to the **instance** type `Nominal[X]` (matching Sinatra's `generate_method`, which turns the block into an instance method of the user's app class); on no match the helper returns `nil` and the block's `self` is unchanged. The lookup is fail-soft (`class_ordering` failures degrade to "no match"). This is the Tier A floor: bare-identifier method lookups inside the block then resolve through the engine's normal `self_type`-driven path.

The class registry MUST always recognise the following Ruby classes: `Integer`, `Float`, `String`, `Symbol`, `NilClass`, `TrueClass`, `FalseClass`, `Object`, `BasicObject`. Implementations MAY extend this list as long as the listed classes remain present.

The default `Rigor::Environment.default` MUST attach a default `RbsLoader` covering RBS core (no opt-in libraries, no signature paths). Constructing `Rigor::Environment.new` (no kwargs) MUST produce an RBS-blind environment so test fixtures can assert engine behaviour without paying RBS startup cost. The `for_project` factory is the canonical entry point for production CLI commands and any other call site that needs the local `sig/` tree.

## Determinism and Caching

`Scope#type_of` results MUST be deterministic for a given `(scope, node)` pair. Caching MAY be used and MAY be keyed on identity (`equal?`) or on structural equality (`==`); caching MUST NOT change observable behavior, only performance.

Two scopes that compare structurally equal MUST produce structurally equal results from `Scope#type_of` for the same node, even if the scopes are not the same Ruby object.

## Stability and Versioning

The contracts in this document are stable within a major version. The following are additionally stable:

- The `Scope#type_of` shape (input types, return type, purity, optional `tracer:` keyword).
- The `Scope.empty(environment:)` constructor signature.
- The `Scope#join(other)` semantics: same-environment requirement, intersection of bound names, union of types.
- The fail-soft policy and its `Dynamic[top]` return value.
- The Fallback Tracer protocol (`record_fallback`, `events`, `empty?`, `size`, `each`) and the `Rigor::Inference::Fallback` value object.
- The minimum class-registry surface listed above.
- The `Rigor::AST::Node` marker module and the existence of `Rigor::AST::TypeNode` with the round-trip behaviour above.
- The method-dispatch boundary: method-summary tables MUST NOT live on `Rigor::Type` instances.

The following are explicitly out of the stability contract until later slices promote them:

- The exact catalogue of Prism nodes recognised by `ExpressionTyper`.
- The internal layout of `Rigor::Scope` and its caching strategy.
- The fact-store schema (Slice 6+) and the RBS-loader cache shape (Slice 4+).
- The capability and projection surfaces on `Rigor::Type`, which depend on the resolution of ADR-3's open questions.
