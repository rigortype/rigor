- **[engine]** Writing a project `sig/` with `rigor sig-gen` no longer makes `call.undefined-method` report class-method calls that the source leaves open. ([#2477](https://github.com/rigortype/rigor/pull/2477))
  - `C.instance` is no longer reported when `C`, or a superclass the project defines, has `include Singleton`, whatever the class's declaration lists.
  - Other class methods are no longer reported when two conditions hold. First, the project's own signatures declare the class with no methods, attributes, aliases or mixins. Second, the source leaves the class open: the class or a project superclass mixes in a module, defines an `inherited` / `included` / `extended` / `prepended` hook or `method_missing`, or has no body inside `paths:`, or its superclass chain reaches a library or core class (for example `ApplicationRecord` or `StandardError`).
  - A typo on such a class is not reported either. Declaring any member of the class, or defining the whole class inside `paths:`, keeps the check.
