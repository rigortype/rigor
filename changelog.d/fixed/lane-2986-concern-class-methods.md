- **[check]** `call.undefined-method` no longer fires on methods a class macro defines under a computed name when the macro comes from an `ActiveSupport::Concern`'s `class_methods do … end` block or its `ClassMethods` module, called in the includer's class body or in the concern's `included do … end` (or, for a prepending class, `prepended do … end`) block. ([#2989](https://github.com/rigortype/rigor/pull/2989))
  - The concern's `ClassMethods` is found as ActiveSupport finds it: on the concern or a module it includes, else at the top level, never in an enclosing namespace.
  - A concern that ActiveSupport collects as a dependency of the includer is not read when the outer concern has a `ClassMethods` of its own, so a macro from it still reports.
