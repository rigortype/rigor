- **[engine]** A precise `Array[E]` or `Set[E]` now re-grows under a store of another class, so a read after `clear` and a refill no longer reports. ([#2423](https://github.com/rigortype/rigor/pull/2423))
  - `a = ARGV.dup; a.clear; a << 1; a.each { |v| v.fdiv(2) }` and its `ARGV.to_set` twin reported `undefined method 'fdiv' for String`. The carrier now reads `Array[Dynamic[top] | String]` / `Set[Dynamic[top] | String]`: a stored member the element rejects takes the gradual floor, so a later `pop`, `compact!` or `map!` that removes it again does not leave an argument or return a declared type rejects.
  - A literal element is covered too: `s = ints.map { "x" }; s << "y"` no longer folds `s.last == "y"` always-falsey, while a store of the same literal keeps its correct fold.
