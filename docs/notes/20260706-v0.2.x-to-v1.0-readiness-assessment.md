# v0.2.x → v1.0 readiness assessment (evaluation-line consolidation)

Status: consolidation snapshot. 2026-07-06, Rigor v0.2.7 (`[Unreleased]`). Non-normative — the
forward commitment lives in [`docs/ROADMAP.md`](../ROADMAP.md) § "Release strategy" and
[ADR-50](../adr/50-release-engineering-and-stability-strategy.md); this note is a dated "where are
we, what's left" map to steer the evaluation line, produced after the Rails type-coverage arc and
its env/sig-gen robustness follow-ups (PRs #42–51) landed.

## The question

The `0.2.x` line is an **evaluation line**: gather outside feedback and bring the planned feature
set to high completion, pointed at the v1.0.0 hard contract freeze. With the coverage arc's
protection ceiling now established as a **measured hard floor** (the [ADR-67 WD2 spike](20260706-adr67-wd2-in-body-inference-design-spike.md)
closed the last presumed engine lever, and ADR-58 ivar typing is done), what actually remains
between here and v1.0 — and which of it is *actionable now* vs *waiting on demand*?

## What is DONE (the safe-strengthening backlog is largely spent)

The [2026-06-22 compatibility-safe strengthening survey](20260622-rigor-0.2.x-compatibility-safe-strengthening-survey.md)
bucket 1 ("no BC cost, implementable immediately") was the concrete `0.2.x` completion target.
Most of it has shipped:

- **`Dynamic[T]` provenance + tractability labels** — [ADR-75](../adr/75-dynamic-provenance.md) + [ADR-82](../adr/82-dynamic-provenance-wiring.md) (the full WD1–8 arc, this cycle).
- **Structured diagnostic metadata** — `evidence_tier` / `documentation_url` ([ADR-65](../adr/65-diagnostic-evidence-tier-and-doc-url.md)), `receiver_type` / `method_name` ([ADR-61](../adr/61-agent-friendly-diagnostic-statistics.md)).
- **Additive CLI helpers** — `rigor doctor` / `rigor upgrade` skeletons ([ADR-77](../adr/77-doctor-and-upgrade-commands.md)); `describe` ([ADR-73](../adr/73-skill-driven-user-experience.md)).
- **Deterministic builtin/stdlib precision folds** — the carrier sweep is exhausted of clean wins (per CURRENT_WORK (B); remaining named gaps are internal-protocol / format-dependent, not soundly foldable).
- **Effect modeling** `freeze`/`dup`/`clone` shape preservation — [ADR-76](../adr/76-effect-modeling-freeze-dup-shape-preservation.md)/[ADR-78](../adr/78-reflexive-overfold-always-truthy.md).
- **Pre-1.0 internal architecture re-examination** — [all four phases COMPLETE](20260610-lib-rigor-architecture-rereview.md) (mechanical fixes, ADR-52 compiled dispatch, ADR-53 discovery-index + one-walk-per-file, structural decomposition).
- **Env / sig-gen robustness** (this cycle, PRs #50/#51) — a malformed project `.rbs` no longer collapses the whole env; sig-gen no longer emits env-breaking RBS.

## What REMAINS, in three honest tiers

**Tier A — demand-gated (this is the evaluation line's actual job — needs outside signal, not more building):**
- Configurable inference budgets ([ADR-41](../adr/41-inference-budget-design.md) WD3) — deferred because *no corpus project yet shows a budget-shaped cost*; re-run the distribution probe when one does.
- The first `bleeding_edge:` discipline (strict-dynamic preview) — the overlay is empty *by design*; reserve it for a genuine next-major authoring expectation, built on the provenance facts.
- `describe --deep`, finer coverage-tractability hints, additive plugin recognizers — all wait on real usage surfacing the need.
- Self-mutation giant-core tier — mature; the tractable tiers are drained, the giant-file tier is a large low-yield effort held for demand.

**Tier B — large, corpus-swept, separate-branch prep (the real v1.0-completion *investments*, each needing the external FP sweep `make verify` cannot supply):**
- Default-widening receiver-typing / nilability / flow / override diagnostics (survey P0) — the precision exists internally; promoting it into the default profile needs the Rails / ActiveSupport / DSL / monkey-patch / RBS-gap corpus sweep.
- [ADR-46](../adr/46-incremental-dependency-graph.md) incremental analysis — proposed; the per-file successor to the ADR-45 run cache, soundness-gated by a byte-identical cross-check.

**Tier C — bounded and actionable NOW (the one piece of v1.0-quality work that is neither demand-gated nor large):**
- **The doc review battery's mechanical L0 harness** ([`spec/docs/` design](20260610-user-docs-review-battery-design.md)) — a permanent `make docs-check` gate: (1) snippet execution (handbook ` ```ruby ` blocks run through `rigor check`, `assert_type`/`dump_type` claims validated), (2) **CLI/config/rule-id drift** (manual flags/keys/rule-ids cross-referenced against the option parser / config schema / rule registry), (3) **link integrity** (relative links + ADR references resolve). This directly institutionalizes the discipline this whole session kept exercising by hand — stale CLI docs, drifted rule ids, dead links (cf. the `waza` `blob/main` 404s [ADR-81](../adr/81-skill-set-optimization.md) caught) — and it aligns with the ADR-50 v1.0 vocabulary freeze (a drift gate *enforces* docs-match-frozen-vocabulary). Bounded, mechanical, no design controversy.

## Recommendation

The evaluation line is doing its job: the safe engine backlog is spent, so the honest posture is
**stop adding engine precision (the ceiling is a hard floor) and shift to (i) gathering outside
feedback — Tier A's unblock — and (ii) production-quality hardening.** The single highest-value
bounded build available now is **Tier C: the L0 doc-drift harness**. It is the release-quality gate
that keeps the docs honest through the freeze, it is do-able without external signal, and it
converts a recurring manual chore into CI. The Tier B diagnostic-promotion investments are the
larger v1.0 payoff but each is a corpus-sweep project to schedule deliberately, not a quick slice.

Deliberately NOT recommended: another engine-precision feature (the ceiling assessment forbids it),
or forcing a Tier A item without the demand signal it is explicitly waiting for.
