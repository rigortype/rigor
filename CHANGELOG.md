## [0.4.1] - 2026-10-08

v0.4.1 makes repeated runs on a large Rails app faster and trustworthy: an unchanged `--incremental` run is answered from the cache without starting the analyzer, cold runs allocate less, and a batch of cases where `--incremental` served an answer computed before an edit is closed. Method, constant and override lookups now follow Ruby's ancestor order, and where a file cannot prove that order (a gem module without RBS ahead of the definer, a hook-driven or conditional include) Rigor now declines instead of guessing, which removes a family of false positives at the cost of typing fewer calls on Rails apps; see the upgrade note under Changed. It also fixes two internal-error crashes, on a directory named `~something` and on `class self::X` inside a `class_eval` on a non-constant receiver.

### Changed

- **[rigor check]** A call reached through an ancestry the file cannot order now types as `Dynamic` instead of from whichever definer came first, which removes the `call.undefined-method` false positive on a concern includer whose `included do` block includes the real definer ([#1594](https://github.com/rigortype/rigor/issues/1594), [#1629](https://github.com/rigortype/rigor/pull/1629)).
  - Upgrade note: fewer calls are typed on Rails apps, so `rigor coverage` drops (GitLab's controllers by about three quarters, Mastodon by about a fifth), and a true positive that depended on one order is lost; [#1651](https://github.com/rigortype/rigor/issues/1651) tracks recovering it.
  - The unordered cases are a gem module without RBS included ahead of the definer, an include made by an `included do` hook or under a condition, and a conditionally defined method.
  - Where every project definer of the method raises, the call still types `bot`, so a guard such as `fail_with 'no' unless x` keeps narrowing `x`.
- **[rigor check]** A method or visibility that may not hold is now read as uncertain, so `call.wrong-arity` and the override and visibility lints stay silent instead of checking against it ([#1623](https://github.com/rigortype/rigor/pull/1623), [#1631](https://github.com/rigortype/rigor/pull/1631)).
  - A method is possibly absent when it is defined only under a condition, inside a block other than a `Class.new` / `Module.new` / `Struct.new` / `Data.define` body, in a rescuing `begin`, or in a class reopened under a modifier.
  - A visibility is uncertain after a `private`, `protected`, `public` or `module_function` call written under a condition, inside a block or in a `begin`, so a module's `def` after a conditional `module_function` is no longer reported as narrowed by an includer's private override.
- **[rigor check]** An `--incremental` run with nothing changed since the last one is answered from the cache without starting the analyzer, Rails view templates included ([#1552](https://github.com/rigortype/rigor/pull/1552)).
  - On Mastodon this took a null run from 0.94 s to 0.18 s, and from 2.49 s to 0.28 s with rigor-actionpack and the other Rails plugins.
  - The shortcut steps aside under `--workers`, `--explain`, an editor buffer or an `effects:` block.
- **[plugins/rigor-rbs-inline]** An `--incremental` edit that leaves a file's declarations and synthesized RBS unchanged now re-checks only that file, so a comment edit on Mastodon re-checks 1 file in 2 s instead of 311 files in 13 s ([#1545](https://github.com/rigortype/rigor/pull/1545)).
  - In an annotated file, an edit that changes what rbs-inline writes (an annotation, or adding, removing or renaming a `def`) re-analyses the whole project, and `enabled: false` on the plugin entry is honoured here too.
- **[rigor check]** Cold and `--incremental` runs allocate and compute less, with every diagnostic unchanged.
  - A cold run allocates about 5% fewer objects, recovering costs v0.4.0 added to block entry, call-argument typing, template lookups and the declaration walks ([#1508](https://github.com/rigortype/rigor/pull/1508), [#1509](https://github.com/rigortype/rigor/pull/1509)).
  - Building a union renders far fewer member descriptions to order it, which saves about another 4% of a cold run's allocations ([#1511](https://github.com/rigortype/rigor/pull/1511)).
  - Recording dependencies for `--incremental` allocates about three quarters fewer objects, and a cold incremental run on Rigor's own `lib` uses about a fifth less CPU ([#1546](https://github.com/rigortype/rigor/pull/1546)).
  - Each analysed file no longer copies the project-wide method-namespace table, which cost about a quarter of a second of CPU per cold run on Mastodon ([#1551](https://github.com/rigortype/rigor/pull/1551)).
  - The cache is compressed at zlib's fastest level, so snapshot rewrites and the RBS environment store are quicker while the cache grows by about a quarter ([#1530](https://github.com/rigortype/rigor/pull/1530)).
- **[skills]** `rigor-project-init` now recommends acknowledge (baseline) mode for every project and offers strict mode only as an opt-in, because a zero-diagnostic gate on a fresh project meets diagnostics on correct code that only signature or RBS work can clear ([#1539](https://github.com/rigortype/rigor/pull/1539)).

### Fixed

- **[rigor check]** A path argument whose first segment starts with `~`, such as a `~drafts` directory, no longer stops `rigor check`, `rigor unused` or `rigor effects` with `ArgumentError: user drafts doesn't exist` ([#1510](https://github.com/rigortype/rigor/issues/1510), [#1639](https://github.com/rigortype/rigor/pull/1639)).
  - In `.rigor.yml` path settings and Bundler's `BUNDLE_PATH`, `~/` and a bare `~` still expand to your home directory, while `~name` is now read as a literal directory name.
- **[rigor check]** `class self::Opaque` inside a `class_eval` or `class_exec` block on a non-constant receiver no longer stops `rigor check` or `rigor sig-gen` with an `anonymous class has no name` internal error ([#1518](https://github.com/rigortype/rigor/issues/1518), [#1642](https://github.com/rigortype/rigor/pull/1642)).
  - The declaration is declined and its body is no longer read as a class of the same lexical name, so the rest of the file is analysed as usual.
- **[engine]** Method, constant and override lookups now follow Ruby's ancestor order, so a module that an included module includes answers ahead of the superclass ([#1567](https://github.com/rigortype/rigor/issues/1567), [#1578](https://github.com/rigortype/rigor/pull/1578)).
  - `class C < Base; include A` where `A` includes `M` now types `C.new.foo`, `C.foo` through `extend A`, and `C::X` from `M` rather than `Base`.
  - A public `P#foo` prepended over a private `C#foo` no longer reports `def.override-visibility-reduced` or `def.method-visibility-mismatch` ([#1568](https://github.com/rigortype/rigor/issues/1568), [#1571](https://github.com/rigortype/rigor/issues/1571)).
- **[rigor check]** `call.wrong-arity` and the override and visibility lints no longer fire where Ruby's ancestor order for the receiver is not provable.
  - `class C < Base; include M` where `Base` already includes `M` was checked against `M`'s method instead of the `Base` method Ruby runs ([#1570](https://github.com/rigortype/rigor/issues/1570), [#1605](https://github.com/rigortype/rigor/pull/1605)).
  - A class-method call is no longer checked through an `extend` Ruby skips or a class an `inherited` hook may have changed ([#1607](https://github.com/rigortype/rigor/issues/1607), [#1632](https://github.com/rigortype/rigor/pull/1632)).
  - The `def.override-*` and `def.method-visibility-mismatch` lints no longer read a parent or prepended definer Ruby may not reach, and a receiverless `def` inside `class << self` is compared with the singleton signature ([#1606](https://github.com/rigortype/rigor/pull/1606)).
- **[engine]** `extend X` and `class << self; include X; end` written inside a block that provably runs in a class body, such as `3.times { extend X }`, are now recorded, so a class-method call through them no longer reports a false `call.undefined-method` ([#1592](https://github.com/rigortype/rigor/issues/1592), [#1593](https://github.com/rigortype/rigor/pull/1593)).
- **[inference]** Class guards (`is_a?`, `kind_of?`, `instance_of?`, `C === @x`, `case @x when C`, `case @x in C`) now narrow an instance-variable receiver, so `@io.is_a?(StringIO) ? @io.string : nil` no longer reports `call.undefined-method` ([#1446](https://github.com/rigortype/rigor/issues/1446), [#1499](https://github.com/rigortype/rigor/pull/1499)).
- **[inference]** A `!~` guard now narrows the regex match globals as the negation of `=~`, so `return if line !~ /\A(\w+)=/` followed by a call on a copy of `$1` no longer reports `call.possible-nil-receiver` ([#1379](https://github.com/rigortype/rigor/issues/1379), [#1496](https://github.com/rigortype/rigor/pull/1496)).
- **[rigor check]** A path argument that names a configured path, as `rigor check lib` does with `lib` under `paths:`, no longer hides the project's constants from each other, so a call such as `LIMIT.upcase` on an Integer constant is reported again ([#1556](https://github.com/rigortype/rigor/issues/1556), [#1582](https://github.com/rigortype/rigor/pull/1582)).
- **[rigor check]** `--incremental` no longer serves an answer computed before an edit to an input it used to miss.
  - A `pre_eval:` file outside the analysed paths, or an auto-detected `sig/*.rbs` ([#1554](https://github.com/rigortype/rigor/issues/1554), [#1585](https://github.com/rigortype/rigor/issues/1585), [#1618](https://github.com/rigortype/rigor/pull/1618)).
  - A lockfile configured with `bundler.lockfile:` or `rbs_collection.lockfile:` at a non-default path, and the `Gemfile.lock` or `ext/**/extconf.rb` that rigor-ffi reads to choose its target ([#1532](https://github.com/rigortype/rigor/issues/1532), [#1644](https://github.com/rigortype/rigor/pull/1644)).
  - An inline RBS annotation, whose callers kept the old type when the annotated class had a subclass elsewhere, and whose annotated `attr_reader` readers were not re-checked at all ([#1536](https://github.com/rigortype/rigor/issues/1536), [#1545](https://github.com/rigortype/rigor/pull/1545)).
  - A class's own `deconstruct` or `deconstruct_keys` defined in another file, which also no longer crashes when served from a seed bundle ([#1615](https://github.com/rigortype/rigor/issues/1615), [#1620](https://github.com/rigortype/rigor/pull/1620)).
- **[rigor check]** `rigor check --incremental --no-cache` is now a cold full analysis that neither reads nor writes the incremental snapshot, instead of replaying the previous run's diagnostics ([#1525](https://github.com/rigortype/rigor/issues/1525), [#1643](https://github.com/rigortype/rigor/pull/1643)).
- **[rigor check]** `rigor check --incremental` now stays warm on projects using rigor-sidekiq, rigor-rails-i18n or rigor-rails-routes, where every run used to report "plugin fact surface changed" and analyse in full ([#1574](https://github.com/rigortype/rigor/issues/1574), [#1577](https://github.com/rigortype/rigor/pull/1577)).
  - On Mastodon an edit took about 21 s instead of about 2 s.
- **[rigor check]** A warm `--incremental` run now lists its diagnostics in the order a full run of the same tree does, so its text and JSON output no longer reshuffle ([#1524](https://github.com/rigortype/rigor/issues/1524), [#1535](https://github.com/rigortype/rigor/pull/1535)).
- **[plugins]** A plugin producer served from its own cache now carries its inputs into the run-result cache, so a column added to `db/schema.rb` after a model-only edit no longer stays `plugin.activerecord.unknown-column` until `--no-cache` ([#1558](https://github.com/rigortype/rigor/issues/1558), [#1564](https://github.com/rigortype/rigor/pull/1564)).
- **[rigor coverage]** `rigor coverage --protection` no longer loses a class's `extend` edges when it seeds per-file scopes, and a seeded mutant is no longer judged with the original file's deferred-range offsets ([#1603](https://github.com/rigortype/rigor/issues/1603), [#1616](https://github.com/rigortype/rigor/pull/1616), [#1548](https://github.com/rigortype/rigor/issues/1548), [#1598](https://github.com/rigortype/rigor/pull/1598)).
- **[docs]** The agent install guide (`docs/install.md`) now looks up the latest release on RubyGems and installs it explicitly, so an agent no longer carries on with a stale Rigor already on PATH ([#1534](https://github.com/rigortype/rigor/pull/1534)).
  - When mise's `minimum_release_age` quarantine holds a release back, the agent asks the user before bypassing it.

## [0.4.0] - 2026-09-27

v0.4.0 opens the 0.4 line by bringing Rails views into the analysis: rigor-actionpack compiles ERB templates into units that `rigor effects`, `rigor type-of` and a controller's effect summary can see, `rigor check` reports `flow.*` inside views, and new or extended plugins type the Grape, Sorbet, GraphQL and Active Model Serializers DSLs. Ruby's special variables (`$~`, `$1`, `$_`, `$!`, `$?`) are now typed by the scoping rules Ruby follows, and two new rules report global writes Ruby always refuses. `rigor sig-gen` now copies inline-declared methods into `sig/` by default and gains a `--check` CI gate, and a `sig/` declaration that contradicts its inline annotation is now an error, so read the upgrade notes under Changed. The rest is a large false-positive batch, most of it in block, loop and in-place mutation inference that used to read a counter or collection at its first-iteration value.

### Added

- **[plugin contract]** A plugin can claim non-Ruby project files with `template_globs:` and compile each into a template unit, which Rigor parses, types and reports at the template's own lines and lists in `rigor effects` as `view:<name>` ([#1037](https://github.com/rigortype/rigor/pull/1037)).
- **[plugins/rigor-actionpack]** ERB views under `app/views/` are now analysed as template units, so a view's effects appear in `rigor effects` as `view:users/show.html` and `effects.envelopes:` can hold views to a budget ([#1050](https://github.com/rigortype/rigor/pull/1050)).
  - Erubi compiles the views when your bundle resolves it, stdlib `ERB` otherwise, and `flow.*` checks report inside templates by default while `call.*` checks stay off until you set `view_type_checks: true`.
  - A partial's locals are bound from the sites that render it, which is what lets `flow.*` report in views, and layouts compile into effect units too ([#1066](https://github.com/rigortype/rigor/pull/1066)).
  - A language-server session recompiles only the templates that changed on disk, so a per-buffer publish on Redmine runs 4 ERB compiles instead of 506 ([#1053](https://github.com/rigortype/rigor/pull/1053)).
- **[plugins/rigor-actionpack]** A controller action's effect summary now includes the templates it renders, explicitly or through the implicit render, and each template reaches the partials it renders ([#1057](https://github.com/rigortype/rigor/pull/1057)).
  - Each `format.<fmt>` arm of a `respond_to` block reaches its own conventional template, while `format.any` / `format.all` name none ([#1071](https://github.com/rigortype/rigor/issues/1071), [#1160](https://github.com/rigortype/rigor/pull/1160)).
  - A `.js.erb` template that renders an HTML-only partial follows Action View's `.js` to `.html` lookup, and the lookup stops where a Haml or Builder template is what Rails runs ([#1070](https://github.com/rigortype/rigor/pull/1070)).
- **[rigor type-of]** `rigor type-of` on an ERB view types the compiled code under the view's `self`, locals and instance variables at the template's own line and column, and declines positions in markup instead of failing with a parse error ([#1069](https://github.com/rigortype/rigor/pull/1069)).
- **[plugins/rigor-grape]** The new bundled `rigor-grape` plugin types the `Grape::API` endpoint DSL and `Grape::Entity` `expose` declarations, where every call previously read as `Dynamic[top]` ([#1099](https://github.com/rigortype/rigor/issues/1099), [#1111](https://github.com/rigortype/rigor/pull/1111)).
  - A `desc 'x' do … end` body binds `self` to Grape's route-attribute context, so an undeclared name inside one reports `call.undefined-method` as Grape raises `NoMethodError` ([#1117](https://github.com/rigortype/rigor/issues/1117), [#1118](https://github.com/rigortype/rigor/pull/1118)).
- **[plugins/rigor-active-model-serializers]** The new `rigor-active-model-serializers` plugin types the `object` reader inside an `ActiveModel::Serializer` subclass as the model it serializes, and leaves it alone unless the model answers every name the serializer reads ([#1044](https://github.com/rigortype/rigor/pull/1044)).
  - rigor-activerecord now records `delegate`, a concern's associations, Paperclip and Active Storage attachments and enum predicates in the model index it publishes, so the serializer plugin no longer declines a model that answers them ([#1052](https://github.com/rigortype/rigor/pull/1052)).
- **[plugins/rigor-sorbet]** The plugin types Sorbet's own annotation DSL through a bundled `sorbet-runtime` signature, so `sig { params(…).returns(…) }`, `T::Array[…]`, the `T.*` type functions and the `T::ImmutableStruct` / `T::Enum` class macros resolve instead of reading `Dynamic[top]` ([#1097](https://github.com/rigortype/rigor/issues/1097), [#1135](https://github.com/rigortype/rigor/pull/1135)).
  - A plain `T::Struct` subclass still needs its own `extend T::Sig`, and `T`'s surface is partial on purpose, so an unmodelled `T.*` call reads opaque rather than undefined.
- **[plugins/rigor-graphql]** The plugin bundles graphql-ruby's class-level DSL signature, so `field`, `argument`, `value`, `implements` and the schema registration macros inside a `GraphQL::Schema::*` subclass resolve instead of reading `Dynamic[top]` ([#1106](https://github.com/rigortype/rigor/pull/1106)).
- **[plugin contract]** Manifests gain `rbs_complete_ancestors:` and `rbs_complete_extends:`, which let a Ruby subclass, or a class that `extend`s a module, resolve inherited calls against a plugin's bundled signature ([#1106](https://github.com/rigortype/rigor/pull/1106), [#1135](https://github.com/rigortype/rigor/pull/1135)).
  - `Macro::BlockAsMethod`'s `self_type:` also accepts a String naming the `instance_eval` target, for a DSL whose block runs on a different object than the receiver ([#1111](https://github.com/rigortype/rigor/pull/1111)).
- **[plugins/rigor-activerecord]** A `scope` declared inside a concern's `included do … end` block is folded into every model that includes the concern, so `Account.without_suspended` types as `ActiveRecord::Relation[Account]` ([#1034](https://github.com/rigortype/rigor/pull/1034)).
- **[rigor check]** Two new rules report a write to a special global that Ruby rejects every time it runs ([#1448](https://github.com/rigortype/rigor/pull/1448)).
  - `global.write-type-mismatch` reports a literal the setter refuses with `TypeError`, such as `$/ = 1`, `$~ = "x"` or `$stdout = 1`, and judges only values written as literals.
  - `global.readonly-write` reports a write to a read-only special such as `$!`, `$$`, `$?` or `$LOAD_PATH`, which raises `NameError`.
  - Both are errors under the default `balanced` profile, so such a write now fails `rigor check`; `global.write-type-mismatch` is a warning under `lenient`.
- **[rigor check]** `call.wrong-arity` now checks calls to a method your project defines in Ruby, against the `def`'s own parameter list when nothing declares it and against its declaration when `sig/` or an inline annotation types it ([#999](https://github.com/rigortype/rigor/pull/999), [#1010](https://github.com/rigortype/rigor/pull/1010)).
  - It stays silent wherever metaprogramming, reopened classes, mixins, subclasses or plugins could make a different definition run.
- **[rigor sig-gen]** `rigor sig-gen --check` exits 1 when `--write` with the same options would change or refuse something in `sig/`, for use as a CI freshness gate ([#1422](https://github.com/rigortype/rigor/pull/1422)).
- **[rigor sig-gen]** With the `effects:` opt-in on, `rigor sig-gen` writes `%a{pure}` (and, under the new `--effect-envelopes`, `%a{rigor:v1:effect …}`) above every method whose effect closure it fully read and found empty ([#1036](https://github.com/rigortype/rigor/pull/1036)).
  - It withholds the annotation from a method that is clean only because `effects.tolerated:` says so or that reaches a callee nothing describes, and leaves an already-annotated declaration untouched.
- **[rigor sig-gen]** A proposed type that matches the expansion of a type alias your `sig/` declares is written as the alias name, such as `-> ::Rigor::Type::t` instead of its 22 members ([#1032](https://github.com/rigortype/rigor/pull/1032)).
- **[config]** The new `test_paths:` key declares where the project's tests live, and `rigor sig-gen --params=observed` observes those roots, so a Minitest project's `test/` types parameters without `--observe` ([#1395](https://github.com/rigortype/rigor/pull/1395)).
  - Unset, it auto-detects `spec/` and `test/`, and `rigor init` writes the roots it finds.
- **[inference]** `Integer#to_s` types as `decimal-int-string`, and `Float#to_s` as `numeric-string` when the receiver is proven finite and `non-empty-string` otherwise, instead of the bare `String` both used to widen to ([#1001](https://github.com/rigortype/rigor/pull/1001)).
- **[docs]** A new type-specification topic, [Global variables](docs/type-specification/global-variables.md), states where a global variable's type comes from, where each special variable lives, and which evidence changes a type Rigor reads by idiom ([#1478](https://github.com/rigortype/rigor/pull/1478)).
- **[docs]** The [DeepWiki](https://deepwiki.com/rigortype/rigor) pages are generated from a maintained outline, so they follow the binding specifications and the project's own terminology instead of guessing at them ([#1460](https://github.com/rigortype/rigor/pull/1460)).

### Changed

- **[rigor sig-gen]** **BREAKING:** `rigor sig-gen` now writes a method declared inline by `# @rbs` / `#:` into `sig/` by default, and `--write` refuses with exit 1 when a `sig/` declaration disagrees with the inline one until the two agree or `--overwrite` replaces it ([#1422](https://github.com/rigortype/rigor/pull/1422)).
  - A project whose Steep reads the same annotations (`inline: true` beside `signature "sig"`) must set `sig_gen: { inline_declared: skip }` in `.rigor.yml`, or Steep reports each copied method as `DuplicatedMethodDefinition`.
  - Combining two of `--print`, `--diff`, `--write` and `--check` is now a usage error (exit 64) instead of the last flag silently winning.
- **[plugins/rigor-rbs-inline]** A method declared both in `sig/` and inline is now compared, so the more precise declaration binds and a proven contradiction reports the new `rbs.contradicting-signature` error at the `sig/` line ([#1428](https://github.com/rigortype/rigor/pull/1428)).
  - A refinement pair such as `Symbol` in `sig/` against `:asc | :desc` inline binds the inline side without a diagnostic, and only absolutely written core or stdlib classes prove two types disjoint.
  - **Upgrade note:** a contradicting pair that used to be an info now fails `rigor check`, and a more precise inline parameter type can surface a new call-site error the old `sig/` type accepted.
- **[plugins]** A plugin's project-wide disclosure, such as a `load-error` or rigor-activerecord's missing-schema notice, is now reported once per run at `.rigor.yml:1:1` instead of once per analysed file or per `--workers` worker ([#1054](https://github.com/rigortype/rigor/pull/1054), [#1062](https://github.com/rigortype/rigor/pull/1062)).
  - **Upgrade note:** a baseline row recorded at the old file position no longer matches and surfaces as new, and warning-level rows such as the plugins' `load-error` rows fail `--fail-on=warning`, so run `rigor baseline regenerate`.
  - rigor-rails-i18n's view-template diagnostics keep their own file and are reported once under `--workers N`, which needs no baseline change, through the new `Plugin::Base#emit_once` channel ([#1067](https://github.com/rigortype/rigor/pull/1067)).
- **[engine]** `$_` is frame-local, and a `gets` condition Rigor can prove is Ruby's own narrows it to `String` inside the loop and `nil` after it, for `while $stdin.gets` and implicit-self `while gets` alike ([#1405](https://github.com/rigortype/rigor/pull/1405), [#1449](https://github.com/rigortype/rigor/pull/1449)).
  - A `while` body now reads its condition's narrowing even when it reassigns no local, so `while (line = STDIN.gets); line.chomp; end` no longer reports a false `call.possible-nil-receiver`.
  - The implicit-self narrowing is declined where the file shows `self`'s reader may be written in Ruby, and an implicit-self `readline` does not narrow yet ([#1458](https://github.com/rigortype/rigor/issues/1458)).
- **[engine]** `$!` and `$@` read as the rescued exception and its backtrace inside a `rescue` clause, and `$?` and `Process.last_status` read as `Process::Status` after a backtick command, `system` or a blocking `Process.wait` ([#1425](https://github.com/rigortype/rigor/pull/1425), [#1438](https://github.com/rigortype/rigor/pull/1438)).
  - `Process.last_status` no longer reports `call.undefined-method`.
  - `$?` stays possibly `nil` when the file also runs a `WNOHANG` wait or `waitall`, or a rescue may have interrupted the subprocess.
- **[inference]** A Ruby class that subclasses a core or stdlib class resolves its inherited calls against that class's signatures, so `class MyError < StandardError` reads `message` as `String` instead of leaving it untyped ([#1131](https://github.com/rigortype/rigor/pull/1131)).
- **[inference]** `tap`, `then` and `yield_self` run their block exactly once, so a block that never completes normally no longer leaves the receiver in the call's type (`[1, 2].tap { raise "x" }` is `bot`) ([#1105](https://github.com/rigortype/rigor/pull/1105)).

- **[plugins/rigor-rbs-inline]** A `# @rbs name: T` annotation whose `T` does not parse, and an `@rbs`-prefixed tag the gem does not recognise, are reported as `source-rbs-annotation-not-honoured` instead of silently ignored ([#1023](https://github.com/rigortype/rigor/pull/1023)).
- **[rigor sig-gen]** A method whose declared return is `untyped`, or is spelled through a project type alias, now gets the right `tighter-return` proposal instead of disappearing or being proposed spuriously ([#1000](https://github.com/rigortype/rigor/pull/1000)).
- **[rigor sig-gen]** A `tighter-return` proposal keeps the declared parameters, annotations and visibility and changes only the return, so `--write --overwrite` no longer rewrites `def m: (Integer x) -> Numeric` to `(untyped) -> Integer` ([#1436](https://github.com/rigortype/rigor/issues/1436), [#1483](https://github.com/rigortype/rigor/pull/1483)).
  - A declared `initialize` is no longer listed as `[new]`, and a member with several overloads or declared through `alias` gets no proposal instead of one that merges or misreads it.
- **[effects]** A `Const.new` call resolves to that class's `#initialize`, so a constructor's labels reach its callers and no longer withhold `%a{pure}` from them ([#1042](https://github.com/rigortype/rigor/pull/1042)).
- **[effects]** A method, `include` or `prepend` is attributed to the side of its class that Ruby defines it on, so a `define_method` inside `class << self` is a class method and an `include` there no longer reaches instance callers ([#1316](https://github.com/rigortype/rigor/pull/1316), [#1320](https://github.com/rigortype/rigor/pull/1320)).
  - A method defined inside `Class.new`, `Struct.new`, `other.class_eval` or on a single object is no longer filed under the enclosing class, and a committed effect snapshot may need regenerating.
  - A class whose `new` comes from a singleton-side mixin now reads as having the empty constructor, so `sig-gen` can write `%a{pure}` on a caller whose `new` does work ([#1322](https://github.com/rigortype/rigor/issues/1322)).
- **[effects]** `Hash#compare_by_identity`, `#rehash`, `#shift`, `String#force_encoding` and the other in-place String mutators count as receiver mutations, while a mutation of a fresh allocation or copy reads as `mutate.local` ([#1253](https://github.com/rigortype/rigor/pull/1253), [#1270](https://github.com/rigortype/rigor/pull/1270), [#1292](https://github.com/rigortype/rigor/pull/1292)).
  - `new` counts as a fresh allocation only on a constant, a `class` call or `self` in a class method, so a write to `user.posts.new` reads as an `unknown-ownership` taint ([#1306](https://github.com/rigortype/rigor/pull/1306)).
  - A `%a{pure}` method that makes such a call now reports `effect.envelope-exceeded`, and a committed effect snapshot may need regenerating.
- **[plugins/rigor-activesupport-core-ext]** The bundled ActiveSupport overlay declares about thirty more core extensions, such as `Object#presence_in`, `#deep_dup`, `Enumerable#many?`, `Hash#with_defaults` and `Range#overlaps?`, so calls to them no longer report `call.undefined-method` ([#1326](https://github.com/rigortype/rigor/pull/1326), [#1330](https://github.com/rigortype/rigor/pull/1330), [#1334](https://github.com/rigortype/rigor/pull/1334)).
  - If your project's `sig/` declared any of these to silence the old false positive, delete that declaration, because the duplicate stops Rigor from building the class.
  - `Hash#reverse_merge` and `#with_defaults` no longer claim the result holds only the receiver's keys, and `Hash#deep_dup` is no longer marked `%a{pure}`.
- **[plugins/rigor-activerecord]** `find` is typed by the form it is called in, so a block form reads `Post | nil`, two or more ids read `Array[Post]`, and a model's own `self.find` reads as that method ([#1321](https://github.com/rigortype/rigor/pull/1321), [#1327](https://github.com/rigortype/rigor/pull/1327), [#1328](https://github.com/rigortype/rigor/pull/1328)).
  - A relation's block-form `find`, which used to read as the model, now reads `Post | nil`, so using it without a nil check reports `call.possible-nil-receiver`.
  - rigor-actionpack no longer seeds a view's `@ivar` as a single model when the controller assigned it from a call that may return several records ([#1323](https://github.com/rigortype/rigor/pull/1323)).
- **[plugins/rigor-activerecord]** A read of an enum-backed column types as the enum's keys, such as `"active" | "archived"`, instead of the column's storage type ([#1089](https://github.com/rigortype/rigor/issues/1089), [#1161](https://github.com/rigortype/rigor/pull/1161)).
- **[plugins/rigor-activerecord]** `delete_all(:nullify)` on an association reader such as `user.posts` no longer reports a false `call.wrong-arity` ([#1312](https://github.com/rigortype/rigor/pull/1312)).
- **[plugins/rigor-activerecord]** Active Record writers carry the effects they have, so association builders and proxy writers carry `mutate`, `insert` and `upsert` carry `io.db.write`, and writers that query first carry `io.db.read` ([#1309](https://github.com/rigortype/rigor/pull/1309), [#1314](https://github.com/rigortype/rigor/pull/1314), [#1315](https://github.com/rigortype/rigor/pull/1315)).
  - A project that declared `insert`, `insert!` or `upsert` on `ActiveRecord::Relation` in its own `sig/` should remove it, because the two collide as `RBS::DuplicatedMethodDefinitionError`.
