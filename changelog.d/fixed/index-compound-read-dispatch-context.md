- **[inference]** A compound index write — `c[k] += v`, `c[k] ||= v`, `c[k] &&= v` — on an object whose class defines `[]` in the project without a signature now reads `c[k]` from that method's body, as a plain `c[k]` already did: with `class C; def [](k) = 0; def []=(k, v); end; end`, `c[:a] += 1` is `1` rather than `untyped`. ([#1236](https://github.com/rigortype/rigor/pull/1236))
  - A memoizing `c[k] ||= v` over such a `[]` whose body can return `nil` beside an untyped value (`return nil unless @data; @data[k]`) now keeps that untyped value in its type instead of reading as `v`, so `rigor sig-gen` skips a method returning it rather than typing it as `v`.
  - `if (h[k] &&= v)` on a core `Hash` or `Array` no longer draws a false `flow.always-truthy-condition`: when the slot is absent the write stores nothing and is `nil`.
