- **[inference]** A method defined in a `refine X do … end` block no longer reports a false `call.undefined-method` where a `using` of its module is lexically in effect (after `using` at the file's top level or in a class or module body, inside the refine block, or anywhere in a file whose `using` takes a non-constant such as `Module.new { … }`), and `def o.m` on a local no longer reports `o.m` in the same scope; a refined method called before or without `using` still reports, as Ruby raises there, and a refine block's methods now see an instance of the refined class as `self`, so they are checked against that class's signatures. ([#1120](https://github.com/rigortype/rigor/issues/1120), [#1424](https://github.com/rigortype/rigor/pull/1424))
