- **[engine]** A constant referenced inside a compact namespace declaration — `Rails` written in `module MyApp::Inner`, `User` written in `class Admin::UsersController` — now resolves where the code is written the way Ruby resolves it, to the top-level constant rather than to a same-named one under the enclosing namespace, which had also been reported as `undefined method` on correct code; the fix covers constant reads, `is_a?`/`kind_of?`/`instance_of?`, `case`/`when` and `Class === x` alike, and the nested spelling of the same class keeps reaching the nearer constant exactly as before. A value that arrives through another method's inferred return type is still resolved as though the declaration had been written nested, so a compact-form method whose return type Rigor infers can still report the wrong namespace at its call sites. ([#652](https://github.com/rigortype/rigor/issues/652))
