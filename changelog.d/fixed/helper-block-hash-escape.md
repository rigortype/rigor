- **[inference]** A hash passed to a helper that stores into it from a block no longer keeps its literal entries after the call, so a condition on the hash no longer reports a false `flow.always-truthy-condition`. ([#2510](https://github.com/rigortype/rigor/issues/2510), [#2514](https://github.com/rigortype/rigor/pull/2514), [#2515](https://github.com/rigortype/rigor/issues/2515), [#2516](https://github.com/rigortype/rigor/pull/2516))
  - Covers the OptionParser idiom with a helper: `options = { format: "text" }; OptionParser.new { |o| Opts.add_format(o, options) }.parse!(argv)` with `def self.add_format` or `module_function` writing `options[:format]` in an `on` block.
  - The helper may be called on a constant (`Opts`, `::Opts`, `A::Opts`), on an instance (`Opts.new.add_format(...)`, or a local holding one), or on a class that inherits the singleton method from a project superclass; it may hand the hash on to further helpers on other classes (`Help.c(...)`, `Helper.new.c(...)`), whose constants resolve in the nesting of the class that defines them (a bare constant is looked up under each prefix of a qualified class name and at the top level, a helper found under any is followed, and the constant is also typed under each nesting the class could have had, so an alias, an inherited or included constant or a constant holding an instance is followed too, with the callees of both resolutions combined); a helper inherited from a superclass or an included module, class-side or instance-side (`SubHelper.new.c(parser, options)`), is not read, and its argument is floored; a receiver of a union type resolves each member; a constant narrowed by a guard (`if INST.is_a?(Sub)`) neither feeds nor reads the shared per-def cache. ([#2524](https://github.com/rigortype/rigor/issues/2524))
  - A callee that never writes the hash, a hash that is not passed, a receiver of unknown type, `Const.new` of a class that defines its own `self.new`, and a splat argument keep the literal.
