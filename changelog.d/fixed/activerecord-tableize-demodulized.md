- **[plugins]** `rigor-activerecord` no longer flattens a namespaced model's constant path into its table name (`Blog::Post` → `blog_posts`) — it now demodulizes first, the way Rails does, and applies a `table_name_prefix` / `table_name_suffix` only when the enclosing module or class declares one as a literal your source spells out; when a declared prefix or suffix can't be read that confidently, or a model is nested inside another model class, the model's column, alias and association checks stand down instead of guessing a table that might belong to something else. Namespacing from a `Rails::Engine.isolate_namespace` declaration, a model's own `table_name_prefix`, or a base class's `table_name_prefix` is not read yet, so those still resolve the plain guessed name uncorrected. ([#623](https://github.com/rigortype/rigor/issues/623), [#677](https://github.com/rigortype/rigor/pull/677))
