- **[engine]** A refinement of `Object`, `Module`, `Class`, `Kernel` or `BasicObject`, or of a module a class extends, now reaches a call on a class object: under `refine(Object) { def oo = :o }` and its `using`, `Integer.oo` no longer reports `call.undefined-method` and types as `:o`, and `C.z(1, 2, 3)` no longer reports `call.wrong-arity` when `C` extends a module whose refinement answers. A class object's own singleton method still answers first, so `Integer.sqrt(1, 2)` keeps reporting under a refinement of `Object#sqrt`. Inside the span of a `using` of a module Rigor cannot read (a gem's), calls on class objects now type as `Dynamic` too. ([#1752](https://github.com/rigortype/rigor/issues/1752), [#1836](https://github.com/rigortype/rigor/pull/1836))
