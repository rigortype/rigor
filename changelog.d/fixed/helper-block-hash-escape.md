- **[inference]** A hash passed to a helper that stores into it from a block no longer keeps its literal entries after the call, so a condition on the hash no longer reports a false `flow.always-truthy-condition`. ([#2510](https://github.com/rigortype/rigor/issues/2510), [#2514](https://github.com/rigortype/rigor/pull/2514), [#2515](https://github.com/rigortype/rigor/issues/2515), [#2516](https://github.com/rigortype/rigor/pull/2516))
  - Covers the OptionParser idiom with a helper: `options = { format: "text" }; OptionParser.new { |o| Opts.add_format(o, options) }.parse!(argv)` with `def self.add_format` or `module_function` writing `options[:format]` in an `on` block.
  - The helper may be called on a constant (`Opts`, `::Opts`, `A::Opts`), on an instance (`Opts.new.add_format(...)`, or a local holding one), or on a class that inherits the method from a project superclass or an included module, class-side or instance-side, whose inherited helper is not read and floors its argument. It may hand the hash on to further helpers on other classes (`Help.c(...)`, `Helper.new.c(...)`), whose constants resolve as Ruby resolves them in the nesting the calling method is written under: `class B::Opts` reads `::Helper`, `module B; class Opts` reads `B::Helper`, and an inherited or included constant, an alias or a constant holding an instance is followed (a method in `class << self` still tries each spelling, as Ruby reads its constants through the singleton class). A receiver of a union type resolves each member; a constant narrowed by a guard (`if INST.is_a?(Sub)`) neither feeds nor reads the shared per-def cache. ([#2522](https://github.com/rigortype/rigor/issues/2522), [#2524](https://github.com/rigortype/rigor/issues/2524), [#2570](https://github.com/rigortype/rigor/pull/2570))
  - A callee that never writes the hash, a hash that is not passed, a receiver of unknown type, `Const.new` of a class that defines its own `self.new`, and a splat argument keep the literal.
