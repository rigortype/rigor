- **[engine]** `call.possible-nil-receiver` no longer fires on a value guarded by a safe-navigation chain (`if custom&.value.present?`, `return if backup&.user.nil?`, `x&.y == "literal"`) or by an `include?` test against a collection that cannot hold nil, so idiomatic Rails guards stop reporting working code.
