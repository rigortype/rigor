- **[engine]** A class guard on a global, constant or local receiver now protects the call it guards, so `$stdout.is_a?(StringIO) ? $stdout.string : nil` no longer reports on an `IO`-typed `$stdout`. ([#1453](https://github.com/rigortype/rigor/pull/1453), [#1429](https://github.com/rigortype/rigor/issues/1429))
  - A guard naming a class the receiver's inferred type cannot hold makes its branch gradual: the receiver reads `Dynamic[StringIO]`, a misspelled method on it still reports, and the branch's value leaves as `Dynamic`, so it is never an error at a typed boundary later.
  - A `when` clause naming such a class is no longer reported by `flow.unreachable-clause` or dropped from the `case` value, and each arm of a value-position `case` is typed under the subject's clause narrowing.
  - `respond_to?(:string)` on an `IO`-typed receiver lets the guarded `string` call through, and it drops union members known to lack the method.
