- **[inference]** A string literal no longer keeps its value after `delete_prefix!`, `delete_suffix!`, `encode!`, `scrub!`, `unicode_normalize!`, `setbyte`, `bytesplice` or `append_as_bytes`, so `s = +"ab"; s.delete_prefix!("a")` no longer makes `s == "ab"` report an always-truthy condition. The same holds when the literal is an instance variable or constant that another method mutates in place, or when a method or closure it is passed to or captured by mutates it, including a variable that may also hold `nil` or a collection. A `non-empty-string` refinement is now dropped after a call that can empty the string, such as `tr!` with an empty replacement, and kept after one that cannot, such as `tr!("-", "_")` or `squeeze!`; and `h[k] ||= default` followed by a String mutation of `h[k]` no longer reads the slot back as possibly nil. ([#1270](https://github.com/rigortype/rigor/pull/1270))
  - **[effects]** `force_encoding` and the calls above now count as receiver mutations on a `String`, so `rigor effects` labels a method that makes one on a string it does not own with `mutate.*`, and with `effects.check` enabled a `%a{pure}` method that does so reports `effect.envelope-exceeded`. A method that calls one on a string it has just copied (`raw.dup.force_encoding(...)`) reads as `mutate.local`, which every envelope tolerates, so it stays pure. A committed effect snapshot may need regenerating.
