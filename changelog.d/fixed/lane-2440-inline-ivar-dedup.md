- **[rbs]** A project that commits `rbs-inline --output`'s RBS under `sig/` no longer fails the definition build of every class whose `# @rbs @ivar: T` annotation, or whose mixin of a module declaring one, is repeated in the committed file. ([#2467](https://github.com/rigortype/rigor/pull/2467))
  - An instance variable or class instance variable declared both in `sig/` and inline is reconciled like a method. When the types match, nothing is reported. When they differ, the `sig/` declaration binds and the inline one is reported at `:info`.
  - An `include`, `extend` or `prepend` that `sig/` already makes with the same arguments is dropped from the inline side, because rbs counts a module's instance variables once per declaration that mixes it in.
  - The `rbs.coverage.definition-build-failed` warning names both colliding files. It names an inline-RBS source by its `.rb` file. Its advice now fits each case: a duplicated instance variable (inline, committed, or mixed in twice), a superclass mismatch, a missing superclass, or a type applied with the wrong arguments.
