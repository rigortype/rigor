- **[config]** `severity_overrides:` now names a plugin's diagnostic by its qualified id (`plugin.<id>.<rule>`, or `plugin.<id>` for the whole plugin) instead of its bare rule, so `load-error: off` no longer silences every plugin's own `load-error`, and a family wildcard such as `rspec: warning` no longer re-stamps a plugin's dotted rules. The plugin loader's rows answer to `plugin_loader.load-error` first and to the bare `load-error` after it. `rigor check` warns about an override key it can tell reaches no row (a bare plugin rule, a plugin family key such as `rspec`, `all`, or a `plugin.<id>` key for a plugin that `plugins:` does not configure), and `rigor doctor` reports such a warning as `[FAIL]` and exits 1, where it exited 0 before. ([#2000](https://github.com/rigortype/rigor/pull/2000))
