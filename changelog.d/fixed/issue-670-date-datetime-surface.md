- **[plugins]** Ordinary Rails code on a `Date` or `DateTime` receiver no longer draws `undefined method` — `Date.current.past?`, `Date.current.beginning_of_quarter`, `DateTime.now.past?`, `Date#in_time_zone` and the rest of the ActiveSupport calculation, conversion and time-zone surface are now declared, audited against activesupport 8.1.3.1. Because `DateTime` inherits from `Date`, the rows whose result differs between the two are declared separately for each, so `DateTime.now.beginning_of_month` and `DateTime.current` now read as `DateTime` where they previously read as `Date` — a wrong result type that was already reachable before this change. `date.at_beginning_of_week(:sunday)` and `datetime.at_end_of_week(:sunday)` no longer report a wrong argument count, and `datetime.in_time_zone(-5.hours)` no longer reports a wrong argument type. ([#670](https://github.com/rigortype/rigor/issues/670), [#760](https://github.com/rigortype/rigor/pull/760))
