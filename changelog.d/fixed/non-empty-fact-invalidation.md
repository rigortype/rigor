- **[inference]** A collection's literal shape, and the `non-empty-array` an emptiness guard leaves, no longer outlive a mutation the call site does not spell as a mutator on the variable. ([#3347](https://github.com/rigortype/rigor/pull/3347))
  - After `return if xs.empty?`, `xs.size == 0` was reported as always falsey past `f = -> { xs.clear }; f.call`, inside a `loop do … xs.pop end` body, in a `rescue` clause whose `begin` body emptied `xs`, past `yield xs`, `[xs].each(&:clear)`, `xs.method(:clear).call`, `xs.instance_eval { clear }` and `xs.send(name)`, and for an instance variable past a method on `self` that empties it (`reset!` running `@xs.clear`). Each now reads `xs.size` as `non-negative-int`.
  - Code that only reads the collection in the same positions keeps the guard's fact, and a local passed to `yield` or sent a computed name keeps its type unless it held a literal shape or an emptiness witness.
  - An emptiness guard no longer narrows a local that a lambda, a proc or a `define_method` body in the same method can empty, wherever that closure is written, since it may run after the guard. A closure that only reads the local or appends to it changes nothing.
  - Still not followed: these forms written as an argument of another call (`puts(yield(xs))`).
