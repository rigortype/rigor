- **[config]** `core_root:` loads a directory of core RBS signatures in place of the `rbs` gem's own core, so a project on an older Ruby is checked against that Ruby's API. ([#2518](https://github.com/rigortype/rigor/pull/2518))
  - It is meant for a core generated by [rbs-shifter](https://github.com/rigortype/rbs-shifter): with its Ruby 3.3 core, `[1, 2].rfind { ... }` reports `call.undefined-method` and `" text ".strip(" ")` reports `call.wrong-arity`.
  - Unlike `signature_paths:`, which only adds signatures, it replaces the core. Project signatures, plugins and `libraries:` still load on top of it.
  - A `core_root:` that is missing, holds no `.rbs` file, or does not build an RBS environment stops the run with a `rigor:` line and exit code `64`, rather than falling back to the default core.
  - Switching cores or regenerating one in place invalidates the cache and the incremental snapshot, including in a running language server.
