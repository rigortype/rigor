- **[rigor check]** A call on a project class whose method is reached through an ancestry the file cannot order — a gem module without RBS included ahead of the definer, an include made by a hook (`included do`) or under a condition, a method defined conditionally — now types as `Dynamic` instead of from the definer that happened to come first, so the false positive of [#1594](https://github.com/rigortype/rigor/issues/1594) (`call.undefined-method` on a concern includer whose `included do` block includes the real definer) is gone. Where every project definer of the method raises, the call still types `bot`, so a guard such as `fail_with 'no' unless x` keeps narrowing `x`. Fewer calls are typed as a result, and `rigor coverage` drops on Rails apps; [#1651](https://github.com/rigortype/rigor/issues/1651) tracks recovering that loss. A true positive that depended on one world of such a condition is lost by design. ([#1562](https://github.com/rigortype/rigor/issues/1562), [#1572](https://github.com/rigortype/rigor/issues/1572), [#1629](https://github.com/rigortype/rigor/pull/1629))
