- **[inference]** The block of `Enumerator.new` or `Hash.new` no longer reads the `$1` an earlier match in the method narrowed as a `String`, and a lambda, proc or either of those blocks no longer reads a narrowed `$_`. ([#3220](https://github.com/rigortype/rigor/pull/3220))
  - After `return unless s =~ /(\d+)/`, `$1` reads `Dynamic[top]` in `Enumerator.new { |y| … }` and `Hash.new { |h, k| … }`: the block runs when the enumerator is read or a key is missing, which may be after a later match. Nothing new is reported there.
  - After `return unless $stdin.gets`, `$_` reads `Dynamic[top]` in those blocks and in `-> { … }`, `lambda { … }`, `proc { … }` and `Proc.new { … }`. A `$_` bound where such a body is written is no longer reported inside it: `$_ = nil; proc { $_.upcase }` is now quiet.
  - Only the literal `Enumerator`, `Hash` or `Proc` constant counts. A project class of that name, a subclass, an alias such as `E = Enumerator`, `Object::Enumerator` and `new` on any other receiver keep the earlier reading.
