- **[check]** `rigor coverage --protection` now attributes a method inherited from a class that lives in a gem shipping no RBS to that gem, instead of reporting it as an engine gap — previously only the constant read in the superclass position carried the cause, so a project whose base class comes from an RBS-less gem saw almost all of its untyped receivers labelled "report it" when the action is to add a type. On rubocop-ast the tractability split moves from 687 engine-gap / 13 add-rbs to 527 / 173, with diagnostics unchanged. ([#530](https://github.com/rigortype/rigor/issues/530))
