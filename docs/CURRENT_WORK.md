## Gotchas (load-bearing, learned the hard way)

- **ADR-46** — do NOT extract the `Runner#initialize` ivar pre-seeds (`@class_decl_paths_snapshot = {}` etc.) into a helper; moving them out of the constructor hides them from the engine's OWN flow analysis and `make check` self-flags `snapshot.size` as a nil-receiver false positive. Keep them inline (the constructor carries an `AbcSize` disable).
- **ADR-45** — `@collect_stats` is true by default (can't gate the cache on it; a hit returns nil stats); a lazy `@io_boundary ||=` on a frozen plugin → `FrozenError` (use `instance_variable_get`); a cache write / serialize failure is swallowed (never breaks a run).
- **ADR-24** — a check-rules *reimplementation* of self-call resolution diverges from the engine's real one (which already handles `module_function` / `Data.define` accessors / mixins for precision) → 135 FPs (reverted). The landed route is the evaluation-time `SelfCallResolutionRecorder` ("collect, don't recompute").
- **ADR-62 / ADR-63** — `make verify` gates only `lib` + `plugins`; the **external corpus can still expose false positives** from receivers Rigor mistypes. A union/nilable undefined-method rule inherits the scalar rule's "only as good as the inferred type" exposure — the nilable study caught a `Hash | Hash`#pack FP on mail (`compose_codepoints` mistyped an `Array`). Run a `rigor-survey` corpus diff (`cd $proj; BUNDLE_GEMFILE=$rigor/Gemfile nix develop $rigor -c bundle exec $rigor/exe/rigor check --format json $paths`) before trusting any diagnostic-widening on union / nilable receivers. Also: the inference scanners (`PrecisionScanner` / `ProtectionScanner`) are NOT autoloaded by `require "rigor"` (require them explicitly, as their specs do); rubocop enforces annotated `%<name>s` format tokens; and a `Data.define(:method, …)` member shadows `Data#method` (use `:method_name`).
- **bench-perf** — the Make target is `bench-perf`, not `bench` (the bare name collides with the `bench/` data directory; the file keeps its no-`.PHONY` convention). The release gate is **required** (not advisory). Both baselines are **recalibrated per feature cycle** — `bench/baseline.json` perf targets + `data/oss-sweep/mastodon-thresholds.json`; the v0.2.0 cut set lib allocations ≈18.77 M / peak RSS ≈232 MB / wall 13.75 s and Mastodon `app lib config` to 468 diagnostics at min precision 0.4284. These are exact-count / banded gates with little headroom, so a precision or allocation change flips them red **until recalibrated, by design**. Recalibrate perf from the **CI-measured Linux values** in the failed run's log (allocations is the deterministic signal; wall_s is noisy — `gh run rerun --failed` clears a wall-only flake), and **diff the OSS-sweep diagnostics for false positives before blessing a higher count** (the v0.2.0 recalibration found 3 `StringScanner#[]` FPs → fixed via `data/core_overlay/string_scanner.rbs`, not blessed into the threshold).

### ADR-24 — implicit-self method-call resolution, remaining

- **Slice 4 (recorder + `call.self-undefined-method` rule, shipped `:off`) — LANDED v0.1.17; WD4 corpus FP eval DONE 2026-06-14 → rule stays `:off`, NOT promotable** ([note](notes/20260614-adr24-slice4-self-undefined-fp-eval.md)). The eval landed the universal-base exclusion (Bucket 1, `Object`/`BasicObject`/`Kernel`, 287 corpus FPs) but found the **abstract / template-method base-class pattern** (Bucket 2, 167) is an unaddressable FP under the current per-class gate. **Do NOT widen the standalone-only gate to superclass / include chains** until the abstract-base FP is solved — the required shape is **subclass-aware gating** (record at the recorder whether the missed method is defined on a known subclass; suppress if so). **Arity diagnostics** on resolved closed-class self-calls were NOT part of slice 4 (undefined-method only) — a later extension once the rule proves out.
- **Non-`Bot` general adoption inside class bodies** — a resolved self-call return type is adopted ONLY when it is `Bot`. Unconditional adoption of precise non-`Bot` returns regressed `rigor check lib` by 16 diagnostics (pre-existing callee-return-inference imprecisions surfacing downstream); this follow-up needs callee-return inference precise enough that adopting precise types does not surface those imprecisions.

### Stdlib RBS coverage-gap pattern + the staged upstream PR

When an upstream `ruby/rbs` gap is surfaced by a single internal call site, prefer **(a')** an in-source `# rigor:disable` + load the library; across multiple call sites or user-facing code, escalate to **(b)** a focused RBS overlay under Rigor's own `sig/`, or **(c)** an upstream `ruby/rbs` fix. The `references/rbs` branch `widen-strscan-resolv-stdlib-sigs` (widens `StringScanner#[]`, `Resolv#initialize`) is staged — **branch push + `ruby/rbs` PR creation are the user's task.**
