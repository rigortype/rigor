- **[effects]** An `include` or `prepend` inside `class << self`, `singleton_class.class_eval` or `singleton_class.instance_eval` no longer counts as an instance-side include, since Ruby mixes the module into the class's singleton class there, as `extend` does. One inside a block that builds or opens another class, such as `Class.new`, `Struct.new` or `Other.class_eval`, is no longer filed under the enclosing class either. An instance method's `super` no longer resolves into such a module, `Foo.new` no longer takes its `initialize`, and its effects no longer reach those callers (a committed effect snapshot may need regenerating). ([#1320](https://github.com/rigortype/rigor/pull/1320))
  - This also has a less safe side. A class whose `new` comes from such a singleton-side mixin now reads as having the empty constructor, as a class that gets `new` through `extend` already did, so `rigor sig-gen` can write `%a{pure}` on a caller whose `new` does work.
