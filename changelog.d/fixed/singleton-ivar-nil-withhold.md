- **[diagnostics]** `call.argument-type-mismatch` no longer reports a class object held in an ivar the constructor seeds with `nil`. ([#2902](https://github.com/rigortype/rigor/pull/2902))
  - `@klass = nil` in `initialize`, `@klass = Circle` in another method and `Registry.fields_for(@klass)` against `(singleton(Shape))` is now withheld like the `Integer` instance case, under ADR-58's lazy-initialisation reading; a non-nil part that is itself rejected still reports. The non-nil part counts as accepted when it is not rejected (`yes` or an unresolved `maybe`), so an unrelated project class the engine has not loaded is withheld too ([#2844](https://github.com/rigortype/rigor/issues/2844)).
