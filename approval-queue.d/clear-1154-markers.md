# Re-point the 52 remaining #1154 markers to the issues that name their causes, and retire #1154 from the allow-list

- **PR:** [#2324](https://github.com/rigortype/rigor/pull/2324)
- **Issue:** [#1154](https://github.com/rigortype/rigor/issues/1154)
- **Class:** gate-row
- **Precedent:** [#2316](https://github.com/rigortype/rigor/pull/2316)
- **Decided:** 2026-10-23

## Background

#2199 made `rigor sig-gen` type `@x = x` from the declared type of the parameter `x`, and #2311 and #2316 completed the hand-written `initialize` declarations whose omitted keywords kept that credit from applying. 52 `# sig-gen gap: #1154` markers were left in `sig/`. The brief was to add whatever parameters the audit showed missing, and to clear or re-point the rest, so that #1154 could close. Moving a marker, extending `spec/rigor/sig_gen/gap_issues.yml` and removing a row from it are gate-row decisions.

## Options and trade-offs

- **Audit every row with `SigProvenanceAuditor`, add missing parameters where that is the cause** (taken, but it found no such row). Every one of the 52 readers is `unrenderable` (`sig.skipped.untyped-return`) except two `declared_divergent` rows, and none of them is a bare `@x = x` over a parameter that `sig/` omits or declares `untyped`. The cause is never the #2316 one. Nothing could be added without inventing a type, so no `initialize` declaration, no reader type and no residue pin changed.
- **Force a type, or keep the markers on #1154.** Rejected. A parameter type copied from a reader would not make the generator produce the row, because the credit covers only a bare read; and a marker that names an issue whose mechanism does not apply points a future reader at the wrong engine work (ADR-107 gate G3).
- **Re-point each marker to the issue that names its real cause** (taken), filing one issue per cause that had none (the one-issue-per-cause ruling in the header of `gap_issues.yml`).

## Decision

All 52 markers are re-pointed; none is deleted, and no row moved the wrong way. The provenance spec passes without a pin change. The `sig/` diff is comment lines only, so no declaration, and no `rigor check` finding on `lib/`, can differ.

| Cause | Issue | Rows |
|---|---|---|
| The ivar is assigned from an expression derived from a parameter (`dup.freeze`, `to_sym`, a ternary, `map`), not a bare read. Reproduced on a toy class: `bare` is proposed, `derived` and `sym` are skipped. | [#2321](https://github.com/rigortype/rigor/issues/2321) (new) | 17: `EffectEntryPoints` (3), `AdditionalInitializer` (3), `ProtocolContract` (4), `EffectEdge#method`, `EffectAttribution` (`method`, `narrow`, `callee`), `Effects::Registry` (`labels`, `descriptions`), `Baseline#buckets` |
| The ivar is stored from a private validator or normalizer helper with undeclared parameters (the helper itself is skipped), or written by a private `assign_*` helper (`Manifest`). | [#2312](https://github.com/rigortype/rigor/issues/2312) (existing, commented) | 29: `EffectEdge` (3), `EffectAttribution` (6), `EffectAncestry` (3), `ProtocolContract#param_types`, `Summary` (3), `FileCollection` (4), `Manifest` (9) |
| `filter_map` answers `Array[untyped]` with a typed receiver and block (reproduced). | [#2322](https://github.com/rigortype/rigor/issues/2322) (new) | `Scope#declaration_sourced_global_copies` |

Where a marker's reason text blamed `initialize` for something the helper or the derivation does, it was reworded to the real cause. #1154's row is removed from `gap_issues.yml` and 2321, 2322 and 2323 are added, since no marker cites #1154 any more. The cause #1154's two evidence rows named (`Manifest#template_globs`, `Scope#singleton_class_body`) is now #2312 / generated by #2316. The `Set[untyped]` echo caveat from #2316 does not arise: no reader type was copied and no `# authored:` note was needed.

No reader type was corrected, since none was copied. Not fixed here: none of the causes was both local and free of engine risk (all of them are census or dispatch changes); each is on its issue.

## To undo

Restore `#1154` in the 52 marker lines, put the 1154 row back in `spec/rigor/sig_gen/gap_issues.yml` and drop the three new rows. The comments' reworded reasons can stay.
