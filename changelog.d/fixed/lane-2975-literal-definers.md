- **[check]** `call.undefined-method` no longer fires on methods a literal `send(:define_method, :x)`, `define_singleton_method(:x)` or `Other.define_method(:x)` defines, or on methods further class macros define. ([#2982](https://github.com/rigortype/rigor/pull/2982))
  - `send(:define_method, :x)` and `define_singleton_method(:x)` on `self` record `x` on the side they define it on, and `Other.define_method(:x)` records `Other#x` rather than the enclosing class's `x`.
  - A macro whose body runs `define_method` under a computed name now opens the class whose body calls it when the macro is an instance method patched onto `Module`, a `def` in a `singleton_class.class_eval` block, or one that runs `include(Module.new { … })`. A class-body `include(Module.new { … })` of such a module opens the class too.
