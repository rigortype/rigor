- **[cli]** A source file with a byte that is invalid in UTF-8 in a comment (a latin-1 `caf\xE9`, say) no longer makes `rigor check` report an internal analyzer error that discards the file's diagnostics: the suppression-comment scan now reads the comment through a scrubbed copy. `rigor annotate` and `rigor trace` no longer crash on such a file either. ([#1818](https://github.com/rigortype/rigor/issues/1818), [#1823](https://github.com/rigortype/rigor/pull/1823))
