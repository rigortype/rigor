- **[plugins]** rigor-activesupport-core-ext now types `ActiveSupport::Duration`'s `to_i` / `in_seconds`, `to_f`, the `in_minutes` family, `iso8601` and `parts`, so `1.day.to_i * 2` resolves past the first reader instead of going opaque; the same declarations ship in the auto-applied activesupport overlay too, but an overlay-only project (no plugin loaded) only reaches them through its own `ActiveSupport::Duration`-typed signature, since the overlay's numeric multipliers stay untyped. ([#632](https://github.com/rigortype/rigor/issues/632), [#666](https://github.com/rigortype/rigor/pull/666))
