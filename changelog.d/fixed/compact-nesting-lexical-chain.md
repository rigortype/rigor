- **[engine]** A constant referenced inside a compact namespace declaration — `Rails` written in `module MyApp::Inner`, `User` written in `class Admin::UsersController` — is now resolved the way Ruby resolves it, to the top-level constant rather than to a same-named one under the enclosing namespace, which had also been reported as a false `undefined method` on correct code; `is_a?`/`kind_of?`/`instance_of?`, `case`/`when` and `Class === x` guards over such a name are fixed along with the constant read itself, and the nested spelling of the same class keeps reaching the nearer constant exactly as before. Two paths still read the old answer, so a compact-form class can continue to report the wrong namespace where a value arrives through another method's inferred return type, or through the type Rigor records for an instance variable, class variable or constant while scanning the project.
