- **[engine]** A call through an in-effect Ruby refinement is now typed from the refine body instead of from the method the refinement replaces: under `using SymSyntax`, `:authors[:age]` types as the refine body's `String` rather than core `Symbol#[]`'s `String?`, and a refined `"a".upcase` no longer folds. Ruby's lookup order decides the winner (a later `using` wins, a subclass's own method beats a refinement of its superclass, a refinement of a class beats a module prepended to it), a union receiver is typed per member, and a body Rigor cannot read (a gem refinement, a `using` that names no module) types as `Dynamic[top]`. `send` / `public_send`, `respond_to?`, `method` and `&:name` reaching a refined name type as `Dynamic[top]`. ([#1664](https://github.com/rigortype/rigor/issues/1664), [#1747](https://github.com/rigortype/rigor/pull/1747))
