- **[sig]** The bundled ActiveSupport overlay and the `rigor-activesupport-core-ext` plugin now declare `Object#deep_dup`, `Hash#with_defaults` / `#with_defaults!` / `#reverse_update`, `Hash#to_options` / `#to_options!`, `Hash#extract!`, `Hash#deep_merge?`, `Hash#nested_under_indifferent_access`, `Range#overlaps?` and `Range#to_fs` / `#to_formatted_s`, so `[[1], [2]].deep_dup` and `(a..b).overlaps?(c..d)` no longer report a false `call.undefined-method`. `Hash#reverse_merge` and `#with_defaults` no longer claim their result holds only the receiver's keys and values; the argument's side reads as `Dynamic[top]`. If your project's `sig/` declared any of these methods itself to silence the old false positive, delete that declaration: the duplicate stops Rigor from building the class. ([#1330](https://github.com/rigortype/rigor/pull/1330))
