Mastodon empirical effect: errors 789 → 764 (−25), `call.undefined-method` 49 → 24 (−25 — Tuple-widened receivers dispatch through Array RBS rather than the narrower shape tier), `flow.always-truthy-condition` 9 → 8 (the remaining 8 are the G2-remaining cases — `retry` flow edge, intervening method-call ivar invalidation, read-before-write nil — documented in the module docstring as deferred).

3. **`rigor-rails-routes` custom-helper discovery + `devise_for` recognition** — the Mastodon measurement revealed `unknown-helper` as the dominant remaining error cluster (567 of 764 errors). Two layered fixes against the same `HelperTable`: (a) **walk `app/helpers/**/*.rb`** for module-level `def name(...)` whose name ends in `_path` / `_url`, register them as "known but un-validated" helpers so calls to project-defined URL builders (`full_asset_url`, `host_to_url`, `frontend_asset_url`) do not false-fire. Skips singletons; walks nested modules. New `helper_paths:` config (default `["app/helpers"]`) opts in additional directories. (b) **Recognise `devise_for :resource [, skip: [...]]`** in `RoutesParser` and generate the standard Devise helper catalogue — sessions, passwords, confirmations, unlocks, registrations and their `_url` variants — plus a pattern matcher for dynamic-provider OmniAuth helpers (`<resource>_<provider>_omniauth_(authorize|callback)_(path|url)`). New files: `helper_discoverer.rb`, `devise_routes.rb`. Mastodon empirical effect: **errors 764 → 617 (−147), `unknown-helper` 567 → 420 (−147)**.

4. **`rigor-rails-routes` parser + helper-discovery follow-up** — the empirical residue from slice 3 split into three causes that this slice closes: (a) **`helper_paths:` default expanded to `["app"]`** (was `["app/helpers"]`) so URL-helper methods Mastodon defines under `app/lib/`, `app/services/`, `app/controllers/`, `app/serializers/` are picked up by default. The suffix filter (`_path` / `_url` only) keeps the registered set tight regardless of directory size. (b) **Bug A**: `resources :foo, only: [:create]` / `only: [:update]` / `only: [:destroy]` / `except: [:show]` used to register NO helpers — `entry_for_action` returned nil for those actions. Rails actually generates `foos_path` (collection POST) / `foo_path(id)` (member PATCH / DELETE) for them, so missing them produced an `unknown-helper` on Mastodon's `admin_role_path(@role)` and similar. The action handler now emits the show-/index-equivalent entry. (c) **Bug B**: singular `resource :foo` whose name is plural-looking (`resource :relationships, only: [:show, :update]`) was being singularised to `relationship_path`; Rails keeps the as-given name (`relationships_path`). Fix: skip singularisation for the singular DSL. (d) **Visibility-agnostic helper discovery**: dropped the `private` / `protected` filter on `HelperDiscoverer` — a `private def page_url(page)` in a controller IS registered so the paired view's `link_to "Next", page_url(2)` does not false-fire; the core engine's `call.undefined-method` still catches a genuinely unreachable receiver. Plugin version bumped `0.1.0 → 0.2.0` for cache invalidation. Mastodon empirical effect: **errors 617 → 458 (−159), `unknown-helper` 420 → 261 (−159)**.

5. **`rigor-actionpack` controller discoverer overhaul** — the `unknown-filter-method` cluster (42 of 458 errors) traced to three discoverer bugs against Mastodon's nested controllers. (a) **Nested-module qualification**: `module Admin; class AccountsController < BaseController; end; end` used to register as bare `AccountsController`, clobbering the top-level `app/controllers/accounts_controller.rb` entry — so the wrong inheritance chain flowed downstream and every filter check missed. The fix threads the enclosing module qualifier through the AST walk via a new `enclosing_namespace` field on `ControllerIndex::Entry`. (b) **Multi-level inheritance**: `effective_methods_for` used to walk one parent level only. Mastodon's `Admin::AccountsController < BaseController < ApplicationController` lost `require_user!` (defined on the grandparent). Rewrote as a cycle-safe ancestor walk. (c) **Lexical parent lookup**: a bare `BaseController` reference inside `module Admin` should first resolve to `Admin::BaseController`, then fall through to top-level — matching Ruby's constant-resolution semantics. New `resolve_constant_lexically` helper. Plugin version bumped `0.1.0 → 0.2.0`. Mastodon empirical effect: **`unknown-filter-method` 42 → 8 (−34)**. Remaining 8 are gem-shipped concerns (Pundit's `verify_authorized` etc.) and dynamically-defined filter methods.

6. **`rigor-rails-routes` shadowing-locals + kwargs-arity tolerance** — the residue from slices 3 + 4 was dominated by two patterns. (a) **Shadowing-locals (204 of 261 `unknown-helper` were in `spec/`)**: a `let(:foo_url) { ... }` / `subject(:foo_url) { ... }` / `def foo_url` / `foo_url = ...` introduces a name that shadows the registered helper for the file. The pre-walk now gathers every shadowing name and the analyzer skips route validation for matching call names — RSpec's canonical `let(:collection_url) { 'https://...' }` then `expect(collection_url)` pattern no longer fires `unknown-helper` / `wrong-arity` against the helper Rails would have registered. (b) **Kwargs-only call form**: `short_account_status_url(account_username: u, id: i)` against `get '/@:account_username/:id', as: :short_account_status` (arity 2) passes Rails' segment-via-kwarg form but our strict positional check rejected. The arity check now accepts positional ≤ expected when a trailing `KeywordHashNode` is present. Plugin version bumped `0.2.0 → 0.3.0`. Mastodon empirical effect: **errors 424 → 320 (−104), `unknown-helper` 261 → 187 (−74), `wrong-arity` 30 → 0 (eliminated entirely)**.

7. **`rigor-actionpack` analyzer-side nested-module qualification** — the slice-5 discoverer fix qualified `module Admin; class DomainBlocksController` as `Admin::DomainBlocksController` in the index, but the ANALYZER side still read the AST class name as bare `DomainBlocksController` via `first_class_node` + `qualified_name_for(class_node.constant_path)`. So `diagnose_filters` did `controller_index.known?("DomainBlocksController")` → silent miss (false-negatives on filter validation for nested controllers) and `diagnose_renders` computed `controller_path_for` against the bare name → `domain_blocks/new.html.erb` instead of `admin/domain_blocks/new.html.haml`. New `first_class_node_with_namespace` walker accumulates every enclosing `ModuleNode` qualifier through the AST descent; the resulting qualified name is used for both index lookup and render-path derivation. Plugin version bumped `0.2.0 → 0.3.0`. Mastodon empirical effect: **`missing-template` 27 → 3 (−24)**.

8. **`rigor-rails-routes` member/collection shorthand + `_index_` suffix** — two parser improvements landed together (plugin version `0.3.0 → 0.5.0`). (a) **Member / collection block shorthand**: `resources :accounts do member { post :memorialize }; collection { post :batch }; end` used to silently skip the inline action declarations because the parser's `handle_explicit_route` rejected the symbol-only call shape. New `member_block` / `collection_block` Context frames + `register_member_collection_action` derive `memorialize_<singular>_path(id)` for member actions and `<action>_<plural>_path` for collection actions (with correct arity from the parent scope chain). (b) **`<name>_index_path` for same-singular-plural resources**: `resources :reblogged_by, only: :index` (where `singularize(reblogged_by) == reblogged_by`) used to register `reblogged_by_path` colliding with the show helper. Rails suffixes `_index_` to disambiguate, EXCEPT for the UNCOUNTABLE-noun list (`news`/`series`/etc.) which it keeps under one name. The parser now matches that behavior. Mastodon empirical effect for the combined slice: **errors 296 → 242 (−54), `unknown-helper` 187 → 133 (−54)**.

9. **`rigor-activerecord` migration-files exclusion** — `db/migrate/<timestamp>_*.rb` and `db/post_migrate/` files reference the EVOLVING schema at the time the migration ran (e.g. `Account.where(suspended: true)` works inside a migration that's about to REMOVE the `suspended` column — the current `db/schema.rb` no longer carries it). 11. **`rigor-rails-routes` singular-resource block prefix** — singular `resource :foo do ... end` now contributes the resource's as-given name to the helper prefix for nested declarations. ### Flow-folding — loop-mutation tracking (gaps G1 / G2)

**The collection-mutation portion is closed** (2026-05-27, see `[Unreleased]` slice 2): a literal-shape carrier (`Tuple` / `HashShape`) bound to a local or ivar is widened to the underlying `Nominal[Array, ...]` / `Nominal[Hash, ...]` when an in-place mutator is called on it, including inside non-escaping block bodies. The three `rigor check lib` self-check warnings (`hkt_body_parser.rb:140 / :307`, `hkt_registry.rb:212`) are gone. Engine: `Rigor::Inference::MutationWidening`.

**Remaining G2 cases** that this slice deliberately did NOT address (documented in the module docstring as out-of-scope):

- **`retry` flow edge** — `tries = 0; begin ...; rescue; tries += 1; retry; end` doesn't reflect the `retry`-side rebind into the post-block scope. Different problem (flow edge, not call-site mutation). Example: `lib/mastodon/snowflake.rb:19`.
- **Intervening method call invalidates the ivar binding** — `if @performed; perform!; if @performed` — the intra-procedural call effect on ivars is not modelled. Example: `app/workers/activitypub/delivery_worker.rb:39 / :41`.
- **Read-before-write nil** — `unless @warning_issued; ...; @warning_issued = true` — the ivar accumulator unions writes only, missing the read-before-write `nil`. Example: `lib/chewy/strategy/bypass_with_warning.rb:7`.

These three remain queued under `docs/type-specification/control-flow-analysis.md` § "mutation effects"; each is a separate medium-sized engine change with its own precision-regression risk profile.

### Stdlib RBS coverage-gap pattern

When an upstream `ruby/rbs` RBS gap is surfaced by a single internal Rigor call site, prefer **(a')** an in-source `# rigor:disable` directive + load the library; when it surfaces across multiple call sites or in user-facing code, escalate to **(b)** a focused RBS overlay under Rigor's own `sig/`, or **(c)** an upstream `ruby/rbs` fix. The `references/rbs` branch `widen-strscan-resolv-stdlib-sigs` (widens `StringScanner#[]`, `Resolv#initialize`) is staged for an upstream PR — branch push + `ruby/rbs` PR creation are the user's task.

### Mastodon cross-version sweep — FP findings (2026-05-23)

The v3.5.19→v4.5.10 cross-version regression sweep ([`docs/notes/20260523-mastodon-v4.5-regression-sweep-v0.1.9.md`](notes/20260523-mastodon-v4.5-regression-sweep-v0.1.9.md) § "What is increasing") isolated four engine-side false-positive / misinference clusters. Two are already tracked; two are new:

1. **`StringScanner#[]` Symbol overload** (FP, 3 sites in `signature_parser.rb`) — `scanner[:key]` (a Ruby 3.x named-capture Symbol arg) trips `call.argument-type-mismatch` because Rigor's RBS has only `(Integer) -> String?`. **Already covered** by the "Stdlib RBS coverage-gap pattern" item above — the `references/rbs` branch `widen-strscan-resolv-stdlib-sigs` widens exactly this. The sweep is empirical confirmation; close it when the upstream RBS PR lands.
2. **AR `scope`-body method resolution** (misinference, NEW) — inside `scope :x, -> { select(...).group(:uri) }` the lambda's `self` is the model class, but `select` resolves to `Enumerable#select` (→ `Array[String]`) instead of `ActiveRecord::Querying#select` (→ a relation), so a chained `.group` reads as `undefined-method`. The empirical case for **ADR-26** (`ActiveRecord::Relation` typing); also note the model class-side query surface is the `rigor-activerecord` plugin's job. No new ADR needed — fold into ADR-26 slicing.
3. **Ivar nil-guard / ivar-write typing** (misinference, **FIXED 2026-05-26**) — `@ivar.method` after `return if @ivar.nil?` no longer reports `undefined-method … for nil` when the ivar is seeded `Constant[nil]`. Root cause: `live_branch_for_if` short-circuited when `@ivar.nil?` folded to `Constant[true]`, returning the un-narrowed `post_pred` scope as continuation and bypassing the `branch_terminates?` falsey-scope narrowing. Fixed in `statement_evaluator.rb` `eval_if` / `eval_unless` (commit `36d6b1f`). The case where the ivar's non-nil assignment is in a parent class (invisible to the per-file accumulator) is still a miss — addressed once the parent-class accumulator crosses the project-file boundary (ADR-24 slice 2 / cross-file class registry). Remaining: ivar-write-inference via G2 (see "Flow-folding" item below).
4. **Flow-folding over-claim** (FP, 3 `flow.always-truthy-condition` sites) — **collection-mutation portion FIXED 2026-05-27** via `Rigor::Inference::MutationWidening` (see `[Unreleased]` slice 2). The G2-remaining cases (`retry` flow edge, intervening method-call ivar invalidation, read-before-write nil) stay queued — see the "Flow-folding" item above for the catalogue.
