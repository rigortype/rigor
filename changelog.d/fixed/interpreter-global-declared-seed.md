- **[engine]** A write to a global the interpreter sets, such as `$VERBOSE = true` or `$stdout = StringIO.new`, now widens its declared type in the file's methods instead of replacing it, so `warn "x" if $VERBOSE` is no longer reported as always truthy; the separators `$/`, `$,`, `$;`, `$\`, `$-0`, `$-F` and `$-i` still read only the file's writes, and a report that rested only on the written type, such as `$stdout.reopen(STDOUT)` or `Cap.take(STDOUT)` against `(StringIO)` after `$stdout = StringIO.new`, is no longer made. ([#1433](https://github.com/rigortype/rigor/pull/1433))
