- **[call.wrong-arity]** A call is no longer reported as an arity error when Ruby's method order for the receiver depends on a fact the analysis cannot prove: `class C < Base; include M; end` where `Base` already includes `M` was checked against `M`'s method instead of `Base`'s, which Ruby runs. The rule is now silent where the order is uncertain, including a conditional `include` of a module that defines the method. ([#1570](https://github.com/rigortype/rigor/issues/1570), [#1605](https://github.com/rigortype/rigor/pull/1605))
