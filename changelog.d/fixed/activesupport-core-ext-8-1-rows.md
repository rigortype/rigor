- **[sig]** The bundled ActiveSupport overlay and the `rigor-activesupport-core-ext` plugin now declare `Object#presence_in`, `#with`, `#with_options` and `#html_safe?`, `Kernel#class_eval` on any object, `String#downcase_first`, `#acts_like_string?`, `#is_utf8?` and `#in_time_zone`, and `Symbol#starts_with?` / `#ends_with?`, so calls such as `1.html_safe?` and `"draft".presence_in(%w[draft live])` no longer report a false `call.undefined-method`. The plugin no longer marks `Hash#deep_dup` as `%a{pure}`, because it runs each value's own `dup`, and each key's unless the key is a `String` or `Symbol`, and it attributes a clock and a `Time.zone` read to `String#in_time_zone`. If your project's `sig/` declared any of these methods itself to silence the old false positive, delete that declaration: the duplicate stops Rigor from building the class. ([#1334](https://github.com/rigortype/rigor/pull/1334))
