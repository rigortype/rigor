- **[rules]** Two new rules report a write to a special global that Ruby's setter rejects, so the write raises every time it runs: `global.write-type-mismatch` for a value the setter refuses with `TypeError` (`$/ = 1`, `$~ = "x"`, `$0 = nil`, `$stdout = 1`; a stream takes anything that responds to `write`, and a write to `$stdin` is never checked), and `global.readonly-write` for a write to a read-only special such as `$!`, `$$`, `$?` or `$LOAD_PATH` (`NameError`). The type check follows Ruby's setter rather than the global's RBS type and fires only on a proof: a `Dynamic` value, a union with an accepted member, or a class your project declares stays silent. **Upgrade note:** both are errors under the default `balanced` profile, so such a write now fails `rigor check`; `global.write-type-mismatch` is a warning under `lenient`. ([#1448](https://github.com/rigortype/rigor/pull/1448))
