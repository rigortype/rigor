- **[inference]** A string literal no longer keeps its value after `delete_prefix!`, `delete_suffix!`, `encode!`, `scrub!`, `unicode_normalize!`, `setbyte`, `bytesplice` or `append_as_bytes`, so `s = +"ab"; s.delete_prefix!("a")` no longer makes `s == "ab"` report an always-truthy condition. The same holds when the literal is an instance variable or constant that another method mutates in place, or when it is passed to a method or captured by a closure that mutates it. A `non-empty-string` refinement is now dropped after a call that can empty the string, such as `tr!` with an empty replacement, and kept after one that cannot, such as `tr!("-", "_")` or `squeeze!`. ([#1270](https://github.com/rigortype/rigor/pull/1270))
  - **[effects]** `force_encoding` and the calls above now count as receiver mutations on a `String`, so `rigor effects` labels a method that makes one on a string it does not own with `mutate.*`, and with `effects.check` enabled a `%a{pure}` method that does so reports `effect.envelope-exceeded`. A method that calls one on a string it has just copied (`raw.dup.force_encoding(...)`) now reads as `unknown-ownership` rather than proven pure, so `rigor effects --pure` and `sig-gen`'s `%a{pure}` leave it out. A committed effect snapshot may need regenerating.
