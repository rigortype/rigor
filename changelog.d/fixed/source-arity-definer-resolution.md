- **[call.wrong-arity]** A call is no longer reported as an arity error when Ruby's method order for the receiver depends on a fact the analysis cannot prove: `class C < Base; include M; end` where `Base` already includes `M` was checked against `M`'s method instead of `Base`'s, which Ruby runs. The rule is now silent where the order is uncertain: after a fork (an include Ruby may or may not skip), after a conditional `include` of a module that defines the method, and for a class reopened in two files whose includes both define it (a multi-file mark with two defining closures), even where Ruby raises in every order. ([#1570](https://github.com/rigortype/rigor/issues/1570), [#1605](https://github.com/rigortype/rigor/pull/1605))
