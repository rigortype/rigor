- **[inference]** A discovered class's `include M` where `M` is RBS-known now resolves M's instance declarations — `include Enumerable` / `include Comparable` on a project class answers `sort` / `clamp` instead of `Dynamic[top]`, and a method-level `[A] (A) -> A` (e.g. `Rigor::Testing#dump_type` after `include Rigor::Testing`) binds its variable from the call's arguments. The arm declines when a project `def`, an outside-the-body `include` mark, or a `pre_eval:` patch means the declaration found is not the method that runs. `Scope#includes_of` now lists a class's modules in instance-ancestor search order — a later `include` statement nearer, matching Ruby — so the user-method walk no longer prefers the earlier statement's `def` over the one Ruby dispatches to.
