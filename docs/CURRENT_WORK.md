## Gotchas (load-bearing, learned the hard way)

- **ADR-46** — do NOT extract the `Runner#initialize` ivar pre-seeds (`@class_decl_paths_snapshot = {}` etc.) into a helper; moving them out of the constructor hides them from the engine's OWN flow analysis and `make check` self-flags `snapshot.size` as a nil-receiver false positive. Keep them inline (the constructor carries an `AbcSize` disable).
- **ADR-45** — `@collect_stats` is true by default (can't gate the cache on it; a hit returns nil stats); a lazy `@io_boundary ||=` on a frozen plugin → `FrozenError` (use `instance_variable_get`); a cache write / serialize failure is swallowed (never breaks a run).
- **ADR-24** — a check-rules *reimplementation* of self-call resolution diverges from the engine's real one (which already handles `module_function` / `Data.define` accessors / mixins for precision) → 135 FPs (reverted). The landed route is the evaluation-time `SelfCallResolutionRecorder` ("collect, don't recompute").
- **bench-perf** — the Make target is `bench-perf`, not `bench` (the bare name collides with the `bench/` data directory; the file keeps its no-`.PHONY` convention). `bench/baseline.json` ships uncalibrated → first run writes `bench/baseline.updated.json` (gitignored) and passes.

### ADR-52 — compiled plugin contribution dispatch (slices 1+2+3-partial LANDED; AR blocked; next = slice 4)

[ADR-52](adr/52-compiled-plugin-contribution-dispatch.md) + the grounding [structural audit note](notes/20260610-plugin-architecture-perf-audit.md) (2026-06-10). **Slice 1 (WD1) LANDED** (`67a552de` + `1deecb2f`): the compiled contribution table + the six engine call-site rewirings. WD6-gated byte-identical on Mastodon `app/models` (6 plugins) + GitLab subset (11 plugins, 2,332 lines) via control-vs-HEAD worktrees. GOTCHA the gate caught: the `&:symbol` block path dispatches with a `Prism::BlockArgumentNode` as `call_node` — a bare `call_node.name` raised, absorbed by `block_return_type_for`'s rescue, flipping `select(&:presence)` onto no-block Enumerator overloads (6 new GitLab errors); always derive gate names via `respond_to?(:name)`, regression specs pin it. **Slice 2 (WD2 static method-name-only gate) LANDED** (`c3550b00` + `cd5d5990`): `dynamic_return receivers:` is now optional — a rule may gate on `methods:` alone (receiver-less), for a plugin whose receiver carrier is a refinement not a nominal class; the engine skips the receiver-ancestry check and the registry gates on the name set. Migrated the `rigor-units` example (byte-identical on its demo, 17 diags).

**AUDIT CORRECTION discovered while implementing slice 2** (recorded in the ADR + audit note): the audit's slice-2 targets were both wrong — **activesupport-core-ext ships no `flow_contribution_for`** (pure RBS bundle, not a target) and **sorbet's catalog path matches arbitrary `def` method names** (a *run-time* name set, not static). No production plugin fits the static gate; units was its first consumer.

**Slice 3 (run-time receiver-set callable) PARTLY LANDED** (`fb5aea04`/`0f1a64b2` engine + `be4c532c` rigor-activestorage). `dynamic_return receivers:` now also accepts a callable, `instance_exec`'d against the plugin and memoised per rule, **resolved lazily on first dispatch** (always after `#prepare`) — the design judgment resolved in favour of lazy-on-first-use, NOT a runner `finalize!`: receiver gating lives in the instance `dynamic_return_type` path, never the ContributionIndex (a receiver-gated rule has no `methods:` gate, so the registry already treats it like a static-receiver rule), so no after-prepare table rebuild is needed. KEY soundness argument: the resolved set is a **safe over-approximation** of the block's own filter (engine admits equal-or-subclass, block re-runs the precise lookup), so every receiver the old hook accepted still reaches the block → byte-identical. The callable must reference a lazy/idempotent index (activestorage's `attachment_index`, AR's `model_index`) and must not raise (return `[]` on nil). Per-rule memo is a Hash created in `initialize` + `||= {}`-guarded so `allocate`-based unit specs and self-freezing plugins both work. activestorage gated on GitLab corpus (Mastodon doesn't load it), 2,322 diags byte-identical.

**rigor-activerecord is BLOCKED — a migration attempt was made and reverted** (2026-06-11; nothing committed). The `dynamic_return` receiver gate keys on the call's **`receiver_type`**, but AR's two class-side paths read the **AST** (`class_call_return_type` → `constant_receiver_name`) and **`scope.self_type`** (`implicit_self_class_call_return_type`), NOT the receiver type. VERIFIED ROOT CAUSE: a project model not in RBS — i.e. nearly every real model — types its constant as `Dynamic[top]`, so `User.find(1)` dispatches with `receiver_type = Dynamic`, `class_name = nil`, the gate declines, `u` never narrows to `Nominal[User]`, and the instance chain (`u.name → String`) collapses. The old `flow_contribution_for` never saw `receiver_type` (it read the AST), so it worked regardless. AR's caught it via its OWN end-to-end specs (`activerecord_plugin_spec.rb` "types an accessor end-to-end…", "resolves the block element type…") before any corpus run — cheaper signal than the corpus gate. AR's instance/relation paths WOULD gate fine, but a partial migration that leaves the hook for class-side paths defeats slice 5's goal of deleting the hook. **AR needs a new gate form before it can leave the hook** — see ADR-52 "rigor-activerecord blocker": either (A) the engine types a discovered in-source class constant as `Singleton[Class]` (broad, high-risk dispatch change, its own ADR), or (B) a gate keyed on the **AST receiver constant name** and/or **implicit-self in a class body** (the honest successor form for AST-keyed plugins; the slice-4 design question). The exact-membership-Set gate refinement (O(1) for AR's ~100-model set) was prototyped and reverted with the attempt — only land it together with a working AR migration.

**Next entry: slice 4** — either design AR's AST-keyed gate form (option B above; the more general win, unblocks AR + clarifies what `dynamic_return` should mean for AST-keyed plugins), OR proceed to the run-time *method-name* set (touches the ContributionIndex name gates, unlike receiver sets) for sorbet's catalog + rspec per-file + the config-gated examples (lisp-eval, pattern), leaving AR for the AST-gate slice. **Slice 5** deletes the hook (pre-1.0 BC break, before the ADR-50 v1.0 freeze) — BLOCKED until AR migrates. **Slice 6** (single node-rule walk) is independent and can land any time. Gate per slice: corpus byte-identical (cwd=target, project `.rigor.yml`); examples gate on integration spec + before/after demo diff. **Delegation lesson (AR):** the Sonnet subagent did the mechanical spec rewrite well AND correctly flagged the regression as engine-not-spec — but the FP-core decision (whether AR is *migratable at all*) was mine to make; always run the plugin's own end-to-end specs (not just unit/contract specs) before trusting a migration, they catch receiver-type cascades the unit specs (which stub the receiver) cannot.

### Stdlib RBS coverage-gap pattern + the staged upstream PR
