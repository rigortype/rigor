- **[engine]** A Ruby refinement that redefines a method the class already has (for example `refine Symbol do def [](other) … end end`) no longer leaves calls under its `using` checked against the unrefined signature: `call.argument-type-mismatch` and `call.wrong-arity` decline there. A refinement of an ancestor does not silence a method the receiver's class (or a nearer ancestor) defines itself, which Ruby finds first: under `refine Object do def center(a, b, c) … end end`, `"x".center(1, 2, 3)` is still reported. ([#1663](https://github.com/rigortype/rigor/issues/1663), [#1685](https://github.com/rigortype/rigor/pull/1685), [#1740](https://github.com/rigortype/rigor/issues/1740))
