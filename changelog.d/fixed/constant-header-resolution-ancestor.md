- **[engine]** A superclass or included module named in a compact declaration now resolves where Ruby resolves it: `class Admin::Widget < Base` written at the top level means `::Base`, not `Admin::Base`, so an inherited method no longer goes missing and a constant reached through the ancestor no longer answers from the wrong class. The nested spelling `module Admin; class Widget < Base` still means `Admin::Base`. ([#682](https://github.com/rigortype/rigor/issues/682))
