- **[plugin API]** In plugin code, a call of a member that a `Rigor::Plugin` interface declares now types through that member's signature, so in a hook `scope.type_of(node)` reads `Rigor::Type::t` instead of `Dynamic[top]`. ([#2815](https://github.com/rigortype/rigor/pull/2815))
  - A value typed `Rigor::Plugin::_Scope`, `_Environment`, `_Services`, `_FactStore` or `_Configuration` shows as `Dynamic[Rigor::Plugin::_Scope]` in `rigor type-of`, hover and lens, and every other rule still reads it as `untyped`. A call of a member the interface does not declare stays silent.
  - `call.possible-nil-receiver` can now fire in third-party plugin code on an unguarded use of what `_Scope#local`, `_Scope#self_type`, `_Scope#source_path` and `_Environment#nominal_for_name` return, which the interfaces declare nilable. The same code on a `Rigor::Scope` receiver reports it too; the bundled plugins report none.
  - Hook results read through the interfaces are more precise: `scope.environment` is `Dynamic[Rigor::Plugin::_Environment]`, and `services.fact_store.publish(...)` is `nil`.
  - A call that no overload of the member takes (a wrong arity, a block the member does not take, a splat) and a block-pass that may be `nil` whose two shapes disagree read `Dynamic[top]` as before.
  - Every other RBS interface still reads `Dynamic[top]`, and `rigor sig-gen` output is unchanged.
