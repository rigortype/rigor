# Absorb only the empty hash shape, add missing initialize keywords to the sig, and re-point three gap markers

- **PR:** [#2311](https://github.com/rigortype/rigor/pull/2311)
- **Issue:** [#1149](https://github.com/rigortype/rigor/issues/1149)
- **Class:** gate-row
- **Precedent:** [#2298](https://github.com/rigortype/rigor/pull/2298)
- **Decided:** 2026-10-22

## Background

After #2199, six #1148 markers in `sig/rigor/scope.rbs` were stale (the rows are generated-equal), three remained untyped, and both #1149 rows differed from what sig-gen infers. The issues left open how far to extend #2298's empty-literal absorption, what to do with the `Set[Symbol] | Set[untyped]` row, and where the three still-untyped rows point.

## Options and trade-offs

- **Hash absorption.** Absorb a closed empty `{}` beside a `Hash` nominal only (taken), or any empty shape. An open `{ ... }` shape says the keys are unknown, which is information; it is kept and pinned.
- **`Set[untyped]` arm.** Absorbing it would drop the fallback arm on the strength of the sibling `Set[E]`, a gradual-element join and not an empty-literal rule; the declared `Set[Symbol]` is true but the generator cannot prove it. Taken: leave it, keep the marker, file #2309. The alternative was `# authored:`, which would claim no engine work could ever answer it.
- **`refinement_block_self?` / `singleton_class_body?`.** Their cause is not the endless def: the `initialize` declaration in `sig/rigor/scope.rbs` omitted the `opaque_block_self:`, `block_self_unknown:` and `singleton_class_body:` keywords, so the ivars those keywords seed had no declared parameter type to read (#1154's mechanism). Taken: add the three keywords to the declaration with the types the readers already declare. This is a hand edit to a declaration, but it states parameter intent that was missing, not a forced return type.
- **`ambiguous_ancestor_resolutions`.** Its non-decline arm comes from a private helper with untyped parameters, so it is `untyped`. The umbrella #160 only loosely fits, so the coordinator filed #2312 for exactly this cause (a method whose non-decline arm calls a private helper with untyped parameters is skipped). Taken: re-point to #2312 and add it to the allow-list.

## Decision

The narrowest option in each case, except that the `initialize` edit added only 3 of about 20 omitted keywords (`opaque_block_self:`, `block_self_unknown:`, `singleton_class_body:`), the ones the rows in this PR needed; the rest is #2313. `gap_issues.yml` drops #1148 and #1149 (no marker cites them any more) and gains #2309 and #2312. The scope.rbs residue pin moves 69 to 65: `class_cvars_for` and `class_ivars_for` (hash absorption) and `opaque_block_self` / `opaque_block_self?` (the initialize keywords).

## To undo

Restore the `initialize` keywords' absence and the markers in `sig/rigor/scope.rbs`, restore the two `gap_issues.yml` rows and drop #2309, and revert the pin; for the absorption, revert `absorbed_empty_literal?` to the tuple-only form.
