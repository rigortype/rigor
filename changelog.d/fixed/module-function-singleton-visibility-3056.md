- **[inference]** `pre_eval:` singleton copies now follow Ruby's visibility: a protected `module_function` copy reports `call.undefined-method` unless the call's `self` is the owner or a class whose singleton chain holds it, and a repeated `module_function :x` keeps a copy `private_class_method :x` made private. ([#3132](https://github.com/rigortype/rigor/pull/3132))
  - `class << self; protected :x` after `module_function :x` makes the singleton copy protected, so `Kernel.a1` at the top level reports while `Kernel.a1` inside the owner's own singleton method still answers.
  - Ruby re-copies the instance method onto the singleton only when the def changed, so `module_function :x`, `private_class_method :x`, `module_function :x` leaves `Owner.x` private; a `def x` redefinition between the calls makes the next copy public again.
