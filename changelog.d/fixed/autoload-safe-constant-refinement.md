- **[engine]** Reading a constant out of your code no longer makes Rigor load and run that library inside itself: a reference to something like `Prism::Translation::RubyParser` used to be resolved in the analyzer's own process, executing the target file — which in that example calls `exit` when an optional gem is missing, killing `rigor check` outright with no diagnostics and no summary. Constant refinement now answers only from a fixed list of core Ruby constants, so no name in the code being checked can drive it. ([#680](https://github.com/rigortype/rigor/issues/680))
