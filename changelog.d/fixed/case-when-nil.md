- **[engine]** A `case` clause `when nil`, `when true` or `when false` now narrows its subject as `when NilClass`, `when TrueClass` or `when FalseClass` does, so `case x when nil then 0 else x.upcase end` no longer reports `call.possible-nil-receiver` on correct code. A trailing `else` such clauses leave dead (`when String` then `when nil` on a `String?` subject) now reports `flow.unreachable-clause`, as the class spelling already did.
