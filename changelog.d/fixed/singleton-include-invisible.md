- **[effects]** An `include` or `prepend` written inside `class << self` or `singleton_class.class_eval` no longer counts as an instance-side include, because Ruby mixes the module into the class's singleton class there, as `extend` does. As a result, an instance method's `super` no longer resolves into that module and `Foo.new` no longer takes the module's `initialize`, so the module's effects stop reaching those callers (a committed effect snapshot may need regenerating). ([#1320](https://github.com/rigortype/rigor/pull/1320))
  - The change also has an unsafe side: a class whose `new` comes from such a mixin now reads as having the empty constructor, exactly as a class that gets `new` through `extend` already did, so `rigor sig-gen` can write `%a{pure}` on a caller whose `new` does work.
