- **[plugin API]** In plugin code, a call of a member that a `Rigor::Plugin` interface declares now types through that member's signature, so in a hook `scope.type_of(node)` reads `Rigor::Type::t` instead of `Dynamic[top]`. ([#2815](https://github.com/rigortype/rigor/pull/2815))
  - A value typed `Rigor::Plugin::_Scope`, `_Environment`, `_Services`, `_FactStore` or `_Configuration` shows as `Dynamic[Rigor::Plugin::_Scope]` in `rigor type-of` and hover, lens shows the results of its declared-member calls, and every other rule still reads it as `untyped`. A call of a member the interface does not declare stays silent.
  - `call.possible-nil-receiver` can now fire in third-party plugin code when a local variable holds what `_Scope#local`, `_Scope#self_type`, `_Scope#source_path` or `_Environment#nominal_for_name` returns (the interfaces declare these nilable) and a call on it is unguarded. The same code on a `Rigor::Scope` receiver reports it too; the bundled plugins report none.
  - Hook results read through the interfaces are more precise: `scope.environment` is `Dynamic[Rigor::Plugin::_Environment]`, and `services.fact_store.publish(...)` is `nil`.
  - A call reads `Dynamic[top]` as before when no overload of the member takes it (a wrong arity, a block the member does not take, a splat), when it passes a block that may be `nil` and the block-less and block-ful returns disagree, or when one of several overloads it could reach takes a `self` parameter.
  - Every other RBS interface still reads `Dynamic[top]`, and `rigor sig-gen` output is unchanged.
