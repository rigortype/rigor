- **[check]** `call.undefined-method` no longer fires on a class, or on its subclasses, when its instance side mixes in a module Rigor does not record. ([#2993](https://github.com/rigortype/rigor/pull/2993))
  - Any name is accepted after `include(*MODS)`, `prepend(*MODS)`, `send(:include, *MODS)`, `include helper`, `include M1, helper` and `k.class_eval { include M }`.
  - After an `extended` hook's `base.include(M)`, and, until Rigor records them, `self.include M` and a receiverless `send(:include, M)`, `public_send` or `__send__`, only the names `M` may define are accepted.
  - `Other.include(*MODS)` affects only `Other`.
  - `include M; prepend M` still reports, because both modules are recorded.
  - Calls on the class object still report. A splatted `extend(*MODS)` affects only the class object, as before.
