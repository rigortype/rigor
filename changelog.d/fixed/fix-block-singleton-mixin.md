- **[engine]** `extend X` and `class << self; include X; end` written inside an iterator block in a class body (`[1].each { extend X }`) are now recorded, so a class-method read through them no longer reports a false `undefined method`; blocks on any other object (`@lock.synchronize { extend X }`, `on_load` hooks) are still not read as the class's own, and a concern's `included do extend X end` or a `self.included(base)` hook that extends its includer is still not modelled. ([#1592](https://github.com/rigortype/rigor/issues/1592), [#1593](https://github.com/rigortype/rigor/pull/1593))
