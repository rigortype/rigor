## Verdict

Status hygiene in the 42–82 range is **good at the ADR-file layer and lagging at the
aggregator layer**. Every drift found is a downstream index (README and, most often,
`CLAUDE.md`) that failed to advance when work landed — never an ADR file over-claiming an
unbuilt feature. The `CLAUDE.md` bullet list is the least fresh of the three sources: it alone
carries the stale rows for ADR-46 ("proposed"), ADR-53 ("Track B remaining"), and ADR-58
("WD2/WD3 pending"), all three shipped in code. The two most serious drifts, ADR-67 and ADR-74,
are stale in **both** README and CLAUDE.md — each marks a feature that shipped weeks ago
(`rigor coverage` param inference; the `rigor docs` command, v0.2.2) as "Proposed" /
"implementation queued", the exact "shipped but marked unbuilt" defect this lens exists to
catch. The current cycle's ADR-82 WD9 is correctly recorded in the ADR file but not yet
propagated to either index. Recommended action: sync README + CLAUDE.md rows for ADR-46, 53,
58, 67, 74, 82 to their (accurate) ADR-file status, and refresh the ADR-57 status header.
No decision content needs to change — this is purely propagating already-true file status into
the two indexes.
