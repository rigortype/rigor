- **[engine]** A call between a `=~` match and a read of `$1` is now judged by what it calls and its arguments' types, so a lookup that leaves `$~` alone (`val = row[:name]`, `csv.split(",")`, `list.index(3)`, `s.match?(re)`) no longer reports a false `call.possible-nil-receiver` on the read, while `u !~ re`, `u.start_with?(re)`, `binding.eval(src)`, `u.send(:=~, re)` and a matching call inside an argument, receiver chain or array, hash or string literal now forget the narrowing as Ruby does.
