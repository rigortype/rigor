- **[inference]** `transform_keys` / `transform_values` over a hash whose keys are statically known no longer fold to a wrong exact shape in three cases: `transform_keys({ a: :z }) { … }` no longer ignores its mapping hash, so `r[:z] + 1` is no longer reported as a call on `nil`; `transform_values!` / `transform_keys!` whose block can see the hash being rewritten — directly, through another variable or a constant, or through a method call — no longer answer as though the earlier pairs were untouched, so `h.transform_values! { |e| h[:x] + e }` is no longer typed `{ x: 2, y: 3 }` when Ruby produces `{ x: 2, y: 4 }`; and `transform_keys!` now orders its pairs the way Ruby's in-place rewrite leaves them, so `r.keys.first` no longer reads the wrong key.
