- **[plugins]** rigor-activerecord now types a written-receiver read of an enum-backed column as the enum's key (`user.status` is `"active" | "archived"`, or `String` when no key is statically known) instead of the column's SQL storage type, so a correct `user.status.upcase` no longer reports `undefined method 'upcase' for Integer` while a wrong `user.status + 1` keeps its runtime `TypeError` (the engine's argument-type-mismatch rule is nil-only, so the check stays silent on coerce-able arguments); the implicit-self spelling inside the model stays `Dynamic[top]` and the writer / `where(status:)` side is unchanged. thank you @zonuexe!
