- **[plugins]** `rigor-activerecord` now indexes a model declared with a rooted constant path (`class ::User < ApplicationRecord`) under its plain name, so `rigor-actionpack`, `rigor-factorybot` and `rigor-shoulda-matchers` find it in the shared `:model_index` fact and the plugin's own column checks and finder typing cover it — along with its STI subclasses, a `< ::ApplicationRecord` base, a rooted `model_base_classes:` entry, and call sites that spell the receiver `::User`. ([#583](https://github.com/rigortype/rigor/issues/583))
  - A model reopened in a second file (`class ::User` or `class User` adding a method) now contributes to the same index entry instead of replacing it, so the real declaration's associations, scopes, enums, validations and `alias_attribute`s survive — `where(<an alias>: …)` no longer reports a false unknown column depending on which file the project happens to list first. ([#583](https://github.com/rigortype/rigor/issues/583))
