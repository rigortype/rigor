- **[rigor-sorbet]** The plugin now types the Sorbet annotation DSL's own expressions via a bundled `sorbet-runtime` RBS surface — `sig { ... }` resolves through `extend T::Sig`, its block binds `self` to `T::Private::Methods::DeclBuilder` (so `params` / `returns` / `void` / `checked` / `abstract` / `override` / `overridable` / `type_parameters` chain), `T::Array[...]` / `T::Hash[...]` and the `T.*` type-expression functions return `T::Types::*` carriers, `extend T::Helpers` / `T::Generic` resolve the class-declaration macros, and `T::Struct` / `T::Enum` subclasses resolve `prop` / `const` / `sig` / `enums` — where every one of these call sites previously read as `Dynamic[top]`. ([#1097](https://github.com/rigortype/rigor/issues/1097))
  - New manifest field `rbs_complete_extends:` — the `extend`-edge twin of ADR-43's `rbs_complete_ancestors:`: a source `extend M` in a class/module body lets singleton-side calls resolve an allow-listed module's bundled RBS instance surface (`class F; extend T::Sig; sig { ... }; end`).
  - `Macro::BlockAsMethod` matching now also consults `extend` edges (`discovered_extends` plus `Environment#singleton_extended_modules`), so a `sig` block on `class Doc < T::Struct` binds `DeclBuilder` even though `Doc` does not inherit `T::Sig` in source.
  - Value-side assertions (`T.let` / `T.cast` / `T.must` / `T.bind` / `T.assert_type!` / `T.reveal_type` / `T.absurd` / `T.unsafe`) stay recogniser-owned — RBS cannot express "return the asserted type" — and `T`'s surface is deliberately partial behind `open_receivers:` so an unmodelled `T.*` call degrades to opaque rather than `call.undefined-method`.
