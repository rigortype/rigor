- **[engine]** A `Struct` member read chained off a method that returns its own receiver — the fluent-builder idiom, `Line.new("a").with_text("z").text` or `x.dup_self.text` — no longer reports the value the struct was constructed with after a setter has changed it; only a receiver that genuinely builds the struct (`.new`, `[]`, an un-overridden `.with`) is now treated as untouched, so a value arriving from a factory method reads as untyped instead of stale. ([#595](https://github.com/rigortype/rigor/issues/595), [#598](https://github.com/rigortype/rigor/pull/598))
