- **[rigor check]** A call on a project class whose method is defined conditionally, or reached through a conditional include or an `included do` block, now types as `Dynamic` instead of from the definer that happened to come first in the file, so `call.undefined-method` no longer fires on the follow-on call (`C.new.foo.upcase` where Ruby's `foo` depends on a condition the file cannot name). A true positive that depended on one world of such a condition is lost by design. ([#1562](https://github.com/rigortype/rigor/issues/1562), [#1594](https://github.com/rigortype/rigor/issues/1594), [#1572](https://github.com/rigortype/rigor/issues/1572), [#1629](https://github.com/rigortype/rigor/pull/1629))
